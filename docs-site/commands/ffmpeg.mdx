<Warning>
`coreav ffmpeg` is experimental until it meets its 0.1.0 bars, R1 to R4, on held-out files. Its outputs pass the job oracles on the fixtures in CI, but those bars are not measured yet ([the 0.1.0 release issue](https://github.com/coreav-dev/coreav/issues/43)).
</Warning>

`coreav ffmpeg ARGS` takes an `ffmpeg` command line in `ffmpeg`'s own syntax and runs it with CoreAV's own writers, when it is a stream copy (`-c copy`) that CoreAV implements. It selects streams as `ffmpeg` does, with or without `-map`.

| The command line | What runs |
|---|---|
| A copy to `.mp4` (or `-f mp4`) from MP4, MOV, Matroska or WebM | [`coreav remux`](/commands/remux) of the selected streams |
| A copy of one audio stream to `.m4a` (or `-f ipod`) | [`coreav extract-audio`](/commands/extract-audio) |
| A copy to `.avi` (or `-f avi`) from MP4 or MOV | Bounded H.264, MP3 and integer PCM packet output |
| `-ss`, `-t` or `-to`, before or after `-i` | [`coreav clip`](/commands/clip), or for a copy of one audio stream and no video, a clip of that audio alone |
| `-f segment` with MP4 segments | [`coreav split --every`](/commands/split) at `-segment_time` |
| `-f concat` with an MP4 output | [`coreav join`](/commands/join) of the list's files |
| One audio stream to `.wav` or `-f wav` | Signed 16-bit little-endian PCM, the default codec for WAV |
| One audio stream with `-f s16le` or `-f f32le` after `-i` | Registered raw PCM paths to a file or standard output |
| `-f s16le -ar RATE -ac CHANNELS` before `-i`, to WAV or raw S16 | Explicit mono/stereo raw input, with optional output rate conversion |

In a build with a decoder backend, it also runs a command line that encodes the video with `libx264`, through [`coreav transcode`](/commands/transcode). The build's backends decode the video, and an `x264` program encodes it, or an `ffmpeg` program built with libx264 when no `x264` program is found. In strict-safe mode no `ffmpeg` program runs: the command line needs an `x264` program and a backend other than `ffmpeg-fallback` that decodes the video, and is refused with exit status 4 otherwise ([what strict-safe mode covers](/strict-safe#what-strict-safe-mode-covers)).

In a build with the `libopus` feature, such a command line can also encode one audio stream this build decodes, mono or stereo, with `-c:a libopus`, at the bit rate `-b:a` gives (6k to 510k), through [`coreav transcode --audio opus`](/commands/transcode). Sources can be FLAC, MP3, Opus, or AAC-LC with the `aac` feature. CoreAV runs libopus itself in a sandboxed process, never an `ffmpeg` program. In a build without the `libopus` feature, a `-c:a libopus` command line is not native: it goes to the real `ffmpeg`, and in strict-safe mode it is refused with exit status 4 and nothing runs.

In every build with a decoder backend, such a command line can also encode one audio stream this build decodes, mono or stereo, sampled at an AAC rate from 8 to 64 kHz, with `-c:a aac` (or `-acodec aac`), at the bit rate `-b:a` gives (16k to 512k; without it, the encoder's default), through [`coreav transcode --audio aac`](/commands/transcode). Sources can be FLAC, MP3, Opus, or AAC-LC with the `aac` feature. The encoder is FFmpeg's built-in `aac` encoder, run as a separate process: the `ffmpeg` program `COREAV_FFMPEG` names, else the one on `PATH`. A command line is refused with exit status 4 when no `ffmpeg` program is found or it has no `aac` encoder. Strict-safe mode never runs an `ffmpeg` program, so it refuses every `-c:a aac` command line with exit status 4 and nothing runs.

These audio encoders also work without video: use `-vn` or select one audio stream with `-map a` or `-map 0:a:0`. AAC output can be MP4 or M4A; Opus output can be MP4. `-b:a` and the encoder defaults are unchanged. No video decoder or video encoder runs. Multiple audio streams, delayed source audio, chapters, source tags or dispositions the writer does not preserve, video encoder options and trim options are refused. On M4A, `-map_metadata -1` discards source tags. The standalone `coreav transcode` command still requires video.

### MP3 output

In a build with the `transcode` feature, a `.mp3` output or `-f mp3` defaults to MP3 encoding. `-c:a libmp3lame`, `-codec:a libmp3lame` and `-acodec libmp3lame` select it explicitly. CoreAV runs the `ffmpeg` program named by `COREAV_FFMPEG`, else the one on `PATH`, with libmp3lame as a separate resource-limited encoder. CoreAV supplies decoded PCM, checks its output, and writes the MP3 file itself, including ID3v2.4 and Xing/Info gapless metadata. It never links or bundles libmp3lame.

Use `-b:a RATE` for a constant bit rate or `-q:a Q`/`-qscale:a Q` for VBR quality from 0 (highest) to 9. Quality takes precedence when both are given. Without them, the encoder's default applies. The source must be mono or stereo at a supported MP3 rate from 8 to 48 kHz. Sources are the audio codecs this build decodes; AAC-LC input needs `aac`. No video decoder runs. Rate/channel conversion, trim options, multiple streams and cover-art output remain unsupported. Missing FFmpeg or libmp3lame, failed readback and strict-safe mode publish nothing. `coreav transcode` itself does not select MP3.

CoreAV preserves the source's presented sample count. The pinned FFmpeg adds samples for MP3 input lengths where the count modulo a codec frame is from 1 to 46: it presents `N + 47 - (N mod F)` samples, where `F` is 1,152 at 32, 44.1 and 48 kHz and 576 at lower rates. CoreAV's EOF zero guard and gapless tag retain exactly `N`; FFmpeg and ffprobe read the resulting file at its original length. Other duration differences are not covered by this rule.

AVI output also accepts `-c:a pcm_s16le` or `pcm_u8` for mono or stereo audio that this build decodes. MP3 encoding (`-c:a libmp3lame`) needs the opt-in `transcode` feature, absent from default builds, and an external `ffmpeg` program with that encoder. Strict-safe mode refuses this external encoder even when the feature is enabled. AVI output is limited to files smaller than 1 GiB, with fixed-rate, non-reordered, zero-based H.264 video. [The AVI design note](https://github.com/coreav-dev/coreav/blob/main/docs/design/avi-write.md) lists the supported clocks and resource limits.

Any other command line is refused in strict-safe mode, and goes to the real `ffmpeg` otherwise ([strict-safe mode and the fallback](/strict-safe)).

## PCM audio output

WAV output runs natively for FLAC tracks in MP4, MOV or Matroska, including in strict-safe mode. PCM and ALAC tracks in containers are not supported. Automatic selection chooses one audio stream, preferring the default disposition, then the most channels. `-map` can select another audio stream. Video and cover pictures are not selected automatically for these outputs. Headerless raw output uses the separate eligibility rules below.

Standalone integer WAVE input also writes a WAV file natively, with S16 output and unchanged mono/stereo channels and sample rate. U8 and full-width S16/S24/S32 sources use the existing exact packing pipeline. The complete file, including the encoder tag and RIFF sizes, matches the pinned reference. Other source tags require `-map_metadata -1`. Float sources, timing, changed rate/channels and WAV pipes remain refused. The [WAVE-to-WAV plan](https://github.com/coreav-dev/coreav/blob/main/docs/design/wave-pcm-wav-output.md) records this scope.

```sh
coreav --strict-safe ffmpeg -i input.mka output.wav
coreav --strict-safe ffmpeg -i input.mp4 -acodec pcm_s16le -f s16le output.raw
coreav --strict-safe ffmpeg -i input.mka -ss 0 -t 30 output.wav
```

For WAV and legacy raw S16 commands with timing options, the rate and channel count stay unchanged. `-ar` is accepted only at the source rate. `-ac` is accepted only for a mono or stereo source with that same channel count. A zero output `-ss` and `-t` or `-to` can limit the output from its start when the duration is a whole sample count. Input `-ss 0` is supported only for FLAC. Input `-t 0` means unlimited input, while output `-t 0` writes an empty stream. An effective `-to 0` is an error. The decoder still reads the whole input. Nonzero seeking, multiple output files and other PCM codecs are not supported.

Output `-threads` is accepted but does not change PCM serialization or start encoder workers.

WAV metadata copying is not supported. Use `-map_metadata -1` for an input with tags other than container bookkeeping or encoder identification. Stream-to-global metadata mapping and WAV chapter copying are refused. Damaged audio, decoder warnings and WAV output beyond the RIFF size limit fail without replacing the destination. A `.raw` or `.pcm` extension alone does not select raw output; use `-f s16le`.

The [PCM output design](https://github.com/coreav-dev/coreav/blob/main/docs/design/pcm-output.md) records its correctness bars and limitations.

### Headerless audio streams

Use `-f f32le` for interleaved 32-bit float samples, or `-f s16le` for signed 16-bit little-endian samples. Their default codecs are `pcm_f32le` and `pcm_s16le`. An explicit codec must match the selected raw format. Output `-`, `pipe:` and `pipe:1` write only sample bytes to stdout. A closed stdout exits quietly with status 141, including a failure of the final buffered flush.

```sh
coreav --strict-safe ffmpeg -threads 2 -i input.mka -ac 1 -ar 48000 -f f32le pipe:
cat input.mka | coreav --strict-safe ffmpeg -i pipe: -f s16le pipe:
```

Every stage must have an eligibility registration. Current exact decoder rows cover mono or stereo 16-bit and 24-bit FLAC tracks. Unchanged-rate FLAC output is byte-identical to the pinned FFmpeg. Linux x86-64 additionally has registered S16 compatibility-rate paths and mono float-preserving 44.1 or 48 kHz to 16 kHz paths. These platform-specific registrations do not apply on macOS. Channel changes, combined downmix and resampling, other representations and unregistered paths fall back, or exit 4 in strict-safe mode.

Decoder eligibility distinguishes exact output from specification-conformance-only output. MPEG-1 Layer III MP3 in MP4 runs natively when every frame and the native presentation timeline satisfy the [decoder eligibility record](https://github.com/coreav-dev/coreav/blob/main/docs/design/lossy-pcm-eligibility.md). Opus MP4 also runs natively for mapping family 0, mono or stereo, zero output gain and native 48 kHz decoding, with a supported warning-free timeline that inserts no silence. Finite edits own their complete sample window; without an edit, actual PreSkip trims the decoded packet sequence. These lossy outputs are conformance-only, not byte-identical to FFmpeg. MPEG-2 and MPEG-2.5 MP3, AAC, other Opus configurations, and lossy Matroska presentation remain refused. Conformance-only decoder registration never relaxes the exact bar for channel conversion, rate conversion or packing.

Input `-`, `pipe:` and `pipe:0` accept encoded container bytes. CoreAV spools only the encoded input to a private temporary file with a 1 GiB cap because container decoding needs positioned reads. Declared raw S16 stdin streams directly without a whole-input spool. Unsupported encoded input is replayed from its start to the fallback with the original arguments. Decoded audio is never collected as a whole file; a discard decode validates presentation before stdout begins, so this safety check costs an extra decode. Any failure after output begins is terminal and never starts fallback.

Standalone RIFF/WAVE, RF64 and BW64 input uses the existing parser's validated PCM data span. Full-width unsigned 8-bit and signed 16/24/32-bit little-endian PCM support S16 and F32 output with unchanged mono or stereo channels. Finite F32 input supports unchanged-rate F32 output only, preserving sample bits including signed zero. F32-to-S16 packing and rate conversion from F32 WAVE input remain unregistered; the pinned macOS oracle disagrees at rounding boundaries and finite extrema. Changed-rate U8-to-S16 also falls back because the complete source command differs from the existing rate stages. Other integer-source rate conversion still requires its existing Linux x86-64 registration and exact source composition.

Reduced valid precision, F64, RIFX, compressed WAVE, unconventional speaker masks, multiple data chunks, unsupported metadata and incomplete data extents fall back. Empty data followed by another chunk is also refused because the oracle reads that tail as samples. The parser's ability to probe one of these files does not establish exact PCM output. WAVE files and encoded stdin share bounded preflight and output ownership; no decoded file is buffered, and source I/O or malformed headers remain terminal errors. Standalone FLAC decoding is not added. The [WAVE source plan](https://github.com/coreav-dev/coreav/blob/main/docs/design/wav-pcm-source.md) and [raw audio plan](https://github.com/coreav-dev/coreav/blob/main/docs/design/raw-audio-pipes.md) record the boundaries.

## Lossless FFV1 video

A build with a decoder backend accepts `-c:v ffv1` for one progressive, fixed-size, 8-bit planar YUV video stream in a `.mkv` file. Supported sampling is 4:2:0, 4:2:2 or 4:4:4. The encoder runs in CoreAV and preserves the decoded samples without conversion. No external video encoder is needed. The source must be a local MP4/MOV or Matroska/WebM file whose video this build decodes. Strict-safe mode still applies to that decoder.

This first path accepts H.264 with `native-h264`, AV1 with `dav1d`, and VP8 or VP9 with `libvpx`. It does not use the FFmpeg decode fallback or hardware pictures, because their frame descriptions do not establish the required scan structure here.

```sh
coreav --strict-safe ffmpeg -i input.mp4 -map 0:v:0 -an -sn -dn -c:v ffv1 output.mkv
```

Exclude other selected streams explicitly. Audio, subtitles, attachments and additional video streams are not written by this path. RGB, alpha, monochrome, higher bit depths, unknown or interlaced scan structure, changing geometry, filters, resizing, seeking, trimming, frame selection, rate-control options and other containers are not native. `-pix_fmt` can require the decoded format but cannot convert it. Above 101,376 pixels, 4:2:0 requires width and height divisible by four, and 4:2:2 requires width divisible by four, so internal slices meet on chroma boundaries.

Output uses FFV1 version 3 with independent keyframes and slice checksums. Known sample aspect and the writer's supported colour fields are preserved. Unsupported source metadata and display transforms are refused. Encoding has explicit packet, memory, index, disk-spool and deadline bounds; reaching a bound fails without replacing an existing destination. Unsupported native commands retain the existing announced fallback outside strict-safe mode. The [FFV1 design](https://github.com/coreav-dev/coreav/blob/main/docs/design/ffv1-encode.md) records the exact subset and verification gate. No speed or output-size comparison is claimed.

## Images and raw video

A build with a decoder backend also writes PNG (`.png`), BMP (`.bmp`), raw video (`.yuv` or `-f rawvideo`) and YUV4MPEG2 (`.y4m` or `-f yuv4mpegpipe`). These outputs select one video stream and no audio automatically. `-map` can select that stream explicitly. Strict-safe mode uses the same decoder restrictions as thumbnails and never runs FFmpeg.

```sh
coreav --strict-safe ffmpeg -ss 1 -i input.mp4 -frames:v 1 frame.png
coreav --strict-safe ffmpeg -i input.mp4 -f image2 frame%03d.png
coreav --strict-safe ffmpeg -i input.mp4 -r 1/1 frame%07d.bmp
coreav --strict-safe ffmpeg -i input.mp4 -update 1 latest.png
coreav --strict-safe ffmpeg -i input.mp4 -c:v rawvideo -pix_fmt yuv420p output.yuv
coreav --strict-safe ffmpeg -i input.mp4 -f rawvideo -
coreav --strict-safe ffmpeg -i input.mp4 output.y4m
```

`-frames:v N` and its alias `-vframes N` limit the number of output frames. An image sequence needs one `%d` or `%0Nd` placeholder, with one to nine padding digits; numbering starts at one. A single image needs a one-frame input, `-frames:v 1`, or `-update 1` to replace it after each selected frame. `-ss`, `-t` and `-to` select frames on the input's presentation timeline.

Raw output keeps the decoder's pixel format. `-pix_fmt` must name that format; it never adds colour conversion. PNG preserves RGB, RGBA and 8/16-bit monochrome samples, or uses the existing thumbnail conversion for 8-bit colour video. BMP uses that conversion and stores 24-bit BGR pixels. This RGB conversion is not guaranteed to match FFmpeg pixel for pixel. Image encoding itself is lossless.

`-r` after `-i` supports constant-rate video starting at the input's time zero and may drop frames, not duplicate them. Higher output rates, resizing and filters are refused. YUV4MPEG2 supports known progressive, constant-rate, 8-bit planar YUV or monochrome video with at least one selected frame. It refuses autorotation; `-noautorotate` before `-i` preserves the stored planes and their chroma location. Image files are placed atomically one at a time; raw files are placed only after the whole output succeeds. A pipe cannot be rolled back on failure and carries binary bytes on standard output.

[The frame-output design note](https://github.com/coreav-dev/coreav/blob/main/docs/design/frame-output.md) records the correctness bars and limits.

Timeout scope depends on the decoder backend. On clock-supported targets the native H.264 backend uses a 60-second decoder-session deadline, set when the decoder opens and reused by later calls. A slow output sink can make the next decoder call time out. The command adds no separate wall-clock deadline. Decoded bytes remain limited to 4 GiB per decoder. A failed binary-stdout write or final flush fails the command; a closed pipe exits with status 141.

### Raw signed-16 input

Declare signed 16-bit little-endian samples explicitly before `-i`, including both the rate and channel count. The file's extension does not select or override its interpretation. Rates are positive integral Hz; decimal SI forms such as `44.1k` are accepted. Only mono or stereo is native, with unchanged channels, at 1,000 to 768,000 Hz.

```sh
coreav --strict-safe ffmpeg -f s16le -ar 44.1k -ac 2 -i input.pcm output.wav
coreav --strict-safe ffmpeg -f s16le -ar 8000 -ac 2 -i input.pcm -ar 44100 output.wav
```

At an unchanged rate, S16 output copies integer bytes without a floating-point conversion. F32 output scales the input samples to floats. A changed output `-ar` uses a separate, independently derived compatibility kernel. Ratios requiring more than 1,024 phases, 4,096 taps or 65,536 coefficients are refused. Complete sample frames are required. Changed-rate headerless output requires the platform-specific exact registration described above. Unchanged-rate identity output is platform-independent. WAV retains its existing sized-input adapter.

Raw input does not support seeking or duration options, explicit maps, channel mixing, stream copy, other input sample formats, FLAC or lossy output, filters, dither or soxr. Headerless F32 output is supported at the input rate. The [investigation plan and finite synthetic evidence](https://github.com/coreav-dev/coreav/blob/main/docs/design/audio-swr-parity-plan.md) describe the arithmetic and its limitations; matching those cases is not proof of general parity or measured command coverage.

## FLAC audio output

`.flac` or `-f flac` selects CoreAV's native FLAC encoder, also available with `-c:a flac` or `-acodec flac`. It runs in default builds and strict-safe mode without an external program. Native input is currently limited to FLAC tracks with 16-bit or 24-bit samples in MP4, MOV or Matroska. The encoder preserves every sample, the source rate and the FLAC speaker order.

```sh
coreav --strict-safe ffmpeg -i input.mka output.flac
coreav --strict-safe ffmpeg -i input.mp4 -map 0:a:0 -c:a flac output.flac
coreav --strict-safe ffmpeg -i input.mka -vn -map_metadata -1 -t 30 output.flac
```

The encoder chooses constant, verbatim, fixed or linear prediction with partitioned Rice residuals. It writes STREAMINFO with the completed sample count and MD5. Its default compression settings are fixed; compression-level options are not supported. Output `-threads` is accepted but does not start encoder workers.

Rate and channel conversion, nonzero seeking, custom metadata copying and chapters remain unsupported. The PCM duration and zero-time rules above also apply to FLAC. For an input with custom global tags, use `-map_metadata -1`. MP3, AAC and Opus sources keep refusal and the existing external fallback. A selected video or cover picture is refused because PICTURE output is not implemented. Use `-vn` or an audio-only `-map` to omit it explicitly. A speaker layout outside the FLAC channel order is also refused.

The [FLAC output design](https://github.com/coreav-dev/coreav/blob/main/docs/design/flac-output.md) describes the encoder and the registered size and speed comparisons. These comparisons are not a speed claim.

## Examples

```sh
coreav --strict-safe ffmpeg -i input.mkv -c copy -movflags +faststart output.mp4
coreav --strict-safe ffmpeg -ss 10 -t 5 -i input.mp4 -c copy clip.mp4
coreav --strict-safe ffmpeg -f concat -safe 0 -i list.txt -c copy joined.mp4
coreav ffmpeg -i input.mp4 -vn -c:a aac output.m4a
coreav ffmpeg -i input.mp4 -q:a 2 output.mp3
```

`coreav ffmpeg` prints no status text on success. File outputs use temporary files moved into place when complete. Rawvideo pipes write binary bytes on standard output.

## Use it in place of ffmpeg

A link named `ffmpeg` that points to `coreav` behaves as `coreav ffmpeg` with the whole argument list. Under that name, only `COREAV_STRICT_SAFE=1` turns on strict-safe mode.
