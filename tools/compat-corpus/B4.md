# Run the registered B4 driver

This driver implements [round 10](../../docs/measurements/compat-ffprobe/round10-plan.md) and its [calibration design](../../docs/design/b4-calibration.md). It does not change or report historical rounds. `speed.py` continues to own historical B4 and R4.

## Freeze before any payload access

Prepare default-feature release builds of the fixed candidate and fetched-main baseline, and the verified shared oracle installation. The tooling checkout must be clean and its commit must be on fetched `main`. The freeze command checks the effective main ruleset's required CI contexts and their required app identities at the candidate, baseline and tooling commits. It needs Git and an authenticated `gh` with read access. No media is read by this command.

Create a private `sources.json` with these fields. Each commit is a full lowercase SHA-1, and each binary identity is its SHA-256. Build receipts describe the actual build, not a requested build configuration.

```json
{
  "plan": "3c79ef4979aa56bc7b667dc9130833b88f2be634",
  "tooling": "<tooling commit>",
  "candidate": "<candidate commit>",
  "baseline": "<fetched-main commit>",
  "builds": {
    "candidate": {"commit": "<candidate commit>", "profile": "release", "features": "default", "sha256": "<binary digest>"},
    "baseline": {"commit": "<baseline commit>", "profile": "release", "features": "default", "sha256": "<binary digest>"}
  }
}
```

Point `METADATA_ROOT` at the directory containing the registered `corpus/*/manifest.json` metadata, including every held-out manifest. Add `--heldout-roster` for any registered held-out roster not represented there. The existing boolean partition schema requires both `set == "real"` and `holdout is False` for development membership. Missing flags and integer zero do not qualify. An unsupported container or any selected overlap stops the freeze before download. `PRODUCT_ROSTER` is the historical frozen selection, not a newly selected replacement.

```sh
python3 -I tools/compat-corpus/b4_round10.py freeze \
  --manifests "$METADATA_ROOT" --product-roster "$PRODUCT_ROSTER" \
  --sources sources.json --coreav bin/coreav \
  --baseline-coreav bin/coreav-baseline --oracle-bin bin \
  --out frozen.json
```

Keep `frozen.json` private. It contains both exact rosters, source and executable identities, metadata identities, the command hash, judging-file hashes and the complete schedule. Metadata receipts hash the bytes actually parsed, and the freeze rejects changes to those files before it writes the manifest. Later commands verify it rather than select new inputs. Outputs must be new, so another invocation cannot overwrite an earlier attempt.

## Execute on the registered host

Only a separately authorized launch may provision a host. Use on-demand `c4-standard-8`, one thread per core, and the launch controller's observed instance receipt. `scripts/gcp_vm_job.py --stage-instance-receipt` places that receipt in the upload before the job starts. The driver also checks Linux, four visible CPUs, SMT, topology and one-core inherited affinity before any payload access.

Stage the checkout's judging files, command roster, frozen manifest and binaries without media. Pass read-only payload credentials to the remote job through its environment. Set a hard VM lifetime in the controller in addition to the driver's deadline. Include transfer, preparation and a separately bounded network reserve in the approved infrastructure bound. The payload client limits requests and bytes to the frozen roster and does not retry.

```sh
python3 -I tools/compat-corpus/b4_round10.py run \
  --manifest frozen.json --coreav bin/coreav --oracle-bin bin \
  --instance instance.json --cpu 0 --dir data \
  --mode calibration --max-seconds "$DEADLINE_SECONDS" \
  --usd-per-hour "$HOURLY_BOUND" --reserve-usd "$NETWORK_RESERVE" \
  --cap-usd "$APPROVED_CAP" --out out/calibration.json
```

`--mode calibration` is the default. It downloads and opens only the 24 development files and returns a calibration verdict, never a B4 product verdict. A statistical miss completes the fixed schedule and is final. Process, capture, integrity, fallback and safety failures preserve partial observations as incomplete. The total deadline interrupts a running child through the existing event-driven timer's cleanup, without polling or changing its 600-second child timeout.

Only a separately authorized product run uses `--mode product`. Product payload access begins after both complete calibration arms pass. The historical selection has prior observations and is not newly untouched validation data. Four conditioning pairs and five alternating timed pairs retain the registered ratio of side medians and whole-file product intervals.

Delete downloaded files and staged credentials when the job ends. Verify VM, disk and address cleanup in the launch controller, including failed and incomplete jobs. A calibration miss is not evidence of a physical host fault and does not authorize a replacement.

## Report the observed mode

```sh
python3 -I tools/compat-corpus/b4_round10.py report \
  --results out/calibration.json --out out/calibration.report.json
```

The reporter recomputes calibration from schedule-validated call receipts. It checks the global sequence and nonoverlapping clock boundaries before grouping calls, allowing only registered refusal skips and an incomplete suffix. A missing or unreadable fallback log invalidates capture. `ci995_gate` governs the gate; `ci95_diagnostic` is diagnostic only. Resource counters, host-frequency observations and steal ticks are diagnostic and never alter elapsed time or acceptance thresholds. Receipts include conditioning calls and retain logical A/B independently of chronological position.

Reports retain planned, executed, missing and failed calibration counts, position and early/late diagnostics, and product eligibility, refusal, failure and missing coverage when product mode is requested. A development-only result has `b4_passes: null` and `b4_verdict: "not executed"`. Exit codes are 0 for a passing requested mode, 1 for a miss or incomplete run, and 2 for invalid input or preflight failure. No result may be published as a full B4 verdict when only calibration ran.
