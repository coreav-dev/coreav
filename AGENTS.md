# Rules for agents and contributors, and what enforces each

Read `CONTRIBUTING.md` and `.github/pull_request_template.md` first; design notes for each area are in `docs/design/`. This file pairs every rule with what enforces it, so a rule that nothing enforces is visible.

When a review corrects a mistake, fix it and add its rule here. If the rule is already here and nothing enforces it, that is a repeat: in the same change, enforce it at the highest level that works (one owner or one way to do it, then a type, then a check whose error names the fix, then a test) and say why a higher level did not. Drop a row once its mistake cannot happen.

| Rule | Enforced by |
|---|---|
| No `unwrap`, `expect`, `panic!`, `todo!`, `unimplemented!` or slice indexing in production code | Workspace lints in `Cargo.toml`, `cargo clippy --workspace --all-targets -- -D warnings` (`ci.yml`) |
| No `unsafe` outside the files `docs/unsafe-sites.md` lists; the change that adds or changes an `unsafe` site adds or updates its row there | `unsafe_code = "forbid"` (`Cargo.toml`); `scripts/unsafe_sites_check.py` (`ci.yml`) fails on a file with `unsafe` and no row. It checks files, not sites: a new site in a listed file passes it, so its row is review judgment |
| Every commit a pull request adds carries a `Signed-off-by` with its author's email (`git commit -s`) | `scripts/dco_check.py` (`deny.yml`): the name may differ and the email's case is ignored; commits already on `main` are skipped |
| Dependencies keep to the license policy | `cargo deny check` and the fuzz projects' license check (`deny.yml`) |
| Default builds link no still-patented codec | `deny.yml` |
| A pull request's title and its commit subjects are Conventional Commits, `type(scope): summary` with the template's types (merge commits excepted); the title's summary is at most 50 characters and the title under 72; commit subjects are at most 72 characters | `scripts/pr_shape_check.py` (`pr-text.yml`) |
| No Korean text, run identifiers or spend details in a pull request's text | `scripts/pr_text_check.py` (`pr-text.yml`; the private list only on the agent's machine before opening) |
| Every action is pinned to a full commit sha | `scripts/workflow_check.py` (`deny.yml`) |
| Every `${{ }}` expression in a workflow uses a context GitHub offers where it stands: `runner` in a job's `env:` passes every other check and fails when the workflow runs | actionlint with shellcheck and pyflakes off (`deny.yml`), and a workflow with that mistake in the same step that must fail. `workflow_check.py` reads lines and would copy GitHub's availability table, so the tool that keeps it is the check |
| The oracle FFmpeg and the x264 commit of its libx264 are pinned once, in `scripts/oracle-ffmpeg.env`; scripts and workflows read them from there | `scripts/oracle_pin.py --check` (`deny.yml`) fails on an FFmpeg download URL, archive name, cache-key version or `VERSION` constant, an x264 commit, or a value of the pin, in any tracked file outside `docs/`, Markdown and `evidence/` or `results/` directories. Prose that names a version is review judgment |
| No file names an issue or pull request by a bare number; one of this repository is written `coreav-dev/coreav#N`, any other is described | `scripts/issue_refs_check.py` (`deny.yml`) fails on `#N`, `issue N`, `PR #N`, `prN` and `pull request N` in every tracked text file, and on `issue-N` and `prN` in paths. A number alone in a file name or a build label passes it, so that is review judgment |
| The required-check table in `docs/design/ci-checks.md` and the workflows agree | `scripts/workflow_check.py` (`deny.yml`) |
| Every workflow with a required check runs on a merge group, in concurrency groups of that run's own, cancelled only on a pull request | `scripts/workflow_check.py` (`deny.yml`) parses the trigger mapping with Psych's YAML nodes, so quoted or spaced keys cannot bypass its checks; ambiguous or unsupported nodes fail. It refuses a missing `merge_group:` trigger, `types:` without `checks_requested`, a branch filter on that trigger, and, unless it cancels job by job, a missing workflow-level group or one other than the one `ci-checks.md` ("The merge queue") names; `ci.yml`'s job groups were already held to that form. A job-level condition that skips a merge group's work is review judgment |
| A change of the oracle FFmpeg's pin (`scripts/oracle-ffmpeg.env` or `scripts/install-oracle-ffmpeg.sh`) starts every workflow that runs the installer | `scripts/workflow_check.py` (`deny.yml`) fails on a trigger `paths` or `paths-ignore` filter of such a workflow that the pin does not pass. A job-level filter (`changed-paths`) is review judgment |
| Current comparisons use the shared FFmpeg pin; the historical training extractor stays isolated | `scripts/oracle_pin.py --verify-bin` before oracle use, including cache hits; `--check` restricts historical-extractor references to the training job and its measurement directory (`deny.yml`) |
| Every oracle audio decode uses one input thread, without changing video threads | `scripts/oracle-audio-args.txt` owns the arguments; Python reads `oracle_audio.INPUT_ARGS`, shell reads the file, and Rust tests include it. `scripts/oracle_pin.py --check` rejects unowned Python audio inputs and duplicate audio thread options; command-capture tests check input placement (`deny.yml`). Types cannot govern command lists across Python, shell and Rust |
| A hash muxer does not imply packet copy: an audio-capable hash command uses the shared audio input options unless it explicitly sets the audio output codec to `copy` | `oracle_audio.python_problems` recognizes explicit copy codecs, not packet-copy exemptions; extraction and Matroska hash commands are covered by command-capture tests, and extraction by the real FLAC/ALAC edit-list regression. Types cannot distinguish FFmpeg command meanings across languages |
| No change makes a guarded command run more instructions without a stated cost | `bench-guard` in `ci.yml` fails when a case counts more than the tolerance above its count (5%, `tolerance` in `bench/guard/baseline.json`): a pull request against its base, `main` against the baseline. A rise within the tolerance passes, and a change that moves the baseline only gets a warning: that its cost is stated is review judgment |
| Transcode rate probing consumes the same timeout budget as encoding and never builds an unrelated full report or scans fragment totals | The ISO rate entry calls the library's header probe directly, without the report wrapper's fragment-scan option; `rate_probe_reads_only_the_fragment_header_window` bounds reads over ten thousand fragments and covers one frame. `rate_probe_does_not_scan_declared_sample_count` covers ten million samples with `ctts`. `RateSource` and the timeout regressions check read boundaries and remaining time. A synchronous source read cannot be interrupted |
| ISO rate-only probing and full reports use the resolved codec when applying the H.264 VUI fallback | `video_rates` is shared by both paths; `unsnapped_h264_times_keep_the_vui_rate` checks that the full report keeps its existing rate and the transcode uses that same rate |
| An H.264 speed round's bars are judged on every stream of its set | `scripts/h264_parity.py` records requested and failed streams; `scripts/h264_parity_bars.py` refuses incomplete reports |
| A new round adds no copy of an analyzer under `docs/measurements` | `scripts/tests/test_measurement_analyzers.py` (`deny.yml`) |
| The numbers of `docs/measurements/compat-ffprobe.md` are those of its `b3a-round*.json` | `tools/compat-corpus/record.py --check` (`deny.yml`) |
| B4 and R4 measure process exit without timeout polling delays; their real-child regressions do not depend on a narrow timing gap | The Linux process-exit descriptor in `speed.timed` owns both deadlines; R4's `timed_run` delegates to it. Real-child tests in `test_speed_b4.py` and `test_speed_r4.py` use a wide delay gap but directly refuse polling sleeps, with kill/reap and scratch-cleanup checks |
| R4 infrastructure errors abort rather than becoming excluded child failures | `timed_run` requests exception propagation from the shared timer; `test_infrastructure_errors_abort_after_a_completed_pair` injects launch and descriptor errors after a measured pair and requires propagation with a retained, aborted report, which the reporter and host reject |
| The documentation site's command reference shows each command's `--help` as the command prints it, and every command has a page | `crates/coreav-cli/tests/docs_site.rs` (`ci.yml`; `COREAV_BLESS_DOCS=1` rewrites the help text) |
| The documentation site's links into the repository and between pages resolve, without the `/docs` base path | `scripts/tests/test_docs_site.py` (`deny.yml`); Mintlify's link check (`docs-site.yml`, not required) |
| State kept per PID in `coreav-mpegts` is bounded: by a limit of `Limits`, or by the 8,192 PIDs a packet can name | `PidMap` (`crates/coreav-mpegts/src/pid_map.rs`): `PidMap::streams` and `PidMap::programs` take their limit from `Limits`, `PidMap::pids` the PID space; `disallowed-types` in `crates/coreav-mpegts/clippy.toml` refuses the standard maps elsewhere in the crate (clippy, `ci.yml`) |
| `coreav-cli`'s opt-in `aac` feature builds beside the transcode features: a crate matching on `coreav_audio::Codec` forwards `aac` to `coreav-audio` and gates its arm on its own feature | `cargo clippy -p coreav-cli --features aac,libopus,native-h264` (`ci.yml`) fails on the missing arm |
| An access unit keeps the PES identifier where it starts through video-run release, audio-frame splits and EOF | Mixed-identifier regressions in `coreav-mpegts/tests/captures.rs`, for the default and ffprobe listings; the optional packet field also represents sections with no PES identifier, so its type alone cannot enforce provenance |
| AC-3 and E-AC-3 downmix values follow their own specified field orders, not one shared positional array | Named fields of `Downmix` and asymmetric AC-3/E-AC-3 tests in `ffprobe/ts/params.rs` (`ci.yml`) |
| An AAC SBR suffix scan visits candidate headers once per possible alignment rather than retrying every fill length after every empty fill | The single candidate-header range in `aac_ends_with_sbr`; `sbr_payload_can_end_with_bits_that_look_like_an_empty_fill` covers long empty-fill suffixes and ambiguous payload tails |
| The empty-edit fixture byte contract applies only to files registered as generated in their directory's manifest, never ordinary namesakes | The generator's existing `MANIFEST` owns fixture identity; `test_ordinary_namesakes_are_compared_in_both_command_modes` exercises both command modes with absent, unrelated and skipped manifest entries. File names alone cannot prove provenance |
| The AV1 `nclx` fixture exception checks the exact stored colour/range bytes and output pair, and fails when the oracle starts agreeing | `av1_nclx_fixture` runs before both command-comparison loops; `Av1Nclx` tests in `tools/compat-corpus/tests/test_ffmpeg9.py` cover changed bytes, outputs, tags and stale agreement |
| Which keyframe a thumbnail may give is decided in one place | `select::offered` in `coreav-thumbnail`, and the agreement test in `mkv.rs` |
| Frame listings read packet payloads only for streams with a selected decoder | Per-stream `PacketSource::visit` payload requests from `Frames::by_stream`; `frames_request_payloads_only_for_selected_decoders` (`ci.yml`) |
| Chapter-picture packets include their sample bytes when a decoder requests them, just like regular samples | The payload request in `IsoPackets::visit`'s chapter-picture path; `chapter_picture_packets_include_requested_payloads` (`ci.yml`) |
| A frame-oracle timeout or crash fails the run even for a baselined pair, and cannot enter the baseline | `oracle_failed` and unique fixture-name validation in `tools/compat-corpus/frames.py`; `test_baseline_cannot_suppress_or_record_an_oracle_failure` and `test_duplicate_fixture_names_are_refused_before_comparison` (`ci.yml`) |
| Missing FLAC or ALAC configurations, invalid FLAC block-size bounds, and unsupported ALAC cookie versions produce a malformed-configuration warning, not configured audio values | `a_malformed_lossless_configuration_is_refused` in `coreav-isobmff/tests/audio_layouts.rs`; the library parses these bytes before exposing configured values, and `coreav_isobmff::lossless_config` is the one parser of them (the writers read the sample description's values or call it) |
| The audio encodes (`--audio opus`, `--audio aac`) take FLAC or MP3 only, in every build, though the decoder also takes Opus and, with `aac`, AAC | `flac_or_mp3` in `coreav-transcode`'s `audio.rs` is the one place the stream is chosen; the Opus-only, AAC-only and Opus-before-FLAC cases in `coreav-cli/tests/transcode.rs` (`ci.yml`, with and without `aac`) |
| R4 refusal groups are deterministic, pair totals are exclusive and failures take precedence over refusals | One invocation log per call and the committed `R4_REASON_GROUPS` table in `speed.py`; mixed-outcome, duplicate-record, unknown-group, coverage and empty-command regressions in `test_speed_r4.py` |
| Oracle-failed refusal diagnostics use the full invocation predicate without hiding other failures or entering refused-pair counts | `r4_invocation` owns qualification for both paths; outcome/report regressions in `test_speed_r4.py` cover unterminated logs, tool mismatches, mixed events, no-log CoreAV failures, exclusive counters and speed-adjacent diagnostic reasons |
| An R4 infrastructure abort retains completed outcomes and unprocessed eligible pairs without becoming a pass | The runner seeds the full eligible roster before execution and writes it in `finally`; abort-after-progress, missing-abort-marker and host-job report-retention regressions enforce the reporter and driver's nonpassing abort handling |
| Thresholds are committed before the run they judge | Not enforced: judgment (the commit before the run is the evidence) |
| R3 reports every command of its set, including commands no input file reached | `test_every_command_is_reported_even_without_a_file_of_its_families` in `tools/compat-corpus/tests/test_r3.py` |
| A rejected R4 rehearsal retains its public reports for diagnosis | `test_reports_survive_a_rejected_rehearsal` in `scripts/tests/test_compat_workflow.py` |
| Compatibility shards and R4 scans produce nonempty summaries, and aggregation requires every expected shard | Crash and incomplete-input tests in `scripts/tests/test_compat_workflow.py` run the workflow shell blocks |
| R1 uses the registered dist-profile binary and retains its SHA-256 with each fixture result | `test_r1_uses_the_registered_profile_and_records_its_binary_hash` in `scripts/tests/test_compat_workflow.py` executes all three R1 steps |
| Measurement workflow checkouts do not persist Git credentials | `test_measurement_checkouts_do_not_persist_credentials` in `scripts/tests/test_compat_workflow.py` |
| One outcome per pull request; the template's sections; no hard-wrapped body lines | Not enforced: judgment |
| M4A extraction with copied metadata preserves each header's distinct creation and modification times, widening the header when either requires 64 bits | `source_creation_and_modification_times_stay_distinct` in `coreav-isobmff-write/tests/extract.rs` checks stored values in both header versions and the metadata-clearing modes |
| Design notes change in the same pull request as the design | Not enforced: judgment |
| Code is written from specifications, never from other implementations' source | The code-similarity check for `coreav-h264`, `coreav-kernels-h264`, `coreav-opus` and `coreav-kernels-audio` (`docs/design/ci-checks.md`, "Before opening a pull request"); elsewhere review |
