# VideoToolbox ownership, smoke and speed plan

This plan was committed before native implementation and every encoder or timing run of the original ownership work unit. It governs the implemented standalone owner and its tools. The original owner and tools merged in coreav-dev/coreav#289. The ownership design is in [the macOS note](../../../docs/design/encoders/macos.md). The [encoder contract](../../../docs/design/encoders.md) remains the source of the M1 through M5 acceptance bars. This amendment registers source selection, preparation and the prebuilt baseline observation boundary, not transcode integration or an acceptance result. The preparation and fill rules are committed before verification or selection; the stage-one PR and a separately reviewed metadata-only seal merge before judged encoding or timing. This judges encoder behaviour on prepared raw I420, not end-to-end preservation of source colour. Results are a later PR.

## Reference host

For this work, `ENC-MAC-1` is a dedicated Mac mini M1-M: Apple M1, eight CPU cores comprising four performance and four efficiency cores, eight GPU cores, 8 GB unified memory and a 256 GB SSD. This replaces the former Mac mini M4 Pro profile before measurement. Use macOS 15.8.2, build 24H232; record and commit the observed build before judging. Results apply to this OS profile, not macOS 15.7. If that OS image or machine is unavailable, commit a replacement profile before running rather than substitute a virtual machine or a different Mac silently.

Keep one physical allocation for the session. Record hardware identifiers, OS build, framework encoder ID and actual hardware-use status. Do not use a VM, shared CI runner or a different allocation between paired commands. Absolute elapsed times are M1-specific. The speed claim concerns the same-host CoreAV-to-`h264_videotoolbox` ratio, not a claim that M1 matches a newer Mac. Hosted runner timing is diagnostic only and can never satisfy this plan.

No host is provisioned by this PR. Prepare and verify tools before allocating the timed host. Do not rent or run judged inputs merely because the plan exists.

Verify the pinned binaries and the reviewed macOS identity record before every session, cache hit included. Missing or mismatched provenance stops before any input opens.

Before judging, commit an immutable registration containing the merged candidate and tooling revisions, plan digest, complete ordered input roster, source/raw-frame hashes, selected streams, presented-frame counts and clocks, colour/range descriptions, both executable digests and configurations, exact paired commands, host/OS manifest, framework identity, thread settings and metric tool/model hashes. Stage one binds reviewed candidate source-file bytes and tool/plan bytes, not a guessed future squash-merge commit. The later seal supplies actual merged candidate/tooling revisions and reviewed build identities; validation requires those revisions to reproduce the frozen native-source and tool hashes. The source-freeze file itself is committed and reviewed, and the seal binds its exact hash and merged review revision. Host/build facts that do not yet exist cannot be represented by placeholder-compatible runtime records.

### Eligibility and preparation verification gate

Freeze one complete held-out membership snapshot and its digest before opening any source. Record the cutoff, membership digest, tool identities and every disposition. Exclude training membership and duplicate full-source hashes. Both completed metadata catalogs and all their refusals remain immutable; this preparation amendment starts a separate disposition record linked to them, not a rewrite of their outcomes. It changes source preparation and pre-freeze fill rules, not holdout membership, class sizes, resource limits or any encoder acceptance bar.

Run verification only on the isolated cloud worker, never a personal device or public CI. Use the unchanged pinned Linux ffmpeg/ffprobe executables and verify their identities before use. Storage access remains read-only. No candidate or baseline lossy encoder, codec timing or quality metric is permitted. The complete amended gate retains its original persisted start/deadline and byte ledger: at most 8 GiB per source, 100 GiB of source bodies in total, 16 MiB per metadata output, 60 seconds per probe or preparation command, and two hours overall. Verification consumes the remaining budget, not a reset allocation. Stream each downloaded body once through SHA-256 and byte accounting, then probe and prepare only those same verified local bytes. Delete local source and temporary raw files after retaining bounded evidence. Refuse before work if the remaining time, source-body allowance or disk capacity cannot cover it. Raw output has the exact checked extent `width*height*3*N/2`, never a metadata-output exemption for an unbounded file. Global exhaustion produces an incomplete result and a per-class shortfall, not a fresh budget or a smaller passing set.

Use ffprobe's default parameter discovery with fixed `-probesize 5242880 -analyzeduration 5000000`. Retain old and new fields separately. Missing fields and zero-valued invalid geometry/rate placeholders are unknown, not established conflicting facts. Added nested wrapper fields and `r_frame_rate` are diagnostic only. Disagreement between valid positive selected-stream geometry or clock facts refuses; the two already observed positive height disagreements remain refused. Do not silently overwrite an observation or infer a source clock from the raw H.264 advertised rate.

Select the unique default ordinary video stream, or the lowest-index ordinary video stream when none is marked default; refuse ambiguous defaults. Attached pictures are not ordinary video. Require positive even width at most 3840 and positive even height at most 2160, with no resizing or rotation. Require positive exact rational source rate and time base, and a declared integer source frame count. Refuse alpha and anything explicitly marked HDR, including PQ/HLG transfer or BT.2020 primaries/matrix; unsupported formats or conversion tags also refuse. The source need not already be 8-bit 4:2:0, BT.709 limited, or only 8–30 seconds long.

Require retained codec-header proof of progressive frame coding. Capture header-derived `field_order` and applicable sequence-header scan/field-coding indicators, with their exact field names and values. An interlaced or field-coding indication refuses even if another summary says progressive. Absent, unknown, contradictory or unsupported scan evidence refuses; codec name, cadence and absence of an interlace tag do not prove progressive coding. No deinterlacing is permitted. The reviewed codec-specific header reader owns this proof before a candidate can pass.

For exact rational rate `r`, set `N=max(240,ceil(10*r))` using integer arithmetic. Require `N<=1800`, `8<=N/r<=30`, and declared source count at least `N`. Select the first `N` presented pictures after container edits/preroll. No temporal interpolation, duplicate-frame filling, cadence resampling or search for a better segment is allowed. Retain source origin, edits/preroll and audio-start facts separately; rebasing the prefix does not erase them. Capture packet metadata without payloads and prefix frame metadata. Require finite ordered presentation times and positive durations on the original rational grid within half a source tick. Account explicitly for packet-to-picture mapping and discarded preroll; an unexplained count, clock gap, discard or mapping is a refusal. A packet is not assumed to equal a displayed picture. A missing prefix picture or failed decode is a recorded verification failure, never a shorter accepted prefix.

Canonical preparation has one fixed conversion path and uses one decoder thread and one filter thread. Disable implicit filter conversions. Explicitly expand supported non-alpha integer YUV input to same-size planar 16-bit 4:4:4 with the pinned `scale` filter, bilinear chroma interpolation, `accurate_rnd+bitexact` flags and `sws_dither=none`, preserving the resolved source matrix and range. Then use pinned `zscale` with explicit source primaries, transfer, matrix and range, output BT.709 primaries/transfer/matrix and limited range, `dither=ordered`, and explicit output `format=yuv420p`. This fixes the high-bit-depth rounding path and ordered, coordinate-dependent dither before 8-bit quantization; no random dither, mutable seed, automatic tone mapping or alternate conversion path is allowed. Record the complete literal filter/command vectors, executable/configuration identities and every conversion setting. Missing required filter or unsupported pixel format refuses rather than falling back.

For absent source primaries, transfer or matrix tags, the fixed interpretation default is BT.709. For an absent range tag, the default is full for a literal `yuvj` source format and limited otherwise. Explicit supported SDR tags take precedence over defaults and are converted, not relabeled as originally BT.709. Record every missing-tag default per input with the missing field, assumed value and fixed rule, explicitly marked assumption/unobserved. Never place an assumed value in the observed-header record. These conventions define the prepared reference; they make no claim to recover unknown original colour. Require the prepared reference to be exactly `N` progressive I420 pictures at the unchanged rational cadence, and retain its byte extent, whole-file hash, every frame hash, source-clock mapping and preparation diagnostics.

### Deterministic pre-freeze fill rule

Commit this rule and all preparation settings before any new media read or draw. Replay the complete frozen membership and retained headers mechanically to form the candidate pool; never add a source or hand-select a candidate. Assign each source to its native height class. Within each class, order by SHA-256 of the UTF-8 bytes `coreav-encoders-v1:` followed by the full source SHA-256; this literal is the fixed seed. Resolve any unresolved identity/order tie by refusing, not an arbitrary choice.

Visit candidates in that order and take the first ten per class that pass progressive-header, packet, prefix and raw-preparation verification. Record every visited candidate, failure reason, source/tool/command hashes and budget charge. A failed candidate is skipped only by this precommitted rule; there is no hand replacement, changed conversion, replay of a substantive failure or search outside the frozen pool. Stop work in a class once its ten verified sources are fixed. Unvisited later candidates remain explicitly outside the selected prefix of that class, not claimed verified. A class that exhausts its pool or the global budget before ten pass remains short; no passing four-class roster follows from it. After the covered roster freezes, no source may be substituted for any later failure.

## Inputs and paired work

Use the contract's native height-class definitions, with this registration covering the three disjoint classes bounded by 360, 720 and 1080 lines and width at most 3840. Freeze the first ten verification successes per covered class under the deterministic fill rule above. Prepared inputs have 240 through 1800 presented frames, duration 8 through 30 seconds and 8-bit 4:2:0 BT.709-limited output. Commit all thirty inputs, preparation records and their order before any judged encode. Do not substitute after freeze, borrow training inputs, shrink a covered class or relax eligibility after seeing an encoder result.

Prepare one immutable raw reference per selected stream before the timed session. Both commands consume identical hashed frames, geometry, source clock, prepared colour description, range and frame order. The only sample conversion is the explicit, frozen canonical preparation above; no implicit scaling, rotation, additional colour/range conversion, bit-depth change or frame-rate conversion is allowed. Preserve the frame-clock rationals rather than converting timestamps through floating-point seconds. This judges encoder behaviour on prepared raw I420, not end-to-end preservation of source colour.

Hardware-required and software-only encoders are separate cells. The hardware cell is required. Software may be unavailable only when both APIs fail the preflight encode/drain/decode smoke before the roster is encoded. A mismatch between APIs, unknown hardware identity, missing controls or any failure after accepting a frame is a nonpassing result, not an exclusion. Record actual selected encoder IDs and hardware status, not requested preferences.

Both sides use High profile, no frame reordering and a maximum keyframe interval of two seconds. The per-class bitrate targets are 1, 3, 6 and 20 Mbit/s. At a constant frame rate, the frame-count keyframe bound is the floor of two times that rate, paired with the native two-second duration bound. Freeze the corresponding FFmpeg controls from its pinned encoder help before judging; refuse an unmatched setting. Read back effective native controls and check output configuration. Do not translate x264 CRF or preset values to a platform quality scale.

Keep the rational source clock separate from the encoder's `ExpectedFrameRate` optimization hint. CoreAV sets that hint to the nearest whole frames per second, with half-way cases rounded upward, using integer arithmetic, and requires exact integer readback in native settings. For the prebuilt baseline, retain the literal requested command arguments and the corresponding nominal integer hint separately, explicitly labeled unobserved. An input-rate argument or the rounding policy does not prove a baseline session-property readback. This does not round, resample or replace the original `rate`, packet timestamps or frame durations: a 30000/1001 source retains that exact clock and a nominal hint of 30. Never use a raw H.264 demuxer's advertised frame rate to establish that clock. Every existing packet-clock and timestamp-error tolerance remains unchanged.

Independently decoded frame count, profile, level, geometry, pixel format and colour remain output observations. Enforce the existing bitrate, payload-size, keyframe, frame-count and timestamp bars without changing their values. Raw H.264 advertised rate is not a source-clock observation.

## Correctness and quality gates

Every output must decode completely with the pinned FFmpeg H.264 decoder and, within its supported profile, CoreAV's independent decoder. Frame count, dimensions, frame order, colour description and declared times must agree with the reference. Timestamp error is at most half a source tick and A/V start-offset error at most 1 ms where audio exists. Source patterns in synthetic fixtures independently check frame identity; their success is not a substitute for the held-out roster. Parameter sets and sample descriptions must match the decoded stream. Encoded-byte equality is not required.

Quality is checked before a speed result can pass, separately for every available encoder cell and height class as required by M2. Compare every decoded frame to the common reference in fixed presentation order, with no searched alignment. Use the pinned `vmaf_v0.6.1` model at native resolution, all-plane PSNR and SSIM All. Median CoreAV-minus-baseline deltas must be at least -1.0 VMAF, -0.10 dB PSNR and -0.001 SSIM. At least 98% of each class's ten inputs must meet all three per-input floors of -2.0, -0.50 dB and -0.005; every fixture meets those floors. Missing, NaN or invalid metric output fails rather than disappearing from the denominator.

For each output, all-plane clip PSNR is `10 * log10(255^2 * sum(samples) / sum(squared_error))`, pooling every Y/U/V sample of every presented frame. Retain each frame's integer sample count and squared-error sum. Zero total error is explicitly perfect (positive infinity), not a finite cap; equal-perfect CoreAV/baseline PSNR has delta zero, CoreAV-perfect versus finite is an improvement, and finite versus baseline-perfect fails every finite PSNR floor. Replay recomputes these values from retained frame facts bound to decoded/source bytes. VMAF is the arithmetic mean of per-frame `vmaf_v0.6.1` scores at native resolution; SSIM is the arithmetic mean of the pinned filter's per-frame SSIM All values. No frame is omitted.

Each input's elementary-stream payload-size ratio, defined as CoreAV payload bytes divided by FFmpeg payload bytes, must be within 0.95 through 1.05 inclusive. For clips of at least eight seconds, each side's mean payload bitrate must be within 10% of its target. Also record MP4 size when a container is present. Extra bits cannot purchase a quality pass. A standalone elementary-stream result does not establish MP4 indexing or integrated transcode acceptance.

## Timing method and speed bar

Use one warmup and five measured invocations per command and input, alternating AB and BA order. Inputs are warm in the page cache and outputs use the same RAM filesystem. Each invocation begins at process creation and ends after successful output close and direct-child exit. Use a process-exit event or blocking wait, not timeout polling sleeps. Keep finite child/job deadlines, preserve crash and timeout classification, terminate the process group on timeout and reap the child. A failed command cannot produce a time ratio.

The paired command registration includes native frame reporting and FFmpeg's post-encode packet-statistics output; writing that instrumentation is part of the whole-process cost. Retain exact rational packet timestamps and packet sizes. An elementary H.264 stream alone cannot recover the original submission timestamps. The logged EncoderID, same-host encoder-list query, output-derived facts and requested-only settings are frozen in the reviewed records and command registration as described above. Run one identity query after each successful baseline encoder process exits, outside that process's elapsed interval, and retain its separate process record. This is output validation, like independent decoding, not encoder work or a change to the encoder process boundary. A failed or mismatched query invalidates that output and its time. Missing hardware or output evidence fails preflight rather than becoming an inferred identity.

For each input divide the median CoreAV elapsed time by the median FFmpeg elapsed time. The median of those ratios must be at most 1.00 overall and in every height class of each available encoder cell. Report 95% input-level bootstrap confidence intervals with 10,000 resamples and seed 0, plus the share of inputs faster than FFmpeg. A faster claim additionally requires the interval's upper bound below 1.00. Do not pool hardware and software or hide a class miss in an overall median.

Run A/A and null gates before and after the session. A/A median times differ by at most 3%, and the null comparison's 95% interval contains 1.00. No swap, thermal warning, throttling or competing encoder work is allowed. Record thread limits, affinity where the OS supports it, memory limits, OS build and background load. If a gate fails, void the session and retain all evidence. Do not rerun a missed arm unless an evidenced host fault voided it.

The PCM/raw-frame driver and an integrated video-plus-audio command are different results. This work can judge only the raw-frame driver it implements. Integration remains with its owner and needs the same frozen original streams, selected/copied tracks, controls and timestamp/container policy before it can claim M4. Do not present a raw-driver pass as an end-to-end pass.

The smoke submits small, bounded frames, drains, independently decodes and checks exact count/order and source-pattern identity. It records runner image, OS build, selected implementation and hardware status. A recognized unavailable software encoder exercises refusal cleanup and is reported as unavailable, not encoded success. Linux verification of transferred artifacts retains their hashes and verifies the shared pinned decoder before use.

A dropped frame, missing/duplicate identity, early completion, crash, timeout, output change or missing case is nonpassing. No use-after-free, panic or partial final output is permitted. Affected output-reader fuzzing remains in CI. The in-process native API cannot promise an interruptible framework call or a hard teardown deadline; report that limit rather than claim strict-safe isolation.

Timed roster execution is unreachable from PR events. A manual judged mode requires the merged candidate, tooling and registration, a matching fixed-host manifest and complete preconditions above. A hosted diagnostic label cannot be promoted to a judged result. Unit tests cover altered/missing evidence, case coverage, wrong clocks/settings/identity, metric and bitrate failures, ratio aggregation, host-gate failure, process exit/timeout cleanup and retained nonpassing reports without opening the held-out roster.

## Post-merge operation

Prepare the immutable registration validated by `registration.py`, the thirty raw references and covered-class fixtures, the reviewed macOS FFmpeg build/observability record and its companion ffprobe, and the separately hashed Linux decoder and metric model. `producer.py host --report "$HOST"` records sanitized hardware observations; the provider/allocation declaration remains a separate registration fact. No command acquires or installs these prerequisites.

On the Mac and on x86-64 Linux, capture the CoreAV executable build with `python3 scripts/encoders/macos/coreav_build.py --root "$CLEAN_CANDIDATE_CHECKOUT" --cargo-home "$PREPARED_CARGO_HOME" --output "$NEW_EXTERNAL_DIRECTORY"`. The command builds archived clean candidate bytes with the pinned dist toolchain and an isolated target directory, using prepared dependencies without network access. It records the actual build, toolchain, host and binary in `build.json`, alongside `videotoolbox`. Register the two reviewed records through `coreav_builds.macos` and `coreav_builds.linux`, each with `file`, `sha256` and a merged `review_commit`. The Mac record binds `executables.coreav`; the Linux record binds `metric_tools.coreav_decoder`. A candidate revision and an unrelated binary hash are insufficient. The reviewed records are the provenance trust boundary, not a cryptographic proof that arbitrary supplied build assertions are true.

Register a cache observer by executable path and SHA-256, kind `vmtouch-verbose/1`, actual page size and arguments `["-v", "-m", "32G"]`. A null observer is allowed while preparing the schema, but refuses execution. Every warmup and measured side needs complete before/after residency readings. Missing, partial or unsupported readings refuse the campaign; they do not exclude an input or authorize a different Mac.

With `ROOT` naming the clean registered checkout and all paths absolute, capture and analyse in this order:

```sh
python3 scripts/encoders/macos/producer.py preflight --root "$ROOT" --registration "$REG" --output "$PREFLIGHT" --ffprobe "$MAC_FFPROBE"
python3 scripts/encoders/macos/timing.py gate --root "$ROOT" --registration "$REG" --availability "$AVAIL" --ram-output "$RAM" --phase before --report "$BEFORE"
python3 scripts/encoders/macos/timing.py run --root "$ROOT" --registration "$REG" --availability "$AVAIL" --ram-output "$RAM" --before-gate "$BEFORE" --artifacts "$ARTIFACTS" --report "$TIMES"
python3 scripts/encoders/macos/timing.py gate --root "$ROOT" --registration "$REG" --availability "$AVAIL" --ram-output "$RAM" --phase after --report "$AFTER"
python3 scripts/encoders/macos/producer.py fixtures --root "$ROOT" --registration "$REG" --availability "$AVAIL" --capture "$TIMES" --artifacts "$ARTIFACTS" --report "$FIXTURES"
python3 scripts/encoders/macos/producer.py analyse --root "$ROOT" --registration "$REG" --capture "$TIMES" --fixture-capture "$FIXTURES" --artifacts "$ARTIFACTS" --availability "$AVAIL" --before-gate "$BEFORE" --after-gate "$AFTER" --oracle-bin "$ORACLE_BIN" --coreav-decoder "$LINUX_EXPORTER" --model "$MODEL" --output "$EVIDENCE" --storage-root "$STORAGE" --storage-budget-bytes "$BUDGET"
python3 scripts/encoders/macos/timing.py report --root "$ROOT" --registration "$REG" --capture "$TIMES" --artifacts "$ARTIFACTS" --evidence "$EVIDENCE" --report "$RESULT"
```

`AVAIL` is `$PREFLIGHT/availability.json`. Transfer immutable captured bytes before the Linux analysis command, including `gate-before.artifacts` and `gate-after.artifacts` beside their respective reports. Gate JSON contains only hash/extent descriptors; complete trace and packet bytes remain in these directories and are revalidated before replay. Use only a trusted main or manual-dispatch context for analysis. Repeat the exact analysis command with `--resume` after interruption; it rehashes and rederives completed evidence, rebuilds only owned incomplete units and preserves failure history. It cannot recapture timings or turn a substantive decoder/conformance/quality failure into a retry.

`STORAGE` must be an existing persistent-storage root containing the retained artifacts. Choose a separate evidence path beneath it; analysis creates that directory on its first invocation. The capacity gate derives the full retained decode bound from every timed and fixture output, adds 1 GiB of base campaign metadata, 5.25 GiB for the two gates' copied artifacts and 32 GiB for scratch, and requires both the declared byte budget and available space to cover it. The gate-artifact bound is 48 calls times seven files times 16 MiB. Raw references and original prerequisite metadata storage are separate. For scale, two maximum covered-size 3840×1080×1800 I420 decodes need 22,394,880,000 bytes per captured output; one encoder cell has 360 timed outputs before fixtures. A capacity or residency failure is nonpassing, never permission to shrink the frozen roster.
