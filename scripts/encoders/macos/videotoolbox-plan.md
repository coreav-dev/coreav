# VideoToolbox ownership, smoke and speed plan

This plan was committed before native implementation and every encoder or timing run of the original ownership work unit. It governs the implemented standalone owner and its tools. The original owner and tools merged in coreav-dev/coreav#289. The ownership design is in [the macOS note](../../../docs/design/encoders/macos.md). The [encoder contract](../../../docs/design/encoders.md) remains the source of the M1 through M5 acceptance bars. This amendment registers source selection, preparation and the prebuilt baseline observation boundary, not transcode integration or an acceptance result. The amended plan and tools merge before raw preparation, and a separately reviewed metadata-only seal merges before judged timing. Results are a later PR.

## Reference host

For this work, `ENC-MAC-1` is a dedicated Scaleway Mac mini M1-M: Apple M1, eight CPU cores comprising four performance and four efficiency cores, eight GPU cores, 8 GB unified memory and a 256 GB SSD, in Paris. This replaces the former Mac mini M4 Pro profile before measurement. Use macOS 15.7; record and commit its exact build before judging. If that OS image or machine is unavailable, commit a replacement profile before running rather than substitute a virtual machine or a different Mac silently.

Keep one physical allocation for the session. Record hardware identifiers, OS build, framework encoder ID and actual hardware-use status. Do not use a VM, shared CI runner or a different allocation between paired commands. Absolute elapsed times are M1-specific. The speed claim concerns the same-host CoreAV-to-`h264_videotoolbox` ratio, not a claim that M1 matches a newer Mac. Hosted runner timing is diagnostic only and can never satisfy this plan.

No host is provisioned by this PR. Prepare and verify tools before allocating the timed host. Do not rent or run judged inputs merely because the plan exists.

## Tools and registration

The oracle version comes only from `scripts/oracle-ffmpeg.env`. Hosted Linux conformance uses the existing authenticated archive, installer and `oracle_pin.py --verify-bin`, unchanged. macOS encoding artifacts are transferred with hashes; decoding and probing those immutable bytes does not require the encoding host.

The timed baseline is the release-owned pinned prebuilt macOS arm64 FFmpeg with `h264_videotoolbox`, at the shared oracle version and with its exact configuration recorded. A Linux oracle cannot run Apple's encoder or establish the paired Mac time. The macOS executable identity record requires release-owner review before use and binds both extracted executable hashes, exact version-banner tokens, archive provenance, architecture and signing identity to the macOS fields of the shared pin. Its configuration and configuration hash must match the recorded binary; the Linux build token and Linux configuration requirements are not identities of this prebuilt. No binary is redistributed. This plan adds no pin, authorizes no source acquisition or build, and accepts no arbitrary executable with a matching banner. Verify the pinned binaries and the reviewed macOS identity record before every session, cache hit included. Missing or mismatched provenance stops before any input opens.

Before judging, commit an immutable registration containing the merged candidate and tooling revisions, plan digest, complete ordered input roster, source/raw-frame hashes, selected streams, presented-frame counts and clocks, colour/range descriptions, both executable digests and configurations, exact paired commands, host/OS manifest, framework identity, thread settings and metric tool/model hashes. The runner refuses absent, unmerged or dirty registrations and any changed tool, input, plan or setting. Do not leave binary identity to a mutable PATH lookup.

### Two-stage registration

1. The source-registration PR freezes all forty source identities and selected-stream metadata, the complete eligibility cutoff, this plan with every threshold, the selection and preparation tools, and the baseline observation amendment. Selection reads retained metadata only. It opens no judged media and runs no decoder, encoder, probe, metric or timing command on judged inputs. Public records use neutral labels and hashes, with no source URLs, collection categories, storage credentials or private object keys.
2. After the source-registration PR merges, preparation uses only the frozen sources and tools. Prepare immutable raw frames and reviewed executable records, then rent the single registered M1 allocation and record its exact host and OS identity. A separate metadata-only seal PR binds the observed raw-frame hashes, reviewed build records and exact physical-host facts. It changes no threshold, source roster or tool. The seal receives its own review and merges before any timing.

The second stage cannot repair a missing or incomplete first stage, substitute an input or edit a failed result. If preparation exposes an unsupported source, metadata disagreement or another substantive failure, retain it and refuse the round; do not replace that source. Runtime validation continues to refuse absent, incomplete, unmerged or mismatched seals. Expected facts are not observations, and placeholder hashes cannot stand in for facts that have not yet been acquired.

### Eligibility metadata acquisition gate

Commit these criteria before acquiring new metadata. Freeze one complete held-out membership snapshot and its digest before opening any source. Record the catalog cutoff time, membership digest, tool identities and every candidate's disposition. Exclude training membership and duplicate source hashes before selection. Do not add a source, change the pool or hand-substitute a refused file after observing metadata. The only pre-freeze media operation is the pinned Linux ffprobe reading container/stream headers and packet metadata, including counts. Run it on a fresh isolated medium cloud machine, never a personal device or public CI. Do not run a pixel-output decode, encode, time a codec or compute metrics in this gate. Storage access is read-only and the acquisition catalog remains private.

The initial `-nofind_stream_info` method cannot report pixel format for the observed video streams. Preserve that complete catalog and every original refusal. The amended metadata method enables ffprobe's default codec-parameter discovery with explicit `-probesize 5242880 -analyzeduration 5000000` bounds (5 MiB and 5 seconds of media analysis). This permits only parameter discovery, including any internal decoding ffprobe needs for discovery; no decoded frame is output or retained. Keep the existing wall-clock and output caps. Retain the exact command and all available missing stream fields for every frozen row, not only potential selections, and apply the unchanged criteria mechanically to the combined original and newly observed fields. Conflicting previously observed fields refuse rather than silently replace evidence. No `-show_frames`, frame counting, raw-frame output, timing or metric command is allowed. Commit this method amendment before fresh acquisition, use a fresh isolated cloud worker, and bind the new private catalog to the original frozen membership and complete prior catalog. A remaining class deficit is reported before preparation or any rental; no substitution or criterion relaxation follows from it.

Select the unique default ordinary video stream, or the lowest-index ordinary video stream when none is marked default; refuse ambiguous default streams. Attached pictures are not ordinary video. Require positive even width at most 3840 and positive even height at most 2160, exactly `yuv420p`, explicit BT.709 primaries, transfer and matrix, and explicit limited range. Unspecified, mismatched, high-bit-depth, full-range or HDR descriptions do not establish the required reference format and are refused, not converted or guessed. Require a positive exact rational time base and rate, an integer declared frame count from 240 through 1800, and duration from 8 through 30 seconds. Do not estimate a frame count by multiplying rounded duration and rate.

For a header-eligible stream, count its packets without requesting payloads. Require the packet count to equal the declared frame count, finite integer timestamps and positive durations, no discard flags, and unique presentation timestamps matching the constant-rate presentation sequence within the existing half-source-tick tolerance. Packet durations must match that rate within the same tolerance. Retain the selected stream index, original timestamp origin and exact rational rate. These are header/packet-derived expected presentation facts, not decoded-frame observations. Raw preparation after the source-registration merge must independently establish the exact frame count and clock; disagreement refuses the frozen round and never replaces the input.

Record malformed or absent required fields, probe errors, deadlines, timestamp gaps and every other criterion miss as explicit metadata refusals. Hash-check each acquired source against its frozen identity. Never accept a partial or failed probe as a valid catalog row. The acquisition gate permits at most 8 GiB per source, 100 GiB total source bytes, 16 MiB of output per probe, 60 seconds per probe and two hours for the complete gate. Exceeding a whole-gate budget or leaving any candidate unvisited makes the catalog incomplete and unable to freeze a passing roster. An input that cannot be acquired under the byte limits remains unresolved rather than silently becoming ineligible. No quality or timing threshold changes in response to this metadata. Select the first ten eligible sources per height class only after the complete catalog is validated, using the existing hash salt and order. Fewer than ten in any class is an incomplete round, not a reduced set.

## Inputs and paired work

Use the contract's four disjoint height classes, bounded by 360, 720, 1080 and 2160 lines and width at most 3840. Select the first ten eligible held-out inputs in each class by SHA-256 of `coreav-encoders-v1:` followed by the full file hash. Inputs have 240 through 1800 presented frames, duration 8 through 30 seconds and 8-bit 4:2:0 SDR output. Commit all forty inputs and their order before the run. Do not replace failures, borrow training inputs, shrink an incomplete class or relax eligibility after seeing a result.

Prepare one immutable raw reference per selected stream before the timed session. Both commands consume identical frames, geometry, source clock, colour description, range and frame order. No implicit scaling, rotation, colour/range conversion, bit-depth change or frame-rate conversion is allowed. Preserve the frame-clock rationals rather than converting timestamps through floating-point seconds.

Hardware-required and software-only encoders are separate cells. The hardware cell is required. Software may be unavailable only when both APIs fail the preflight encode/drain/decode smoke before the roster is encoded. A mismatch between APIs, unknown hardware identity, missing controls or any failure after accepting a frame is a nonpassing result, not an exclusion. Record actual selected encoder IDs and hardware status, not requested preferences.

Both sides use High profile, no frame reordering and a maximum keyframe interval of two seconds. The per-class bitrate targets are 1, 3, 6 and 20 Mbit/s. At a constant frame rate, the frame-count keyframe bound is the floor of two times that rate, paired with the native two-second duration bound. Freeze the corresponding FFmpeg controls from its pinned encoder help before judging; refuse an unmatched setting. Read back effective native controls and check output configuration. Do not translate x264 CRF or preset values to a platform quality scale.

Keep the rational source clock separate from the encoder's `ExpectedFrameRate` optimization hint. CoreAV sets that hint to the nearest whole frames per second, with half-way cases rounded upward, using integer arithmetic, and requires exact integer readback in native settings. For the prebuilt baseline, retain the literal requested command arguments and the corresponding nominal integer hint separately, explicitly labeled unobserved. An input-rate argument or the rounding policy does not prove a baseline session-property readback. This does not round, resample or replace the original `rate`, packet timestamps or frame durations: a 30000/1001 source retains that exact clock and a nominal hint of 30. Never use a raw H.264 demuxer's advertised frame rate to establish that clock. Every existing packet-clock and timestamp-error tolerance remains unchanged.

## Baseline observation boundary

The prebuilt logs its actual session EncoderID, but not every VideoToolbox session property. Keep observed facts separate from requested settings; do not fill missing readbacks with requested values.

- Resolve the exact logged EncoderID with CoreAV's own bounded encoder-list query on the same registered physical host. Require exactly one matching entry and an explicit runtime-checked hardware flag, as for native admission. Missing flags, ambiguous matches, invalid objects and unknown identities fail closed. Bind the query, its executable, the retained trace and the host identity to the output evidence. An encoder name or a hardware-selection option is not hardware evidence. Judge only cells where both arms' hardware status is established; this does not turn unknown software status into unavailability.
- Derive baseline payload bitrate, frame- and time-based keyframe bounds and reordering behavior from the complete output and the encoder's exact packet ledger. Independently decoded frame count, profile, level, geometry, pixel format and colour remain output observations. Enforce the existing bitrate, payload-size, keyframe, frame-count and timestamp bars without changing their values. Raw H.264 advertised rate is not a source-clock observation.
- Retain realtime, nominal integer frame-rate hint and rate-control arguments as requested-only, with an explicit unobserved label. Retain the literal option vector, including absent options, rather than invent a default or effective mode. Never label these fields observed or use them to claim equal effective framework settings. Their observability limit accompanies every result.

The macOS baseline identity change is limited to the pinned prebuilt's provenance. Keep all other `baseline_build` validation, reviewed-record requirements and fail-closed behavior. The registration tools must reject incomplete observation records before a judged cell is accepted. Synthetic regressions cover changed or unmatched IDs, duplicate/missing/wrong flags, cross-host query records, requested-as-observed substitutions, output-ledger disagreement and misleading raw advertised rates. This amendment changes evidence sources and labels, not a numerical tolerance or acceptance threshold. It precedes every run using the amended contract and requires the native/evidence owner's sign-off.

## Hosted software observability

Hosted CI does not exercise the software encode path. Its software-only check records a separate typed refusal only when initial session creation observes an EncoderID, exactly one encoder-list entry matches that ID, and that entry has no hardware flag. Missing IDs, duplicate or unmatched entries, invalid flags, any other missing required field and every other refusal still fail. The refusal is not encoded output, availability, encoder absence or a conformance pass, and it enters no such count or summary.

This hosted-only exemption must fail with an instruction to remove it if hardware status becomes observable. Hardware-required and automatic hosted cells still encode and pass full independent-decoder verification. Judged preflight rejects the hosted refusal even for software, with a regression preventing it from becoming an unavailable cell. Production admission remains fail-closed. Software encode verification is deferred to the post-merge Apple-silicon run; that run still requires observable status and cannot use this exemption.

## Correctness and quality gates

Every output must decode completely with the pinned FFmpeg H.264 decoder and, within its supported profile, CoreAV's independent decoder. Frame count, dimensions, frame order, colour description and declared times must agree with the reference. Timestamp error is at most half a source tick and A/V start-offset error at most 1 ms where audio exists. Source patterns in synthetic fixtures independently check frame identity; their success is not a substitute for the held-out roster. Parameter sets and sample descriptions must match the decoded stream. Encoded-byte equality is not required.

Quality is checked before a speed result can pass, separately for every available encoder cell and height class as required by M2. Compare every decoded frame to the common reference in fixed presentation order, with no searched alignment. Use the pinned `vmaf_v0.6.1` model at native resolution, all-plane PSNR and SSIM All. Median CoreAV-minus-baseline deltas must be at least -1.0 VMAF, -0.10 dB PSNR and -0.001 SSIM. At least 98% of each class's ten inputs must meet all three per-input floors of -2.0, -0.50 dB and -0.005; every fixture meets those floors. Missing, NaN or invalid metric output fails rather than disappearing from the denominator.

For each output, all-plane clip PSNR is `10 * log10(255^2 * sum(samples) / sum(squared_error))`, pooling every Y/U/V sample of every presented frame. Retain each frame's integer sample count and squared-error sum. Zero total error is explicitly perfect (positive infinity), not a finite cap; equal-perfect CoreAV/baseline PSNR has delta zero, CoreAV-perfect versus finite is an improvement, and finite versus baseline-perfect fails every finite PSNR floor. Replay recomputes these values from retained frame facts bound to decoded/source bytes. VMAF is the arithmetic mean of per-frame `vmaf_v0.6.1` scores at native resolution; SSIM is the arithmetic mean of the pinned filter's per-frame SSIM All values. No frame is omitted.

Each input's elementary-stream payload-size ratio, defined as CoreAV payload bytes divided by FFmpeg payload bytes, must be within 0.95 through 1.05 inclusive. For clips of at least eight seconds, each side's mean payload bitrate must be within 10% of its target. Also record MP4 size when a container is present. Extra bits cannot purchase a quality pass. A standalone elementary-stream result does not establish MP4 indexing or integrated transcode acceptance.

## Timing method and speed bar

Use one warmup and five measured invocations per command and input, alternating AB and BA order. Inputs are warm in the page cache and outputs use the same RAM filesystem. Each invocation begins at process creation and ends after successful output close and direct-child exit. Use a process-exit event or blocking wait, not timeout polling sleeps. Keep finite child/job deadlines, preserve crash and timeout classification, terminate the process group on timeout and reap the child. A failed command cannot produce a time ratio.

The paired command registration includes native frame reporting and FFmpeg's post-encode packet-statistics output; writing that instrumentation is part of the whole-process cost. Retain exact rational packet timestamps and packet sizes. An elementary H.264 stream alone cannot recover the original submission timestamps. The logged EncoderID, same-host encoder-list query, output-derived facts and requested-only settings are frozen in the reviewed records and command registration as described above. Run one identity query after each successful baseline encoder process exits, outside that process's elapsed interval, and retain its separate process record. This is output validation, like independent decoding, not encoder work or a change to the encoder process boundary. A failed or mismatched query invalidates that output and its time. Missing hardware or output evidence fails preflight rather than becoming an inferred identity.

For each input divide the median CoreAV elapsed time by the median FFmpeg elapsed time. The median of those ratios must be at most 1.00 overall and in every height class of each available encoder cell. Report 95% input-level bootstrap confidence intervals with 10,000 resamples and seed 0, plus the share of inputs faster than FFmpeg. A faster claim additionally requires the interval's upper bound below 1.00. Do not pool hardware and software or hide a class miss in an overall median.

Run A/A and null gates before and after the session. A/A median times differ by at most 3%, and the null comparison's 95% interval contains 1.00. No swap, thermal warning, throttling or competing encoder work is allowed. Record thread limits, affinity where the OS supports it, memory limits, OS build and background load. If a gate fails, void the session and retain all evidence. Do not rerun a missed arm unless an evidenced host fault voided it.

The PCM/raw-frame driver and an integrated video-plus-audio command are different results. This work can judge only the raw-frame driver it implements. Integration remains with its owner and needs the same frozen original streams, selected/copied tracks, controls and timestamp/container policy before it can claim M4. Do not present a raw-driver pass as an end-to-end pass.

## Hosted smoke and safety

PR CI runs safe-model and tooling regressions, native builds and synthetic correctness smoke on hosted macOS. The smoke submits small, bounded frames, drains, independently decodes and checks exact count/order and source-pattern identity. It records runner image, OS build, selected implementation and hardware status. A recognized unavailable software encoder exercises refusal cleanup and is reported as unavailable, not encoded success. Linux verification of transferred artifacts retains their hashes and verifies the shared pinned decoder before use.

All callback lifetime, reentrancy, overlapping-copy completion, cancellation, unavailable encoder, oversized output, malformed configuration, bounded-queue and cleanup fixtures must pass. A dropped frame, missing/duplicate identity, early completion, crash, timeout, output change or missing case is nonpassing. No use-after-free, panic or partial final output is permitted. Affected output-reader fuzzing remains in CI. The in-process native API cannot promise an interruptible framework call or a hard teardown deadline; report that limit rather than claim strict-safe isolation.

Timed roster execution is unreachable from PR events. A manual judged mode requires the merged candidate, tooling and registration, a matching fixed-host manifest and complete preconditions above. A hosted diagnostic label cannot be promoted to a judged result. Unit tests cover altered/missing evidence, case coverage, wrong clocks/settings/identity, metric and bitrate failures, ratio aggregation, host-gate failure, process exit/timeout cleanup and retained nonpassing reports without opening the held-out roster.

## Post-merge operation

Prepare the immutable registration validated by `registration.py`, the forty raw references and fixtures, the reviewed macOS FFmpeg build/observability record and its companion ffprobe, and the separately hashed Linux decoder and metric model. `producer.py host --report "$HOST"` records sanitized hardware observations; the provider/allocation declaration remains a separate registration fact. No command acquires or installs these prerequisites.

On the Mac and on x86-64 Linux, capture the CoreAV executable build with `python3 scripts/encoders/macos/coreav_build.py --root "$CLEAN_CANDIDATE_CHECKOUT" --cargo-home "$PREPARED_CARGO_HOME" --output "$NEW_EXTERNAL_DIRECTORY"`. The command builds archived clean candidate bytes with the pinned dist toolchain and an isolated target directory, using prepared dependencies without network access. It records the actual build, toolchain, host and binary in `build.json`, alongside `videotoolbox`. Register the two reviewed records through `coreav_builds.macos` and `coreav_builds.linux`, each with `file`, `sha256` and a merged `review_commit`. The Mac record binds `executables.coreav`; the Linux record binds `metric_tools.coreav_decoder`. A candidate revision and an unrelated binary hash are insufficient. The reviewed records are the provenance trust boundary, not a cryptographic proof that arbitrary supplied build assertions are true.

Register a cache observer by executable path and SHA-256, kind `vmtouch-verbose/1`, actual page size and arguments `["-v", "-m", "32G"]`. A null observer is allowed while preparing the schema, but refuses execution. Every warmup and measured side needs complete before/after residency readings. Missing, partial or unsupported readings refuse the campaign; they do not exclude an input or authorize a different Mac.

With `ROOT` naming the clean registered checkout and all paths absolute, capture and analyse in this order:

```sh
python3 scripts/encoders/macos/producer.py preflight --root "$ROOT" --registration "$REG" --output "$PREFLIGHT" --ffprobe "$MAC_FFPROBE"
python3 scripts/encoders/macos/timing.py gate --root "$ROOT" --registration "$REG" --availability "$AVAIL" --ram-output "$RAM" --phase before --report "$BEFORE"
python3 scripts/encoders/macos/timing.py run --root "$ROOT" --registration "$REG" --availability "$AVAIL" --ram-output "$RAM" --before-gate "$BEFORE" --artifacts "$ARTIFACTS" --report "$TIMES"
python3 scripts/encoders/macos/timing.py gate --root "$ROOT" --registration "$REG" --availability "$AVAIL" --ram-output "$RAM" --phase after --report "$AFTER"
python3 scripts/encoders/macos/producer.py fixtures --root "$ROOT" --registration "$REG" --availability "$AVAIL" --capture "$TIMES" --artifacts "$ARTIFACTS" --report "$FIXTURES"
python3 scripts/encoders/macos/producer.py analyse --root "$ROOT" --registration "$REG" --capture "$TIMES" --fixture-capture "$FIXTURES" --artifacts "$ARTIFACTS" --availability "$AVAIL" --before-gate "$BEFORE" --after-gate "$AFTER" --oracle-bin "$ORACLE_BIN" --coreav-decoder "$LINUX_EXPORTER" --model "$MODEL" --output "$EVIDENCE" --storage-root "$STORAGE" --storage-budget-bytes "$BUDGET"
python3 scripts/encoders/macos/timing.py report --root "$ROOT" --registration "$REG" --capture "$TIMES" --artifacts "$ARTIFACTS" --evidence "$EVIDENCE" --report "$RESULT"
```

`AVAIL` is `$PREFLIGHT/availability.json`. Transfer immutable captured bytes before the Linux analysis command. Use only a trusted main or manual-dispatch context for analysis. Repeat the exact analysis command with `--resume` after interruption; it rehashes and rederives completed evidence, rebuilds only owned incomplete units and preserves failure history. It cannot recapture timings or turn a substantive decoder/conformance/quality failure into a retry.

`STORAGE` must be an existing persistent-storage root containing the retained artifacts. Choose a separate evidence path beneath it; analysis creates that directory on its first invocation. The capacity gate derives the full retained decode bound from every timed and fixture output, adds 1 GiB for campaign metadata and 32 GiB for scratch, and requires both the declared byte budget and available space to cover it. Raw reference storage is separate. For scale, two maximum-size 3840×2160×1800 I420 decodes need 44,789,760,000 bytes per captured output; one encoder cell has 480 timed outputs before fixtures. A capacity or residency failure is nonpassing, never permission to shrink the frozen roster.
