# H.264: changes measurement rejected

A rejection is conditional on what the decoder was bound by when it was
measured. A vector kernel can lose while memory traffic dominates and win
once that is gone, so nothing here is thrown away: each row names a branch
that still holds the change, rebuilt on a recent tip so it can be measured
against current code rather than against the code it was written for.

**Re-test these after any structural change that moves the bottleneck** —
the memory-traffic work, and later threading. Run each alone on top of the
new baseline, then the promising pairs as a small factorial (A, B, A+B):
two changes that each do nothing can still do something together, and two
that each help can overlap. Accept only what wins in the same session, on a
pinned core, by the same rule as any other change.

## What the pattern says

Two of the five are measured on both axes and dropped instructions
without moving the clock; one *raised* instructions; and two were
rejected on one axis before the other was measured. So the table
supports the pattern rather than proving it — but the pattern is firm
from elsewhere: by the time these were tried, the cheap high-throughput
instructions were already gone, and what remained was bound by latency or
by memory bandwidth. On the same stream, against FFmpeg's
decode-only 2,099 instructions per macroblock, the decoder went from
5.16x its instructions to 2.79x. The time ratios beside those (3.30x
then 2.45x) are from separate sessions and are not directly comparable —
this machine's absolute ratios drift, and only paired same-session
comparisons are quoted elsewhere in these notes. What is solid is the
instruction ratio halving while the clock did not, which is the same
statement in a form the evidence supports.

The change that did pay in the same period moved no instructions at all:
clearing a picture's motion per macroblock instead of per picture is
−0.36% of instructions and −5.3% of wall time
([`h264-rounds/motion-clear-ab.json`](h264-rounds/motion-clear-ab.json):
paired median 0.947 over 13 rounds), because it removes 2.6 MB of stores
a picture rather than work.

So the order of evidence has inverted. Instructions localise where the
work is; only the clock decides whether removing it was worth anything.
