# Transcode

Encode path, sandboxed workers, and audio-encode selection.

| Rule | Enforced by |
|---|---|
| The ffmpeg adapter's AAC MP4 timing ends a partially presented final sample at priming plus the submitted sample count without changing native transcode bytes, edits or Matroska frames | `mp4_audio_samples` owns the terminal delta, selected by the adapter-only `aac_mp4_tail` policy for replacement tracks. `aac_terminal_timing_matches_the_complete_oracle_boxes` compares complete stts, mdhd and elst bytes and full decoded audio with the pinned oracle. Replacement regressions preserve the default complete-frame timing, exact boundaries, wholly padded packets and Opus durations; the unchanged legacy-encoder comparison retains byte-strict native transcode verification. Runtime oracle bytes cannot be established by codec frame length alone |
| MP3 Xing/Info seek positions retain the pinned oracle's integer-percentile and long-file rounding without changing command admission | `mp3::info_frame` owns the frame-size index and its seek resolution. `ffmpeg_mp3_information_headers_match_complete_oracle_files` checks complete CBR/VBR files from generated lossless sources, verifies the actual reference frame counts and covers both sides of the 400/800/1600-frame resolution changes. The header definition gives approximate positions but no normative encoder rounding; external byte identity needs a runtime comparison |
| Legacy encoder comparisons admit only a source-declared SAR delta, including its exact forced output length | `sar_delta::check` compares every other summary byte, exit code, stderr, box field and complete `mdat` payload exactly; SPS changes use the audited owner's bit boundary and exact RBSP splice. The full legacy gate retains its reference and decodes both outputs; pure mutations and an actual-case `mdat` mutation reject non-SAR changes with named fields. Structural growth, not a file allowlist, owns `output.bytes` |
| Unscaled H.264 encoding retains valid source sample-aspect declarations, including square pixels, without changing scale normalization | `sample_aspect` receives an optional scale result rather than inferring a scale request from dimensions. The declared/absent/invalid unit matrix and `unscaled_encoding_preserves_declared_sar_without_changing_scale` cover summary, `pasp`, encoder signalling and exact declared-source output; identity-scale controls retain normalization. The strict-safe controls query `coreav_worker::enforces_memory_limit` and assert the exact closed refusal on unsupported hosts, while retaining success and pixel comparisons on supported hosts. A ratio's numerical value cannot encode declaration presence, and a decoder feature cannot prove sandbox capability |
| Unscaled AV1 input retains CPU or shared storage through the common encoder writer, including its direct-pipe capability | `Process::spawn` delegates to the same retaining launch path; `shared_av1_input_is_not_downloaded_without_scaling` checks the original shared owner and the scaling control, while `shared_frame_pipe` checks complete protocol bytes, direct writes without parent reads and owner release. The required AV1 fixture also transcodes a real AV1 source. Storage kinds are explicit in `Pixels`; pipe support remains an external runtime capability |
| Kernel-page lookup does not need procfs or an auxiliary-vector syscall after sandboxing | The Linux rustix dependency selects `use-libc-auxv`, so page sizing uses libc's process-initialized value. A no-procfs mount namespace with auxv `prctl` unavailable reproduced the old panic and passes with this feature; a page-count type cannot control dependency initialization |
| Shared slots and decoder allocation capacities align to the kernel's page size, not a fixed 4 KiB | `shm::page_len` owns checked rounding for both parent sizing and pool allocation, and `Pool::open` rejects misaligned slots. Native-page pool/reclamation tests and `page_rounding_covers_large_page_kernels_and_overflow` cover 4, 16 and 64 KiB pages and overflow. Types cannot infer the host kernel's mapping granularity |
| Evicting a decoder pool mapping releases its shared-file backing pages before returning its capacity budget | `Pool::reclaim` owns hole punching and capacity release. `growing_a_released_buffer_keeps_its_shared_slot` writes the old allocation and checks the memfd block count after eviction. Removing a mapping alone leaves shared-file pages resident, so mapped-capacity types cannot enforce this kernel storage lifetime |
| Strict-safe diagnostic tests prove the diagnostic refusal rather than accepting CLI usage or earlier platform errors | `in_process_diagnostics_refuse_strict_safe` checks the boundary directly on every platform; `diagnostic_errors_precede_media_probing` passes the root option before the subcommand, requires structured error JSON and checks the exact diagnostic on Linux, or the earlier OS-limit refusal elsewhere. A generic stderr substring cannot establish which boundary ran |
| Once native FFV1 encoding starts, changed frames and decoder capability failures are terminal and never enter compatibility fallback | `Run::refused` and `Run::decode_error` classify errors from the existing encoder state; `InvalidFrame` maps to invalid data, not an unsupported-input refusal. The shape snapshot stores raw frame colour before container inheritance, so disappearing declarations cannot be masked. `late_frame_changes_are_terminal_without_publishing_another_packet` covers geometry, pixel format, colour changes and disappearing colour. `ffv1_check.py` changes geometry and colour mid-stream and requires specific diagnostics, exit 1, an unchanged destination and no fallback log entry in required CI, with colour checked in both strict modes. Negative tests reject unrelated exit-1 causes. Runtime decoder output and external diagnostics cannot be fixed by a static source format type |
| AVI MP3 uses the shared PCM feeder and audited reader without changing its complete frames or packet clock | `audio::encode_with` owns process settings, sample feeding and readback for both callers; `EncodedAudio::mp3_packets` only retains checked frames. `ffmpeg_avi_mp3_keeps_the_previous_complete_file_bytes` compares entire AVI files with the former raw-pipe encoder invocation and unchanged AVI writer, including mono/stereo, MPEG rate families, default/explicit bitrates and EOF boundaries (`ci.yml`). An external encoder's byte identity needs a runtime comparison |
| MP3 encoding validates the full PCM count including its EOF zero guard, then removes that explicit guard in the gapless tag | The shared audio feeder counts original and fed samples separately; `mp3::read_output` requires the frame-aligned libmp3lame flush count and documented default encoder delay. `ffmpeg_mp3_eof_guard_preserves_exact_boundary_lengths` checks seekable oracle decoding and ffprobe at residues 1, 46 and 47 in all three MPEG rate families; malformed, truncated and out-of-bound output is covered by `mp3` unit tests and the `mp3_output` fuzz target |
| MP3 encoder readback audits the entire spool and rejects extra metadata, information frames and changed framing under the encode deadline | `mp3::read_output` owns the strict ID3 and complete-frame walk without resynchronization. `full_output_structure_auxiliary_data_and_timestamps_are_checked` covers appended bytes, metadata mutations, information frames, changed channels and bit rates. `TimedSource` checks cached parser reads too; `readback_checks_the_deadline_inside_parser_reads` requires timeout classification and at most one underlying read after a controlled deadline crossing |
| An external MP3 encode starts only encoder-only MP3 commands, with no help probe or external container adaptation | The availability probe and MP3 feeder share the argument owner; `mp3_worker_starts_and_output_pass_the_frozen_checks` observes every sandboxed start with the existing FIFO logger, applies the unchanged frozen classifier and compares complete decoded output and timing with the pinned oracle in both source builds (`ci.yml`). Static argument types cannot prove actual external process starts |
| AAC availability starts only an empty raw-PCM encode and retains the worker's limits and terminal failure classes | `probe_encoder` shares the AAC feeder's argument owner and bounds both codec probes to 64 KiB. `aac_worker_starts_and_output_pass_the_frozen_checks` observes every actual start through the unchanged classifier and compares complete decoded output and frame timing on generated lossless sources in both source builds. The availability regressions preserve missing-encoder classification, signal failures and output-limit errors. Runtime subprocess starts and exits cannot be established by an argument vector's type |
| AAC PCM-verification stand-ins accept empty availability input without substituting source samples, and still reject changed nonempty input | `audio_encodes_preserve_the_decoders_presented_samples` passes each actual stdin byte to FFmpeg, compares nonempty input with the native decoder output and proves rejection with a one-byte mutation. Missing-encoder stand-ins use the real nonzero-exit diagnostic. A subprocess argument type cannot establish its stdin bytes or an external diagnostic |
| A missing external MP3 encoder refuses on its diagnostic after a normal nonzero exit, without assuming exit status 1 or converting resource and signal failures into refusals | `probe_encoder` owns the classification; `mp3_availability_errors_keep_their_classification_and_output_bound` checks statuses 1 and 8 and preserves terminal flood and signal failures even when their stderr contains the missing-encoder diagnostic. The external program's exit convention and diagnostic require runtime checks rather than a static type |
| A failed B9 baseline preserves explicit `-an` and otherwise retains the remux audio expectation; it supplies no quality evidence | `check_compat` derives explicit audio absence from its command tokens. The baseline-failure regressions in `scripts/transcode_check_selftest.py` check both expectations, rejection of unexpected audio and failed Q1/Q2 judgments. External command outcomes need runtime checks |
| Audio encodes take the first source stream the build decodes, or the explicitly selected stream, applying source trimming once before output encoder delay | `coreav_audio::decode` owns stream selection and presentation trimming; `Codec::from_name` supplies the CLI's build-aware capability check. The AAC-only, Opus-only, Opus-before-FLAC and timing cases in `coreav-cli/tests/transcode.rs` run with and without `aac` (`ci.yml`) |
| A stopped encoder returns its queued decoder slots without destroying queued caller-provided frames on the caller's thread | The encoder keeper owns queued-frame disposal after process teardown; the frame-pool, early-exit and closed-input cases in `coreav-transcode/tests/sandboxed.rs` check nonblocking caller cleanup and prompt slot return |
| A worker child-lifetime test waits for termination, not zombie reaping or a reusable PID pathname | `the_backends_children_end_with_the_worker` opens a Linux pidfd while the child is alive and waits for its exit event within the existing grace period (`ci.yml`). A `/proc` state can change from zombie to dead between reads without the process becoming alive again |
| Finishing an encoder killed after it closes its input reports a backend error before the deadline, not a timeout | `finish` delegates killed-exit classification to `fail`, which owns error precedence and the deadline check; `finish_with_closed_input` in `coreav-transcode/tests/sandboxed.rs` runs a real child with one oversized frame so the error must come from `finish` |
| The transcode audio-refusal list agrees with muxer default-codec admission | Not enforced: judgment. The audio bullet refers to the one default-codec description rather than repeating an explicit-codec-only rule; a syntax check cannot establish the meaning of arbitrary prose |
| Stored compatibility results retain lossless PSNR infinity without weakening strict receipt JSON | `test_lossless_psnr_infinity_survives_resume_export_and_merge_in_both_versions` checks both readers against the existing writer; `json_document` still rejects nonfinite control values. Runtime metrics cannot be represented by a finite-only JSON reader |
| The registered comparator download follows HTTPS redirects before checking the unchanged archive digest | `build_comparator` owns the HTTPS-only curl command; the redirect-body regression in `test_composed_audio.py` rejects hashing the redirect response instead of the archive |
| Encoder-input receipts report resource limits only when a launcher was supplied | The optional launcher in `audio::encode` owns the optional receipt limits. These fields describe supplied limits, not proof that an operating system enforced them; that remains review judgment |
| Current compatibility evidence cannot change its configuration, file or command by moving its cache entry or removing only outer version markers | `validate_result` checks the requested key at resume, summary, export and merge boundaries; the moved-key and stripped-marker regressions in `test_transcode_merge.py` reject relabeling before judgment |
| New composed-check command expectations do not modify the inherited audio-policy checker | The registered runtime owner is separate; `check_policy` and `test_the_inherited_audio_policy_checker_keeps_its_registered_bytes` check the restored base bytes without updating historical judging records |
| A composed Matroska source reference validates every decoded frame timestamp at the declared clock precision, not only its origin and total sample count | `source_reference` checks the positive bounded time base and the complete cumulative sample clock, quantized to its represented tick. The gap, overlap, reorder, interior displacement and malformed/coarse-clock regressions in `test_composed_audio.py` exercise the acquisition boundary; a summed count cannot prove an external timeline |
| The composed first-audio mapping case applies only when source preflight finds an audio stream; an absent mandatory map cannot produce a video-quality judgment | `fixture_inputs` owns applicability before acquisition. `test_first_audio_mapping_applies_only_to_sources_with_audio` preserves every legacy command and all audio-bearing mapped cases while excluding only the inapplicable new case |
| AV1 sample-spool timing comes from the completed global submission ledger, never segment-local native timestamps | `av1::OutputSink` owns wire and sample validation, exact configuration assembly and bounded payload replay into `Packets`. Synthetic segmented regressions preserve original variable clocks, both timestamp origins, final duration and sync positions, while refusing changed configuration, reset global identities, invalid native assertions, incomplete output, count mismatches and changed spool extents. Actual native and end-to-end container execution remain separate gates |
| An expired prepared AV1 job returns timeout before accessing its source | `Av1Transcode::run` is the sole prepared entry and checks its stored deadline before calling the shared engine. `expired_prepared_job_does_not_access_the_source` requires timeout, zero source accesses, no decoder opening and no spool or output. Expiry depends on elapsed time, so a type cannot establish it |
| AV1 spool cleanup assertions allow asynchronous process actors to release their retained owner | `synthetic_common_engine_keeps_source_times_and_copied_audio` requires observable release within a fixed deadline rather than immediate deletion when actor completion is received. `process_threads_keep_the_private_spool_owner_after_caller_drop` separately blocks the active reader and proves retention until release. Actor scheduling cannot be established by the completion channel's type |
| Private AV1 worker availability requires the CLI's own native feature, not only an enabled dependency feature | `transcode::av1::compiled` owns the CLI-native and `Av1Transcode::compiled()` conjunction for both public selection and private dispatch, before media or worker I/O. `parser_only_entry_is_unavailable_without_emitting_worker_output` requires the unavailable diagnostic when the CLI feature is absent. Cargo features are additive, so a dependency's native feature cannot establish that its caller compiled the dispatch arm |
| AV1 quality arguments do not change H.264 parser errors or their precedence | `parse_args` retains the original parser's result unless complete parsed arguments or a complete lexical projection select explicit AV1. The AV1 quality parser belongs only to that branch. `legacy_parser_errors_keep_their_bytes_and_precedence` compares error kind, exit code and complete text for invalid settings, missing arguments, unknown options and conflicts. Codec selection depends on argument values, so the static argument field types cannot choose the parser |
| An embedded command cannot claim to host the standalone AV1 worker | The embedding entry always supplies the private `CommandHost::Embedded` variant; only the binary entry supplies `Standalone` after worker dispatch. `embedded_host_refusal_precedes_build_and_source_checks` requires the host refusal before build availability or missing-source errors. Neither an executable path nor unified Cargo features establishes an entry hook |
| AV1 CRF admission validates the original integer token before deriving a floating-point value | Every explicit AV1 route reparses with `parse_av1_crf`, which admits a bounded `u8` before converting exactly to `f32`; a successful legacy probe cannot authorize AV1. `av1_crf_admission_uses_the_exact_integer_token` rejects fractional tokens rounded to integers or zero, ordinary fractions and out-of-range integers before source/output access. Valid boundary controls cover both parser paths. The shared float field remains necessary for fractional H.264 CRF |
| Native FFV1 refuses declared chroma siting that the Matroska writer cannot retain | `colour` owns admission for both stream and frame metadata; packet-admission tests reject all five non-left locations before encoder creation or packet publication. The required CLI gate verifies a real centered-chroma source and its specific refusal, while negative tests reject wrong source signalling, false success and unrelated errors. Frame types alone cannot express which metadata a selected container writer preserves |
| The `coreav ffmpeg` video encode (H.264/AV1), audio encode and FFV1 jobs run under one command limit, never a library default such as the 60-second decoder timeout; the AVI MP3 encode keeps its own 120-second deadline | `ffmpeg::ENCODE_LIMIT` is the single owner that the encode request, the audio deadline and the FFV1 job options read. `the_encode_has_the_same_command_limit_as_other_encodes` failed on the FFV1 job's former 60-second default.
