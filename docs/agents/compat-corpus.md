# Compatibility corpus

Corpus exclusions, compatibility workflows, fixture comparisons, and the B4 and R4 drivers.

| Rule | Enforced by |
|---|---|
| Encode-breadth preflight verifies the exact supplied oracle executable, and an encoder start proves only its own codec's invocation | `oracle_programs` binds the supplied paths to the pinned installation before running commands; the AAC gate calls `aac_encoder_start`, not the general encoder allowlist. The unpinned-sibling and MP3-versus-AAC regressions in `test_encode_breadth.py` cover these external invocation boundaries, which Python argument types cannot prove |
| Corpus row exclusions require valid captures, observed values or the sole registered byte-proven absence, and field/case scopes authorized at the plan cutoff | The capture validators and `Registry` in `tools/compat-corpus/corpus_kd.py` own these boundaries. `ProvenAbsence` derives the decoded frame end from the ASC flag at a matching core-rate media clock, not from stored sample duration; its named 700-tick/324-padding deletion regression refuses the former loophole. It remains restricted to KD-FF9-EMPTY-EDIT-PADDING's frozen scope, sample/packet identity and other-packet agreement. JSON values and historical records require runtime validation; an adapter's return type alone cannot prove their validity |
| Cached corpus audit replay recomputes every adapter-reachable attacked occurrence against its attacked context | Read-only packet rows permit skipping only unchanged leaves outside evidenced rule scopes; `test_corpus_replay.py` compares exact streaming judgments, including section-to-packet coverage activation and bounded-cache fallbacks. Object identity proves equal values, not coverage |
| Prepared corpus evidence is bound to its input bytes, not only their paths | `Prepared` snapshots media and registered reader digests before acquisition and verifies them around acquisition and reuse, together with capture, registry and listing identities. The one-byte downmix replacement, acquisition-time change, audit-time change and reader/registry regressions in `test_corpus_replay.py` refuse stale evidence. A file path or unchanged size cannot prove byte identity |
| Matroska corpus stream exclusions bind the original TrackEntry position and TrackNumber, not an inferred stream ID | `mkv_pair` in `tools/compat-corpus/corpus_kd.py` owns the binding to both captured packet-span sequences; `test_corpus_mkv.py` covers omitted and swapped tracks, duplicate TrackNumbers, laces, failed captures and packet mutations |
| The numbers of `docs/measurements/compat-ffprobe.md` are those of its `b3a-round*.json`; a missing prose key cannot hide a figure | `tools/compat-corpus/record.py --check` and the missing-key and parenthetical-scope regressions in `tools/compat-corpus/tests/test_record.py` (`deny.yml`) |
| The empty-edit fixture byte contract applies only to files registered as generated in their directory's manifest, never ordinary namesakes | The generator's existing `MANIFEST` owns fixture identity; `test_ordinary_namesakes_are_compared_in_both_command_modes` exercises both command modes with absent, unrelated and skipped manifest entries. File names alone cannot prove provenance |
| The AV1 `nclx` fixture exception checks the exact stored colour/range bytes and output pair, and fails when the oracle starts agreeing | `av1_nclx_fixture` runs before both command-comparison loops; `Av1Nclx` tests in `tools/compat-corpus/tests/test_ffmpeg9.py` cover changed bytes, outputs, tags and stale agreement |
| A frame-oracle timeout or crash fails the run even for a baselined pair, and cannot enter the baseline | `oracle_failed` and unique fixture-name validation in `tools/compat-corpus/frames.py`; `test_baseline_cannot_suppress_or_record_an_oracle_failure` and `test_duplicate_fixture_names_are_refused_before_comparison` (`ci.yml`) |
| Current fixture CI accepts a historical out-of-scope command only as a clean refusal or an independently verified native success, without changing frozen judging | `current_ci.py` owns the current fixture adapter and `decoded_output.py` compares complete samples, pixels and probe fields against the pinned oracle. `test_current_ci.py` rejects crashes, unverified and wrong-output successes, checks the frozen reporter and workflow hashes, and keeps judged runs on `run.py`. PNG/BMP colour conversion has no acceptance tolerance |
| A raw PCM description uses demuxer options accepted by both pinned oracle programs | `raw_inputs` owns the shared description; the mono/stereo raw-success and wrong-sample cases in `test_current_ci.py` run against both programs in Linux fixture CI. A command list's type cannot prove an external program accepts its options |
| Current-CI H.264, AAC, VP9 and Opus copy verification requires a complete all-copy reference mapping and exact decoded output | `copy_mapping` owns source/output binding and refuses missing, mixed, duplicate and unparsed mappings; the comparator admits these codecs only at qualified output indices. Distinct-input and same-kind-stream regressions for every codec run against the pinned oracle in `test_current_ci.py`; a codec name alone cannot prove which stream the command selected |
| Copied audio retains every decoded frame's rational presentation time, duration and sample count, even without a stream duration | `compare` checks the complete audio frame timeline before PCM equality for qualified copies and requires known positive frame durations. Unit mutations, cases covering missing, malformed, nonpositive and positive durations, and pinned AAC/Opus interior-timestamp regressions in `test_current_ci.py` reject incomplete timing or timing-only changes with identical samples and stream fields. Stream start and decoded bytes alone cannot establish presentation timing |
| R3 reports every command of its set, including commands no input file reached | `test_every_command_is_reported_even_without_a_file_of_its_families` in `tools/compat-corpus/tests/test_r3.py` |
| A shared copy-check timeout voids encode breadth as a tooling fault, not a CoreAV oracle disagreement | `copy_only` classifies crash and timeout together; `test_a_copy_check_timeout_is_a_fault_that_voids_the_run` in `tools/compat-corpus/tests/test_encode_breadth.py` drives a real stopped checker through the caller and its report. The shared outcome cannot impose one policy because R3 fails its pairs while encode breadth voids its run |
| A rejected R4 rehearsal retains its public reports for diagnosis | `test_reports_survive_a_rejected_rehearsal` in `scripts/tests/test_compat_workflow.py` |
| R4 stages store credentials only during child execution, removes them on exceptions and HUP, INT, QUIT and TERM, and removes leftovers before collection | `staged_credentials` owns the write and cleanup; exception, real-child timeout, signal and recovery regressions in `scripts/tests/test_compat_r4_gcp.py` check credential absence and preserve signal behavior |
| The local R4 descendant test publishes readiness only after both PIDs are complete | `LocalGroup.child_script` writes and closes a temporary file before atomically replacing the readiness marker; `test_readiness_is_invisible_until_both_pids_are_written` observes publication during the write (`deny.yml`). A file's existence alone cannot prove its contents are complete |
| Compatibility shards and R4 scans produce nonempty summaries, and aggregation requires every expected shard | Crash and incomplete-input tests in `scripts/tests/test_compat_workflow.py` run the workflow shell blocks |
| R1 uses the registered dist-profile binary and retains its SHA-256 with each fixture result | `test_r1_uses_the_registered_profile_and_records_its_binary_hash` in `scripts/tests/test_compat_workflow.py` executes all three R1 steps |
| Measurement workflow checkouts do not persist Git credentials | `test_measurement_checkouts_do_not_persist_credentials` in `scripts/tests/test_compat_workflow.py` |
| Manual compatibility and codec-coverage workflows measure only the candidate registered in the round README on main | `scripts/registered_candidate.py` owns validation before either plan emits a commit. `test_registered_candidate.py` executes both planning gates with omitted and mismatched inputs, commits invalid registration overrides in a clean fixture and checks the registration error rather than a dirty-checkout failure, preserves automatic PR checks, rejects job-dependency and checkout bypasses, and checks that the README's documented registration format is accepted |
| Compatibility Rust artifacts come from the registered candidate; execution and reporting tools come from the immutable dispatched main revision containing the registered tooling floor | `scripts/compat_sources.py` owns planning, recording and bundle verification, and refuses drift from `judging.json`'s registered SHA-256 roster (the workflow and judging code/data included). `test_compat_sources.py` rejects wrong, mutable, non-main, old and drifted sources and altered bundles and each judging-file mutation; `test_compat_workflow.py` executes both candidate-directory builds and all consumer checks, and rejects checkout or verification bypasses. PR tooling is exempt from main membership only for spent-input rehearsals |
| A VP9 C2 truncated-tail condition accepts only its registered bytes after the complete packet prefix, without exempting a pixel or oracle failure | `file-condition.json` owns the sole full-SHA condition. `known_tail::Condition::matches` checks its size, element headers, partial timestamp and full digest; native capture requires its marker and includes the partial timestamp in the cutoff. Changed-byte, offset, size, clock, stale-marker and scope regressions run in `vp9-corpus`. Types cannot prove the identity or structure of an external file |
| The VP9 corpus workflow runs when its oracle verification or fallback-download helper changes | `test_oracle_tool_helpers_start_both_workflow_events` checks both helpers against both workflow event filters (`vp9-corpus`). A type cannot prove YAML path coverage |
| Committed calibration evidence is checked even without the simulator's optional numerical dependency | `CalibrationEvidence` in `tools/compat-corpus/tests/test_calibration_sim.py` owns the source digest, scenario roster, seeds, trial count and null-bound checks using only the standard library. The existing compat-corpus CI discovers it without NumPy; dependency availability cannot be proved by a type |
| Compatibility design notes name every common option and do not list accepted frame-output options as refused | `test_every_common_option_is_implemented_or_refused_by_design` in `tools/compat-corpus/tests/test_commands_v1.py` requires the option names. Their capability prose and build conditions remain review judgment; help snapshots enforce printed help, not prose |
| B4 and R4 measure process exit without timeout polling delays; their real-child regressions do not depend on a narrow timing gap | The Linux process-exit descriptor in `speed.timed` owns both deadlines; R4's `timed_run` delegates to it. Real-child tests in `test_speed_b4.py` and `test_speed_r4.py` use a wide delay gap but directly refuse polling sleeps, with kill/reap and scratch-cleanup checks |
| R4 infrastructure errors abort rather than becoming excluded child failures | `timed_run` requests exception propagation from the shared timer; `test_infrastructure_errors_abort_after_a_completed_pair` injects launch and descriptor errors after a measured pair and requires propagation with a retained, aborted report, which the reporter and host reject |
| R4 refusal groups are deterministic, pair totals are exclusive and failures take precedence over refusals | One invocation log per call and the committed `R4_REASON_GROUPS` table in `speed.py`; mixed-outcome, duplicate-record, unknown-group, coverage and empty-command regressions in `test_speed_r4.py` |
| Oracle-failed refusal diagnostics use the full invocation predicate without hiding other failures or entering refused-pair counts | `r4_invocation` owns qualification for both paths; outcome/report regressions in `test_speed_r4.py` cover unterminated logs, tool mismatches, mixed events, no-log CoreAV failures, exclusive counters and speed-adjacent diagnostic reasons |
| An R4 infrastructure abort retains completed outcomes and unprocessed eligible pairs without becoming a pass | The runner seeds the full eligible roster before execution and writes it in `finally`; abort-after-progress, missing-abort-marker and host-job report-retention regressions enforce the reporter and driver's nonpassing abort handling |
| B4 round-10 capture requires a readable fallback log, never a missing-file convention from a historical parser | The new driver's `fallback` reads the log directly; `test_deleted_log_cannot_become_a_clean_capture_or_pass_calibration` rejects a deleted executed-fallback record (`deny.yml`). A type cannot prove an external log exists |
| B4 round-10 receipts follow the frozen global schedule and nonoverlapping clocks, with only registered refusal skips and an incomplete suffix | `validate_receipts` owns the sequence before case grouping. `GlobalReceipts` rejects product-before-calibration, reordered cases and overlapping clocks, while retaining valid prefixes and refusal skips (`deny.yml`). Per-case grouping loses order, so it cannot own this check |
| Frozen B4 metadata identities hash the bytes parsed and remain unchanged through source and binary preflight | `read_metadata` snapshots bytes once; `verify_metadata` rechecks them before the freeze is written. `MetadataBinding` mutates partitions after parsing and metadata during preflight (`deny.yml`). Paths and sizes cannot prove byte identity |
| A frozen revision's required CI contexts are matched to the ruleset's required integration before choosing each latest check | `verify_sources` retains both context and integration; `RequiredIntegration` rejects missing or wrong apps and newer unrelated results (`deny.yml`). A check name alone cannot establish its app |
| YUV PNG/BMP coverage checks the lossless encoder against actual pre-encode RGB and that RGB against the same-command FFmpeg output, with no tolerance | `image_capture::Session` publishes only completed, call-bound captures, and `png_bmp_yuv.image_comparisons` owns both independent exact comparisons. Receipt mutations, one-sample encoder/reference changes and normal/captured output identity run in `png-bmp-yuv.yml`; acquisition refuses unmerged or dirty sources and non-Linux hosts. Types cannot prove external process output or file identities |
| Image capture failures void acquisition rather than becoming CoreAV oracle disagreements | The oracle boundary rethrows its closed `CAPTURE_FAULTS` set to the evaluator. `test_capture_faults_void_the_run_instead_of_becoming_oracle_misses` covers harness exits, timeouts, receipt integrity and source/output identity through run accounting; shape disagreements remain misses. External process and file integrity require runtime checks, not types |
