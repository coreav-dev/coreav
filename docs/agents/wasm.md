# WASM

The WASM module and its HTTP source.

| Rule | Enforced by |
|---|---|
| WASM memory gates read only the registered bars, reject decoded duplicate registry keys and require complete isolate-bound readings with exact harness concurrency | `registry`, `gates` and `batch` own the parser, closed gate ledger and request lifecycle; their regressions run with the example unit suite in `wasm-contract`. The module job judges the installed artifact and emits no raw readings |
| A workerd startup failure identifies its own process, not successful output accumulated from earlier workers | `WorkerdDiagnostics` owns each child's stdout, stderr and startup exit snapshot. `runtime.test.mjs` runs the pinned workerd with an invalid configuration after a successful prior log and checks isolated stderr, exit, launch, signal and deadline records. The workflow wiring regression requires installation of the example lockfile before this real-runtime test. Output and status arrive at runtime, so a type cannot establish their process identity; raw output remains runner-local |
| WASM host exceptions stay in `cause`, not in I/O document text or the public error message | Fixed open-failure documents and the Rust-owned read-failure document in `engine.js`; source-open and source-read credential-marker regressions in `packages/wasm/test/module.test.mjs`. Types cannot classify sensitive data in arbitrary JavaScript exceptions |
| HTTP source sizes describe the identity bytes actually read; URLs carry no userinfo, and cross-origin redirect chains never forward caller headers | The one HTTP adapter owns request headers, redirect handling and encoding checks; real gzip 200/206 and header-forwarding regressions in `packages/wasm/test/http.test.mjs` |
| WASM initialization names missing JSPI or exception-reference support before the generated glue runs | `EXNREF_PROBE` plus the JSPI/tag checks in `init`; a Node subprocess with exception references disabled in `packages/wasm/test/module.test.mjs` |
| An HLS rebuild does not accept re-read stored bytes as a fresh build, and concurrent loads retain one owner | The cache owns stored-versus-built provenance in its ready and loading records; stored-load/rebuild and uncached-build regressions in `packages/wasm/examples/test/unit/indexes.test.mjs`. A new byte array alone cannot encode that provenance |
| A measurement inventory classifies every public export as measured or explicitly excluded, without filtering away unknown exports | Not enforced: judgment until the planned measurement harness exists. `docs/design/wasm-workers-measurement-plan.md` requires disjoint, complete inventories and rejection before timing; a prose check cannot prove a future harness's classification |
| Ordinary native JPEG retains SIMD; WASM byte parity uses a separately built native portable-encoder test reference | The thumbnail default and CLI thumbnail features own SIMD opt-in. The existing WASM module job checks both resolved feature graphs before its package-specific reference build and requires exactly one passing portable JPEG golden test with an exact name. Cargo features are additive, so types cannot prevent a workspace-wide build from unifying SIMD into the test reference; an exact filter alone cannot prove that a test ran |
| The temporary WebP pixel exception requires the same PNG picture and every decoded sample, not only agreement between two encoders | The installed driver binds the registry version, captured bytes, PNG input/options/artifact and verified oracle binaries; `compareSamples` compares complete eight-bit RGBA buffers. Pixel mutations, equally wrong outputs, anchor/provenance faults and restored-byte-mode regressions run with the H.264 package tests; other dependency versions use byte equality |
| The opt-in H.264 WASM build records its size optimization and keeps the shared gzip limit | The closed build selection owns `opt-level=z`; `validateProvenance` requires its recorded final compiler flags, and the installed checker applies the same 1,048,576-byte gate to both packages |
| Installed declaration checks rewrite only the base package specifier or its subpaths, never another package's shared prefix | `rewritePackage` owns the specifier boundary; its existing-H.264-name and repeated-rewrite regression prevents setup imports from becoming missing modules instead of exercising the intended invalid call |
| A Node thumbnail cannot report successful EOF or summary before parent-side source cleanup, and admission survives worker termination and cleanup | The parent broker owns completion and admission; `node-wiring.test.mjs` runs actual worker/message-port wiring with fake bindings to check source contracts, read failures, cleanup, cancellation, termination and idle-process exit. The installed Linux preflight checks the real module; helper-only contract tests cannot prove the wiring |
| A test worker creates its stable isolate identity inside a request, never by generating randomness at module scope | `test/installed/worker.test.mjs` loads the actual H.264 worker in a request-restricted realm and checks one identity across two startup requests; the installed preflight exercises workerd. A string type cannot express the runtime's request-only randomness rule |
| A file-based Node worker does not inherit entrypoint-only flags, and runtime-refusal checks disable support in the executing realm | The worker owner starts with empty `execArgv` while process-wide V8 support remains inherited; eval-caller wiring regressions cover both `--input-type` spellings. The installed checker removes JSPI in the root initialization realm and disables exception references for the actual Node worker, rather than deleting a parent-realm property that a dedicated worker cannot observe |
| Bounded source cleanup completes before successful stream EOF, and a deadline or abort during cleanup cannot become document success | The shared engine closes exclusive output only after cleanup and rechecks abort; the Node broker checks its terminal stop result after cleanup. Deferred-close stream and document regressions exercise failures at that boundary, because a promise's type cannot express external cleanup completion |
| Node output cancellation records terminal state before forwarding cancellation and discards in-flight chunks | The parent output owner guards enqueue and completion; `node-lifecycle.test.mjs` cancels with a real worker chunk queued and checks parent survival, rejected summary and reuse |
| A missing source preserves its public error class through both Node broker directions | `restoreError` reconstitutes `SourceNotFoundError`; the real localhost HTTP 404 lifecycle regression checks its class and the public 404 response rather than only its serialized name |
