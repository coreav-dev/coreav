# CI

Workflow required checks, path filters, DCO, pinned actions, merge-group reuse, and workspace lints.

| Rule | Enforced by |
|---|---|
| Conformance archive retries recognize dropped connections even when the exception has no errno | `fetch` classifies `ConnectionError` alongside transient errno values; `test_transient_errors_recover_with_backoff_and_source_logs` covers raw and URL-wrapped `RemoteDisconnected`. External exceptions require runtime classification, not only an errno list |
| Unix socket fixtures fit macOS's 104-byte socket-address path even under long checkout or temporary-directory paths | `wav_non_regular_destinations_refuse_without_staging_or_replacement` and `output::tests::special_destinations_are_never_staged_or_replaced` each create one exclusive mode-0700 directory under a short Unix root and assert the encoded socket path is shorter than 104 bytes before binding. The bounded construction removes both external prefixes; Rust's `Path` type cannot constrain encoded address length |
| AAC qualification keeps its complete JSON report even when the comparison fails | The existing always-run artifact upload owns retention; `test_aac_qualification_report_survives_failure` checks its condition and report path. Rust types cannot govern workflow artifact paths |
| Input-summary fixture CI starts for the registered default CLI build inputs and the inherited Cargo manifest and lockfile | `test_default_cli_build_inputs_trigger_summary_checks` pins the fourteen current local dependency crate paths and both root files, and names the filter entries to restore. The input set is checked against `cargo tree -p coreav-cli -e normal,build`; Rust types cannot govern GitHub path filters |
| No `unwrap`, `expect`, `panic!`, `todo!`, `unimplemented!` or slice indexing in production code | Workspace lints in `Cargo.toml`, `cargo clippy --workspace --all-targets -- -D warnings` (`ci.yml`) |
| No `unsafe` outside the files `docs/unsafe-sites.md` lists; the change that adds or changes an `unsafe` site adds or updates its row there | `unsafe_code = "forbid"` (`Cargo.toml`); `scripts/unsafe_sites_check.py` (`ci.yml`) fails on a file with `unsafe` and no row. It checks files, not sites: a new site in a listed file passes it, so its row is review judgment |
| Every commit a pull request adds carries a `Signed-off-by` with its author's email (`git commit -s`) | `scripts/dco_check.py` (`deny.yml`): the name may differ and the email's case is ignored; commits already on `main` are skipped |
| Every action is pinned to a full commit sha | `scripts/workflow_check.py` (`deny.yml`) |
| A recurring CI job uses a runner image the provider still supports at merge time | Not enforced: judgment. Check the provider's retirement notices; retirement is external to this repository, and a passing job cannot prove continued availability |
| Every `${{ }}` expression in a workflow uses a context GitHub offers where it stands: `runner` in a job's `env:` passes every other check and fails when the workflow runs | actionlint with shellcheck and pyflakes off (`deny.yml`), and a workflow with that mistake in the same step that must fail. `workflow_check.py` reads lines and would copy GitHub's availability table, so the tool that keeps it is the check |
| The required-check table in `docs/design/ci-checks.md` and the workflows agree | `scripts/workflow_check.py` (`deny.yml`) |
| A required check is reported by a job that only reports, never by the job that does the work, and that job is green only when the work succeeded | The report job is review judgment: whether arbitrary steps and shell commands do no work cannot be inferred from the workflow file, so no check claims to. `scripts/tests/test_deny_report.py` runs `deny`'s reporting step and requires a nonzero exit for `failure`, `cancelled` and `skipped`; whether a step added there does work is review. A job GitHub cancels at its own `timeout-minutes` reports its check as `cancelled`, and no newer run replaces it |
| Standalone backend CI skips only an absent crate directory, never an existing crate with a missing or moved manifest | The directory and manifest guards in `encoder-backends.yml`; `test_encoder_backends_workflow.py` executes the workflow block with absent crates, moved manifests and Cargo failures (`deny.yml`). Types cannot prove checkout contents |
| Every workflow with a required check runs on every merge group in independent run groups; main maintenance cannot be cancelled or replaced | One prescribed `GROUP`/`CANCEL` form in `scripts/workflow_check.py` (`deny.yml`) requires every non-report job of `ci.yml`, `python.yml` and `npm.yml` to use independent main run-id groups and PR-only cancellation, with no workflow-level group (read through YAML nodes). Shared groups still replace pending jobs with cancellation disabled, and delayed gates can cancel newer jobs, so no selected-job exception exists. The unfiltered `deny` workflow may cancel whole runs. `test_main_ci_plan.py` checks all 90 three-push/gate orderings, every reuse/fallback combination, matrix legs and running/pending states, without a protected-job allowlist |
| Required-check triggers and workflow groups cannot silently disappear | One Psych node reader in `scripts/workflow_check.py` (`deny.yml`) reads `on:` and workflow-level `concurrency:`, so quoted or spaced keys cannot bypass its checks; ambiguous or unsupported nodes fail. It refuses a missing `merge_group:` trigger, `types:` without `checks_requested`, a branch filter on that trigger and, unless the workflow cancels job by job, a missing or incorrect workflow-level group. A job-level condition that skips a merge group's work is review judgment |
| A main push may reuse only a successful same-tree merge-group result of the same workflow | `.github/actions/merge-group-result` owns the lookup. `test_merge_group_result.py` rejects wrong trees, workflows, repositories, target branches, statuses and stale or unavailable evidence; `test_main_ci_plan.py` checks the retained main-only jobs and full-suite fallback |
| AAC-enabled transcode CI runs the whole fixture test target, not a name-filtered subset that can omit source or schema regressions | `test_aac_source_build_runs_the_whole_transcode_target` reads the workflow's AAC-enabled invocation and rejects the former `opus_encode aac_encode` filters (`deny.yml`). Rust types cannot select tests in a shell command |
| A CI description keeps a no-new-jobs claim attached to the change it describes | Not enforced: judgment |
| Queue-detector evidence errors reset observation streaks, including truncated transfers and null API fields | `Api.request` validates declared Content-Length before parsing JSON and owns transfer-error classification. `test_content_length_premature_eof_cannot_become_an_empty_index`, `test_premature_eof_resets_an_existing_observation_streak` and the partial-read/null-field regressions in `scripts/tests/test_queue_detector.py` run in `deny.yml`. Runtime transfer completeness cannot be proved by a JSON value or a type |
| A shadow queue-detector episode is reported once after revalidation without becoming a published alert | `report` owns the per-episode `shadowed_at` marker and shadow history, recording only revalidated outcomes. `test_shadow_episode_is_rechecked_once_but_can_still_publish_live` and the cancelled/later-failure regressions in `scripts/tests/test_queue_detector.py` run in `deny.yml`; bounded display history is not deduplication state |
| Queue-detector failure diagnostics never echo bodies, tokens, exception arguments or arbitrary header/error fields; request metadata is conditional | `Api` owns a sanitized last-request trace, initially absent; `endpoint`, `response_facts`, `graphql_errors` and `diagnostic` emit closed labels, bounded digits and known query fields only. The `Diagnostics` regressions in `scripts/tests/test_queue_detector.py` inspect stdout, stderr, the job summary and persisted state with hostile bodies, headers and exception arguments; `test_raw_exception_arguments_are_never_rendered` requires a class-only diagnostic before request preparation. Types cannot classify untrusted HTTP strings |
| Audio-source diagnostic preparation failures retain an incomplete report, and command failures expose a bounded stderr tail with their original cause | `main` owns report cleanup around preparation and comparison; `run` owns command failure details. Fixture, version and hash failures plus a real failed child are covered by `test_audio_source_diagnostic.py` (`deny.yml`). A return type cannot guarantee a file is written after an external command fails |
| The generated-audio diagnostic runs after test failure only when its prerequisite build succeeded and the job was not cancelled | The named `decode-build` outcome and the diagnostic's prescribed status condition in `ci.yml`; `test_workflow_diagnostic_survives_test_failure_but_not_a_missing_build` requires both and names the condition to restore. A type cannot govern GitHub Actions scheduling |
| The WASM module workflow runs when a fixture helper or policy example changes | `test_wasm_triggers_cover_module_fixture_inputs` derives the helpers from the fixture generator and checks both trigger filters against them and the policy examples (`deny.yml`). A type cannot govern YAML filters |
| The WASM workflow runs for every shared notice-record input | `test_wasm_triggers_cover_notice_record_inputs` reads `requiredInputs` from the record owner and checks both workflow trigger filters (`deny.yml`). Manifests outside the selected crate still enter Cargo metadata and the record, so a separate hand-written input list would drift |
| An installed-package verification failure records a release blocker even when memory gates are skipped | `test_wasm_reports_installed_package_and_memory_failures` loads the workflow's real step identifiers and evaluates its reporter condition against package failure, memory failure, success, earlier failure and cancellation |
| The VideoToolbox smoke runs for every Rust path dependency it builds and the inherited workspace manifest | `test_videotoolbox_smoke_tracks_its_rust_build_closure` derives normal/build dependencies transitively and the standalone root's dev dependencies from TOML, then requires their directory globs and root manifest in both event filters (`deny.yml`). A Rust type cannot govern workflow triggers |
| Design notes change in the same pull request as the design | test_videotoolbox_owner_docs_do_not_describe_it_as_unimplemented rejects former preimplementation wording for the implemented VideoToolbox owner and requires the plan's explicit CoreAV-to-FFmpeg payload ratio and inclusive bounds (deny.yml). Other design consistency is not enforced: judgment. Rust types cannot establish the meaning of external prose |
| A change of an oracle platform's pin or installer starts every workflow that runs that installer | `scripts/workflow_check.py` (`deny.yml`) checks the platform-specific input lists, including the macOS verifier and its frozen Linux imports. `test_macos_installers_track_only_their_own_required_inputs` checks each macOS input and nested shell calls. A job-level filter (`changed-paths`) is review judgment |
