# CI

Workflow required checks, path filters, DCO, pinned actions, merge-group reuse, and workspace lints.

| Rule | Enforced by |
|---|---|
| A credentialed manual workflow that builds a dispatched commit admits only commits on this repository's branches, so pull-request code from forks never runs beside corpus credentials | The HEVC reference workflow's admission step refuses a candidate no branch contains before the build and every credentialed step; `test_candidate_must_be_on_a_branch_before_it_builds_or_sees_credentials` pins that order. Writers already hold the repository's secrets, so this closes the only path that widens access. Workflow step order cannot be encoded in Rust types |
| Non-required HEVC full jobs run only on explicit main push, schedule or dispatch events, never pull requests or merge groups | `test_full_work_runs_only_on_explicit_full_events` pins both job gates, the schedule, path inputs and PR-only cancellation. | Full-suite failure reporting reads only trusted Actions metadata and final-head evidence names its selected suites | `test_ci_full.py` covers trusted workflow wiring, complete proof steps, identity, pagination, races, deduplication and closed suite selection. | HEVC final-head full evidence includes complete scalar conformance and every original census shard | `FULL_WORKFLOWS` names all four matrix jobs; the shared `PROOF_STEPS` owner requires complete C1 and the packet comparison in each shard. `test_verifier_requires_every_unique_shard_and_complete_scalar_proof` rejects missing or duplicate shards, skipped shard proof and missing scalar comparison. | Conformance archive retries recognize dropped connections even when the exception has no errno | `fetch` classifies `ConnectionError` alongside transient errno values; `test_transient_errors_recover_with_backoff_and_source_logs` covers raw and URL-wrapped `RemoteDisconnected`. | Unix socket fixtures fit macOS's 104-byte socket-address path even under long checkout or temporary-directory paths | `wav_non_regular_destinations_refuse_without_staging_or_replacement` and `output::tests::special_destinations_are_never_staged_or_replaced` each create one exclusive mode-0700 directory under a short Unix root and assert the encoded socket path is shorter than 104 bytes before binding. | AAC qualification keeps its complete JSON report even when the comparison fails | The existing always-run artifact upload owns retention; `test_aac_qualification_report_survives_failure` checks its condition and report path. Rust types cannot govern workflow artifact paths |
| Input-summary fixture CI starts for the registered default CLI build inputs and the inherited Cargo manifest and lockfile | `test_default_cli_build_inputs_trigger_summary_checks` pins the fourteen current local dependency crate paths and both root files, and names the filter entries to restore. | No `unwrap`, `expect`, `panic!`, `todo!`, `unimplemented!` or slice indexing in production code | Workspace lints in `Cargo.toml`, `cargo clippy --workspace --all-targets -- -D warnings` (`ci.yml`) |
| Structural invocation-discovery tests run with their pinned parser installed rather than relying on the runner image | `deny.yml` installs the exact `@ast-grep/cli` package before scripts discovery and exports its binary directory. Rust types cannot select the workflow's compiler |
| No `unsafe` outside the files `docs/unsafe-sites.md` lists; the change that adds or changes an `unsafe` site adds or updates its row there | `unsafe_code = "forbid"` (`Cargo.toml`); `scripts/unsafe_sites_check.py` (`ci.yml`) fails on a file with `unsafe` and no row. It checks files, not sites: a new site in a listed file passes it, so its row is review judgment |
| Every commit a pull request adds carries a `Signed-off-by` with its author's email (`git commit -s`) | `scripts/dco_check.py` (`deny.yml`): the name may differ and the email's case is ignored; commits already on `main` are skipped |
| Every action is pinned to a full commit sha | `scripts/workflow_check.py` (`deny.yml`) |

| Every `${{ }}` expression in a workflow uses a context GitHub offers where it stands: `runner` in a job's `env:` passes every other check and fails when the workflow runs | actionlint with shellcheck and pyflakes off (`deny.yml`), and a workflow with that mistake in the same step that must fail. `workflow_check.py` reads lines and would copy GitHub's availability table, so the tool that keeps it is the check |
| The required-check table in `docs/design/ci-checks.md` and the workflows agree | `scripts/workflow_check.py` (`deny.yml`) |
| A required check is reported by a job that only reports, never by the job that does the work, and that job is green only when the work succeeded | The report job is review judgment: whether arbitrary steps and shell commands do no work cannot be inferred from the workflow file, so no check claims to. `scripts/tests/test_deny_report.py` runs `deny`'s reporting step and requires a nonzero exit for `failure`, `cancelled` and `skipped`; whether a step added there does work is review. A job GitHub cancels at its own `timeout-minutes` reports its check as `cancelled`, and no newer run replaces it |
| Standalone backend CI skips only an absent crate directory, never an existing crate with a missing or moved manifest | The directory and manifest guards in `encoder-backends.yml`; `test_encoder_backends_workflow.py` executes the workflow block with absent crates, moved manifests and Cargo failures (`deny.yml`). Types cannot prove checkout contents |
| Every workflow with a required check runs on every merge group in independent run groups; main maintenance cannot be cancelled or replaced | One prescribed `GROUP`/`CANCEL` form in `scripts/workflow_check.py` (`deny.yml`) requires every non-report job of `ci.yml`, `python.yml` and `npm.yml` to use independent main run-id groups and PR-only cancellation, with no workflow-level group (read through YAML nodes). Shared groups still replace pending jobs with cancellation disabled, and delayed gates can cancel newer jobs, so no selected-job exception exists. The unfiltered `deny` workflow may cancel whole runs. `test_main_ci_plan.py` checks all 90 three-push/gate orderings, every reuse/fallback combination, matrix legs and running/pending states, without a protected-job allowlist |
| Required-check triggers and workflow groups cannot silently disappear | One Psych node reader in `scripts/workflow_check.py` (`deny.yml`) reads `on:` and workflow-level `concurrency:`, so quoted or spaced keys cannot bypass its checks; ambiguous or unsupported nodes fail. It refuses a missing `merge_group:` trigger, `types:` without `checks_requested`, a branch filter on that trigger and, unless the workflow cancels job by job, a missing or incorrect workflow-level group. A job-level condition that skips a merge group's work is review judgment |
| A main push may reuse only a successful same-tree merge-group result of the same workflow | `.github/actions/merge-group-result` owns the lookup. `test_merge_group_result.py` rejects wrong trees, workflows, repositories, target branches, statuses and stale or unavailable evidence; `test_main_ci_plan.py` checks the retained main-only jobs and full-suite fallback |
| AAC-enabled transcode CI runs the whole fixture test target, not a name-filtered subset that can omit source or schema regressions | `test_aac_source_build_runs_the_whole_transcode_target` reads the workflow's AAC-enabled invocation and rejects the former `opus_encode aac_encode` filters (`deny.yml`). | A CI description keeps a no-new-jobs claim attached to the change it describes | Not enforced: judgment |
