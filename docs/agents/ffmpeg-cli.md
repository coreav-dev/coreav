# FFmpeg CLI

CLI and ffprobe behavior, the FFmpeg pin, and fallback names.

| Rule | Enforced by |
|---|---|
| Every resolved audio encoder is authorized before executable discovery, including implicit audio-only and AVI defaults | `encode::authorize_audio` exhaustively delegates every codec to `StrictSafe` for video, audio-only and AVI encoding. The resolved-encoder unit regression checks the codec refusal before platform sandbox checks; `ffmpeg_strict_safe_authorizes_resolved_audio_before_discovery` covers implicit and explicit AAC/MP3, MP3 in AVI, both strict-safe switches and a renamed encoder that records any invocation, requiring exit 4, no invocation and no output (`ci.yml`) |
| Audio-only encoding refuses source offsets, tags and dispositions it cannot preserve, and never treats a concat list as a media file | The shared concat-encoding guard and `audio::plan` own these refusals; `ffmpeg_audio_only_refuses_unpreserved_source_properties` covers positive input origins, delayed audio, custom handlers, forced dispositions and concat in the whole transcode fixture target (`ci.yml`). Types cannot prove source metadata or command semantics |
| Image and raw-video dispatch preserves metadata and encoder-option refusals before selecting a frame job | `ffmpeg::plan` owns both guards before `Job::Frames`; `frame_plans_validate_common_options` covers every encoder setting and all metadata modes, and the strict-safe and fallback metadata regressions require refusal before any output is created (`ci.yml`) |
| The oracle FFmpeg and the x264 commit of its libx264 are pinned once, in `scripts/oracle-ffmpeg.env`; scripts and workflows read them from there | `scripts/oracle_pin.py --check` (`deny.yml`) fails on an FFmpeg download URL, archive name, cache-key version or `VERSION` constant, an x264 commit, or a value of the pin, in any tracked file outside `docs/`, Markdown and `evidence/` or `results/` directories. Prose that names a version is review judgment |
| Windows fallback waits for its program, preserves its exit code and skips CoreAV copies and hard links on PATH | `coreav-cli/tests/fallback_windows.rs` runs in `ci.yml`'s existing `check-windows` workspace tests with a native stand-in executable |
| Current comparisons use the shared FFmpeg pin; the historical training extractor stays isolated | `scripts/oracle_pin.py --verify-bin` before oracle use, including cache hits; `--check` restricts historical-extractor references to the training job and its measurement directory (`deny.yml`) |
| The fallback name lists match the pinned FFmpeg listings and CoreAV's printed keys, not boolean match-return values | `scripts/fallback_names.py --check DIR` in `ci.yml`'s `check` job fails on drift and names the regeneration command; `test_boolean_match_values_are_not_printed_keys` rejects stereo and unit values without dropping boolean field names |
| Every oracle audio decode uses one input thread, without changing video threads | `scripts/oracle-audio-args.txt` owns the arguments; Python reads `oracle_audio.INPUT_ARGS`, shell reads the file, and Rust tests include it. `scripts/oracle_pin.py --check` rejects unowned Python audio inputs and duplicate audio thread options; command-capture tests check input placement (`deny.yml`). Types cannot govern command lists across Python, shell and Rust |
| A hash muxer does not imply packet copy: an audio-capable hash command uses the shared audio input options unless it explicitly sets the audio output codec to `copy` | `oracle_audio.python_problems` recognizes explicit copy codecs, not packet-copy exemptions; extraction and Matroska hash commands are covered by command-capture tests, and extraction by the real FLAC/ALAC edit-list regression. Types cannot distinguish FFmpeg command meanings across languages |
| Transcode rate probing consumes the same timeout budget as encoding and never builds an unrelated full report or scans fragment totals | The ISO rate entry calls the library's header probe directly, without the report wrapper's fragment-scan option; `rate_probe_reads_only_the_fragment_header_window` bounds reads over ten thousand fragments and covers one frame. `rate_probe_does_not_scan_declared_sample_count` covers ten million samples with `ctts`. `RateSource` and the timeout regressions check read boundaries and remaining time. A synchronous source read cannot be interrupted |
| ISO rate-only probing and full reports use the resolved codec when applying the H.264 VUI fallback | `video_rates` is shared by both paths; `unsnapped_h264_times_keep_the_vui_rate` checks that the full report keeps its existing rate and the transcode uses that same rate |
| The documentation site's command reference shows each command's `--help` as the command prints it, and every command has a page | `crates/coreav-cli/tests/docs_site.rs` (`ci.yml`; `COREAV_BLESS_DOCS=1` rewrites the help text) |
| `coreav-cli`'s opt-in `aac` feature builds beside the transcode features: a crate matching on `coreav_audio::Codec` forwards `aac` to `coreav-audio` and gates its arm on its own feature | `cargo clippy -p coreav-cli --features aac,libopus,native-h264` (`ci.yml`) fails on the missing arm |
| AC-3 and E-AC-3 downmix values follow their own specified field orders, not one shared positional array | Named fields of `Downmix` and asymmetric AC-3/E-AC-3 tests in `ffprobe/ts/params.rs` (`ci.yml`) |
| Which keyframe a thumbnail may give is decided in one place | `select::offered` in `coreav-thumbnail`, and the agreement test in `mkv.rs` |
| Frame listings read packet payloads only for streams with a selected decoder | Per-stream `PacketSource::visit` payload requests from `Frames::by_stream`; `frames_request_payloads_only_for_selected_decoders` (`ci.yml`) |
| A source limit error while reading ISO chapters fails ffprobe, rather than becoming an empty or fallback chapter list; text-specific limits still omit that track | `a_limit_the_chapter_track_exceeds_fails_the_probe` and `a_chapter_track_over_the_text_limits_is_still_left_out` in `coreav-cli/tests/ffprobe_limits.rs`, plus `ffprobe_refuses_a_chapter_track_over_the_callers_limit` in `coreav-wasm/tests/ffprobe.rs`. The source error type also carries deliberately omitted malformed-track errors, so the regression tests enforce the distinction |
| An iTunes gapless source I/O error fails the ffprobe report or listing preflight instead of becoming an absent item; malformed gapless text is still omitted | The library's `itunes_gapless` result already separates absence from source failure, and both ffprobe callers propagate it. `a_gapless_source_error_fails_the_report`, `a_gapless_preflight_source_error_fails_before_the_first_packet` and `a_malformed_gapless_item_is_still_omitted` exercise transient reads and malformed text |
| Capacity qualification requires complete oracle output, a kernel-enforced temporary-output maximum and verified pinned baseline libraries | The capacity validator reconciles reference/default counts with the complete presentation or MP4 model and refuses budgets smaller than observed simultaneous files. The runner requires a dedicated tmpfs of exactly the recorded size before child execution; Linux regressions exceed it through child-written files and streamed captures. `oracle_pin.verify_bin` owns oracle version checks. One parsed baseline-library family predicate governs both required-library admission and archive checking, including multi-component direct-path names, whose changed-byte regression refuses a bypass. The binding hashes all resolved dependencies. Runtime evidence cannot be proved by a declared number or a filename |
| PCM time caps preserve the different input and output meanings of zero: input `-t 0` is unlimited, output `-t 0` is empty, and effective `-to 0` is an error | `pcm::plan` owns both groups' cap resolution; `input_and_output_zero_time_options_keep_their_distinct_meanings` in `coreav-cli/tests/ffmpeg_pcm.rs` and the pinned comparisons in `scripts/pcm_output_check.py` run in `ci.yml`. Parsed times alone cannot encode their command-group semantics |
| PCM output accepts output `-threads` without accepting other encoder options or changing its samples | `output_threads_does_not_change_pcm_or_allow_other_encoder_options` and the pinned comparisons in `scripts/pcm_output_check.py` run in `ci.yml`. The shared parsed encoder-options type also serves jobs that use threads, so a type cannot remove that field for PCM alone |
| A PCM example with an unspecified source codec places zero seek and duration options after `-i` | Not enforced: judgment. Input seeking is codec-dependent, and a generic example filename cannot prove its source codec |
| Native PCM output accepts decoded lossless sources only; lossy sources keep the existing FFmpeg refusal and fallback | `Codec::is_lossless` owns the classification beside the decoder capability, and `pcm::plan` requires it. The codec classification test and `opus_pcm_keeps_refusal_and_the_existing_ffmpeg_fallback` cover the source boundary, unchanged output and original fallback arguments. The decoded source's codec cannot be known from the command's type |
| PCM output does not silently drop a subtitle selected by an explicit subtitle codec; `-sn` still disables it | The shared `select_sources` function owns codec-driven subtitle selection without a text-only filter for PCM. `bitmap_subtitle_selection_is_refused_unless_disabled` covers a PGS track; the pinned comparisons in `scripts/pcm_output_check.py` cover text subtitles, destination preservation and exact audio with ordinary selection or `-sn` (`ci.yml`). The command's type cannot establish which streams the input contains |
| PCM codec validation uses the last matching option for the selected stream, not an earlier overridden or unmatched option | `pcm::plan` validates the shared `codecs` result; the parser leaves PCM validation to that owner. `only_the_effective_pcm_codec_is_validated` and the pinned comparisons cover repeated and indexed options, while retaining refusal for an effective unsupported codec (`ci.yml`). Resolving a stream specifier requires the input's runtime stream list |
| Binary frame stdout uses the shared media writer, checks its final flush and preserves closed-pipe status 141 | `output::media_stdout` owns the duplicated-descriptor writer; `raw_stdout_reports_a_final_flush_failure` and `raw_stdout_keeps_the_closed_pipe_exit_status` run the command against a failing sink and a closed pipe. External I/O outcomes require runtime checks |
| Valid output-rate syntax outside the native parser can fall back; invalid rates remain usage errors | `unsupported_rate_syntax_can_fall_back_but_invalid_rates_fail_usage` in `ffmpeg::args` checks named rates, scientific notation, zero, negative and malformed values. The boundary parser classifies the strings before job selection |
| Frame-output geometry changes are checked only after frame selection, so discarded frames cannot fail the command | `Run::take_frame` owns selection before validation; `geometry_changes_are_checked_only_on_selected_frames` accepts the discarded shape change and refuses the selected one without writing output. Decoder frames require runtime selection, not a static geometry type |
| Unsupported automatic subtitle selection is refused for Matroska output rather than silently omitted | `ffmpeg::select` owns the container-specific refusal before video/audio selection. The text and bitmap oracle regressions check implicit text selection, the bitmap selection activated by `-c:s copy`, `.mkv`/`.mka`/WebM refusals and successful exclusions. Plain `-c copy` leaves bitmap subtitles unselected, as the pinned oracle does; stream-indexed codec options do not activate their selection |
