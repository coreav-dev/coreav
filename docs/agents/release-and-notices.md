# Release and notices

Licenses, distribution notices, and package rehearsal.

| Rule | Enforced by |
|---|---|
| A launcher lifecycle fixture publishes a complete positive child PID before the test probes or signals it | The stand-in writes a sibling file and atomically renames it into place; `stopping the launcher stops the binary` validates the record and requires ESRCH after launcher exit. Atomic publication removes the empty-file-to-PID-0 process-group race; cleanup signals only a validated PID. A numeric conversion alone cannot distinguish a complete record from an empty file |
| The installer and Node launcher reject the same missing, wrong-version, non-executable or failed-check platform binary, including a Unix version process that ignores termination | `nativeBinary` owns validation and uses SIGKILL on Unix at its timeout. `native.test.mjs` executes recovery without an environment override and runs a real SIGTERM-ignoring child with the production signal option. External package contents and process signals cannot be enforced by a type |
| Dependencies keep to the license policy | `cargo deny check` and the fuzz projects' license check (`deny.yml`); `scripts/svt_av1_licenses.py` checks the native SVT dependency against its recipe identity and independently pinned notice bytes (`svt-av1-native.yml`). Its rewritten-manifest regressions reject changing both the text and its recorded hash |
| SPDX operators never become notice file names, and neither a named nor a generic file covers an LLVM exception without its complete text | `renderNotices` checks both normalized exception paragraphs after file validation. The registry-term, generic-file content and toolchain-operator regressions in `scripts/notices/test/legal.test.mjs` preserve alternatives and wrapping while refusing base-only text, missing paragraphs, changed permissions and operator filenames (`wasm.yml`, `release.yml`). A filename, identifier or type cannot prove file contents |
| Default builds link no still-patented codec | `scripts/patent_free_check.py` (`deny.yml`) checks every non-patented workspace member's default build, the npm build, `release-default` and `release-full` against `PATENTED`, which includes `coreav-hevc`, `coreav-kernels-hevc` and `coreav-backend-hevc`; `release-full` may keep the H.264 and AAC crates it already ships but no HEVC crate. `test_patent_free_check.py` rejects each HEVC crate in a default or `release-full` graph and a missing listed member |
| Native SVT-AV1 build commands have a finite timeout; a timeout terminates the command's process group, including SIGTERM-ignoring descendants after the direct child exits, reaps the direct child and reports a build error | `run` in `scripts/encoders/svt-av1/build.py` owns the one-hour command timeout and group cleanup. `test_timeout_kills_a_descendant_after_its_parent_closes_the_pipes` in `test_build.py` checks a real SIGTERM-ignoring descendant whose parent exits and whose output pipes close; mocked and real-child timeout regressions also verify cleanup and `BuildError`. Recipe tests run in `svt-av1-native.yml`. External process completion cannot be guaranteed by a type |
| Rust distribution notices include the pinned standard-library target closure, not only the project's Cargo graph | The shared notice generator selects both closures and verifies upstream texts; `scripts/notices/evidence.mjs` independently checks native binaries or raw and shipped modules against the notice sections, with missing-toolchain regressions |
| Distribution notices cover the linked C runtime separately from the Rust `libc` crate | The shared runtime manifest owns target coverage and is bound to the compiler commit. `runtime.test.mjs` and the C-runtime evidence regression refuse missing identities, changed legal bytes, compiler drift and unknown targets; the Windows emission regression requires the static Microsoft runtime identification and official terms link. `test_rust_distribution_notices_check.py` refuses omitted or changed complete runtime sections in packed CLI archives, including all three Windows package shapes. Cargo types cannot describe linker-added code or prove legal-file contents |
| A C library that a crate compiles into the binary (mimalloc, through `libmimalloc-sys`) ships its own licence, not only the binding crate's, and that notice follows the locked crate version | Its C-runtime inventory entry names the bundling crate and version; `checkBundledRuntimes` refuses generation when the build links another version or none. `a bundled C library's notice follows the locked crate that bundles it` in `runtime.test.mjs` checks both refusals and that no other target carries it. A crate's licence metadata cannot describe the licence of the C source it bundles |
| A C-runtime notice cannot establish Rust crate provenance, and runtime expressions preserve upstream licence alternatives | `validateEvidence` admits only Rust notice origins to Rust root and build-output coverage. `C runtime sections cannot cover Rust roots or build output` rejects every runtime-name collision and accepts a separate Rust notice; `LLVM runtime expressions preserve the legacy licence choice` retains the copied LLVM texts' NCSA-or-MIT choice (`runtime.test.mjs`). A shared label shape cannot encode origin or legal meaning, so the evidence owner enforces the boundary and focused tests check it |
| Microsoft runtime notices distinguish the Visual Studio component from the Windows SDK component | The existing runtime manifest owns separate vcruntime and UCRT notice inputs. `Microsoft runtime notices distinguish the SDK and Visual Studio terms` requires the SDK identification and official licence link; packed Windows regressions reject changing either component or either link. A linkage flag cannot identify the supplying agreement, so the owner separates the inputs and tests their emitted content |
| Packing documentation identifies whether verification comes from CI or a package hook | Not enforced: judgment. Generated native platform manifests have no `prepack` hook; the main WASI package has one |
| A similar JavaScript package name does not identify a main CLI WASI tarball | The WASI branch of `notices_check.py` requires the version-number filename shape and still checks target and compiler headers; `test_wasi_archive_names_do_not_cover_the_javascript_package` refuses similar names while the distribution-shape regression retains valid WASI packs |
| Every workflow building a notice-carrying CLI distribution installs `rust-src` for the compiler in `scripts/rust-dist.env` first | `test_every_distribution_build_installs_pinned_rust_src` discovers every workflow job calling `platform.sh`, executes its pin reader with a different version and checks its preceding source installation (`deny.yml`). Its failure names the installation to add; workflow setup cannot be enforced by the binary's types |
| A package rehearsal retains every package outcome after an artifact download fails | Explicit failure-tolerant step conditions and the result directory owner preserve the ledger; `test_package_rehearsal.py` checks each failed-download path from a checkout path with spaces and the absent-root case. Types cannot enforce GitHub Actions step scheduling |
