# Structured ffprobe input from standard input

## Goal and ordering

Commit this plan before implementation. Qualify `coreav ffprobe -of json -show_format -show_streams -i pipe:0` without changing local-file probing. The reference is the pinned FFmpeg/ffprobe 9.0.2, used only as black-box executables. Native admission requires complete JSON byte equality and the existing structured command's exit and diagnostic contract; unsupported transport or container facts refuse before native output. Do not remove fields, change comparison predicates or add a tolerance to make a comparison pass.

This work handles structured stdin only. No-section input summaries, ffmpeg stdin jobs, packet/frame listings, counts, read intervals, arbitrary pipe descriptors, remote protocols and new codecs remain outside this qualification. In particular, this does not widen H.264 summary authority or change oracle selection and qualification.

## Ownership and alternatives

Keep option and command-shape admission in `compat_cmd::run_ffprobe` before consuming stdin. Reuse the existing `EncodedInput` owner for exclusive mode-0600 temporary creation, bounded 64 KiB acquisition, the existing 1 GiB input limit, rewind, cleanup and replay lifetime. Continue using the existing native container readers; do not add another spool, stdin reader, parser or fallback-program selector.

The alternatives are a forward-only source implemented separately for each container, or acquisition into the existing replay owner followed by the existing bounded random-access readers. Choose the replay owner: it keeps one acquisition and cleanup contract and can preserve all consumed bytes for the existing fallback. A seekable temporary backing file does not make the logical input seekable, and its physical size must not become a reported pipe size or an invented bitrate.

Represent the logical input separately from the backing file. The report's input name remains the original stdin spelling. Derive transport-visible fields from proved pipe behavior and container declarations, not from the temporary path or physical spool length. Qualify each container and layout only after the generated pipe/file contrasts establish which values remain authoritative. Do not fix an unknown field by deleting a whole category of metadata or by borrowing a local-file value.

## Execution and refusal boundary

1. Parse and validate the complete supported command shape before stdin acquisition. Unsupported options keep the existing refusal/fallback with stdin untouched.
2. Acquire encoded input once through the existing owner. Exhausted acquisition limits, input read errors and temporary-file failures are terminal without native output, with cleanup; do not attempt fallback with an incomplete replay.
3. Probe the owned backing source under the existing container limits while retaining the logical pipe identity. Before emission, establish complete transport-correct format and stream facts and render the entire supported JSON result into bounded staging. An unanswered fact, unsupported layout or late probe failure cannot leak a JSON prefix.
4. Emit only a completely qualified result. After successful acquisition, a native disqualification uses the existing `refuse_with_input` replay route with the original argv and unchanged fallback selection. Strict-safe mode refuses atomically. Keep the replay owner alive until the child has consumed stdin and remove owned temporary files on every exit path.

The FFmpeg [pipe protocol documentation](https://ffmpeg.org/ffmpeg-protocols.html#pipe) defines descriptor spellings and distinguishes pipe input from seekable protocols. Container declarations retain their existing specification owners. Binary observations qualify diagnostic representation; they do not override contradictory container bytes or specifications.

## Verification and boundaries

First build the independent main baseline and reproduce native refusal with generated media. Compare the same generated bytes passed by stdin and by a local file, using the verified pinned pair. Include ordinary and faststart ISO layouts, a payload larger than the oracle's initial buffering window, fragmented ISO, Matroska with declared and undeclared timing, transport streams, empty/truncated input and unsupported content. This matrix determines the admitted subset; it is not permission to guess support for every container.

Accepted cases require exact complete JSON, the intended exit status and native strict-safe execution. Refused cases require empty stdout and no partial native output; after successful acquisition, real pinned fallback must receive the original complete bytes and original argv. Check all admitted stdin spellings, malformed commands without stdin reads, cleanup, the byte-cap boundary, read/temp-file failure and ordinary local-file regressions. Keep the tests in a new non-frozen target and reuse the existing platform pin verifier without editing it.

Run the smallest affected Rust and fixture tests, Clippy, formatting, public-text and PR-shape checks, and the canonical similarity guard. No real-file scan is required to qualify this transport boundary. Heavy checks belong on Actions. Do not execute or amend frozen inputs, registered harnesses, source closures, judging registrations, known-divergence rules, bars or tolerances. Historical command labels and published coverage counts remain unchanged. Any later input-summary diagnostic must use the established custody certificate/key and encrypted-evidence procedure, but no input-summary run is part of this plan.
