# Corpus key-row comparison and audit tools

`tools/compat-corpus/corpus_kd.py` implements the comparator and audit
mechanism of the [round 9 plan](../measurements/compat-ffprobe/round9-plan.md).
It does not run a measurement as part of its tests. Its production registry
implements three landed MPEG-TS records and three Matroska/WebM records,
tested with generated bytes. Other eligible records still need adapters.

## Cutoff and activation

The `freeze` command takes the full SHA of the authoritative main commit
introducing the corpus exclusion amendment. It refuses a commit outside
`origin/main`, a commit without the amendment, or a later commit. It reads
each implemented record at that cutoff and requires its complete contents
to match. Implemented key scopes must be a subset of the finite `level`
and `fields` declared in that frozen record. Wildcards and unknown scopes
are refused. Regenerating an inventory cannot add a field, case or record
that the cutoff did not authorize. The inventory retains the record, specification citation, digest
and implemented key and container scopes, plus the shared oracle pin's digest. The
selection manifest's digest is fixed here too; comparison refuses another
manifest even when its population and container counts match.
The version-2 inventory also fixes the SHA-256 of the TS reader, Matroska
reader and its `policy_ref` dependency. Comparison recomputes these digests
before capture, so an edited reader invalidates the frozen inventory.

```sh
python3 tools/compat-corpus/corpus_kd.py freeze \
  --plan-commit "$PLAN_COMMIT" --files files.json --out inventory.json
```

Run inputs cannot supply predicates or accepted value pairs. Only the
committed registry can do that. A record absent from the cutoff or a
changed record cannot activate. Missing or unreadable byte evidence covers
nothing; an unexpected reader error aborts rather than reducing coverage.
Only the frozen manifest row's container selects an evidence reader.
Dispatch changes no raw key eligibility or comparison. No production ISO
adapter is registered yet.

## Exact occurrence coverage

The legacy comparator and the new path share `run.key_pairs`. Section
arrays retain their indices and packets retain listing order. MPEG-TS
adapters also require the same PID at the existing stream position, and
the same stream index and PID for a packet pair. They never search for a
matching PID or reorder either listing. A stream-order difference remains
a difference even when both listings contain the same set of PIDs.
The PID prerequisite follows the required frozen record source, not a
convention in the record's identifier or an optional adapter flag.

Each ordinary adapter returns a `Pair` of exact expected oracle and
candidate values, established independently from the media bytes. Both
values must be present and non-null before an ordinary adapter is called.
Both observed values must match that pair. A broad stream
classification predicate cannot certify unrelated fields or packets.

There is one registered exception. `KD-FF9-EMPTY-EDIT-PADDING`, sourced
from `tools/compat-corpus/ffmpeg9.json`, may return a distinct
keyword-only `ProvenAbsence(oracle, track_id, offset, size, last_dts,
frame_length_flag, core_sample_rate, timescale, edit_end)` for
CoreAV's missing `packets.side_data_list.discard_padding`. Its frozen
record must carry `corpus_absence: "last-sample-within-media-edit"`.
The byte predicate must positively derive these values. The certificate
requires the track timescale to equal the ASC core sample rate and derives
the frame span once, as 960 ticks for flag 1 or 1,024 for flag 0. It checks
`last_dts + frame_span <= edit_end`, in media time, and the exact positive
oracle value. SBR doubles samples and rate together, not this span.
Stored sample duration is not an accepted frame-bound input. Deleting
required padding 324 from a 700-tick last sample must remain uncovered.
The certificate binds both packets'
offset, size, stream index and track identity, requires that this is the
last packet of the track on both sides, and checks equal packet counts and
agreement of every other packet. The packet summary comes from the
captured listings, not a claim in CoreAV's output. No stream search or
reordering is introduced.
Absence-enabled comparisons and Matroska files with eligible byte evidence
build an extra packet summary; audit replay scans it again for each mutation. That work is outside timed
commands and does not change the performance bars.

`Pair(value, None)` never certifies absence. An unproven deletion, a missing
oracle value, an explicit null or any other KD's missing value remains
uncovered. The unproven both-present cases get no new coverage. The
production registry does not implement the padding adapter yet.

The MPEG-TS adapters call the landed independent `oracle_kd_ts.Facts`
reader and predicates. `KD-TS-PROGRAM-WRAP` covers only `streams.start_pts`
and `streams.start_time`; both must agree with the file's program clock.
`KD-TS-ANNEX-D-DOWNMIX` covers only its five named stream fields, with
the exact zeros from the oracle and the frame's CRC-validated values from
CoreAV. `KD-TS-VBI-AS-AUDIO` covers only `streams.codec_name`, with the
record's finite MPEG-audio names and byte-proven `bin_data` classification.
Its `kind` scope does not authorize compat's `codec_type` key, and its
`packets` scope does not enumerate compat packet leaves. Those differences,
and missing audio values, stay uncovered. No aliases or packet exemptions
are inferred from those scopes.

The Matroska adapters cover `KD-FF9-ANNEX-D-DOWNMIX`'s five literal stream
fields and `streams.mime_codec_string` for `KD-FF9-AV1-DEFAULT-SUFFIX` and
`KD-FF9-AV1-CHROMA-POSITION`. Each uses only its own landed reader's exact
value pairs. The first AV1 record describes permitted equivalent strings;
the second corrects a misstated chroma position. No fixture, E-AC-3, ISO,
packet-field or nested-program scope is inferred.

Matroska compat output omits track IDs, and omitted TrackEntries can shift
stream indices. Each adapter therefore requires both stream indices to
equal the original TrackEntry position and both captured per-stream packet
`(pos, size)` sequences to equal the byte reader's nonempty frame spans,
in order. The spans come from the complete block walk for that TrackNumber;
frames of a lace share their block-data offset. Duplicate TrackNumbers,
zero-sized frames, missing rows and failed packet captures cannot qualify.
Attacked packet rows are rebound during every audit replay. There is no
track search, reordering or TrackNumber inferred from an array index.

These adapters add independent byte scans and packet summaries during
comparison and audit, outside timed commands. AV1 binding adds a complete
block walk per eligible track; an oversized or unreadable block refuses
that track's evidence. The registered performance work and bars do not
change. Retained run identities include the three reader digests beside
the tooling commit. Reusing evidence between comparison and audit and
bounded caching of packet parsing remain separate work.

The accumulator visits every reference-listed leaf, including differences
after the first saved example. A file/key row is excluded only when it
differs and every differing occurrence is validated. Raw results stay
unchanged. Existing `KD-STRICT` coverage remains separate and never becomes
a new exclusion. The default `run.py` modes, R1 and R2 are unchanged.

## Mutation replay

The audit replays that same occurrence iterator against candidate-only
mutations. It changes section values, stream identities and stream counts,
and packet values and counts at the first, middle and last packet of each
stream. Timing mutations also move claimed evidence with the value.
Tests change independent byte evidence and exercise agreeing and
nonmatching captures as well as covered ones.

A new or worsened raw difference must be uncovered at that exact path and
value. An unrelated caught difference does not excuse a covered one.
Coverage that activates on an existing uncovered difference also fails.
This detects an already-wrong value changed to another wrong value even
when aggregate mismatch counts stay constant. An audit failure makes the
report nonpassing and is not permission to change an exclusion or rerun.

The raw comparison's blind spots are reported, not credited as catches:
candidate-only leaves and trailing packets are not reference-listed,
repeated compact side-data keys overwrite earlier values, and missing
candidate leaves compare like null in the historical raw method. The
coverage boundary refuses explicit null and unproven absence; the one
registered absence certificate is checked independently.

## Capture and reporting

`compare` takes a private JSON list of the fixed selection. Each row has
`alias` (`f` followed by six digits), `path`, `sha256`, `container`
(`isobmff`, `matroska` or `mpegts`) and a Boolean `holdout`. Duplicate aliases
or hashes are refused. Every media checksum is verified before capture.
The shared pin is verified before either listing is captured.

Successful captures are validated before comparison. Section JSON must
contain the requested format, stream, program and chapter structures,
with unique stream indices, unambiguous keys and finite numeric values.
Packet captures need well-formed compact records, stream indices and sizes.
Empty output, malformed records and unknown stream indices abort as
infrastructure failures. Captures and a nonpassing report are retained;
their missing rows cannot silently leave the denominator. This validation
does not change the legacy comparator or its historical output rules.

```sh
python3 tools/compat-corpus/corpus_kd.py compare \
  --inventory inventory.json --files files.json \
  --coreav "$COREAV" --oracle-dir "$ORACLE_BIN" --out "$OUTPUT"
```

The output directory must not exist. Its `private/` directory retains the
selection, captures, exit statuses, raw rows, examples and audit details.
`report.json` contains only opaque file aliases, counts, inventory and
binary/selection digests. It retains the expected population and completed,
failed and unprocessed outcomes after an infrastructure abort. Partial
populations, missing audits, fallback activity and audit failures cannot
pass. The registered arm needs all 1,315 inputs and all three containers;
the manifest's identity must still be checked against the frozen selection
before the run. A matching file count alone does not prove selection.

Per key, the report separates direct agreement, existing covered
agreement, new exclusions and uncovered disagreement. The gated numerator
is direct plus existing covered agreement; the denominator removes only
new exclusions. Empty adjusted denominators are unmeasured. Raw agreement
and raw eligibility counts are retained. Common tag keys and the pooled
rare-tag diagnostic remain visible apart from the non-tag headline counts.
The overall per-key rates judge the bar; container and development/held-out
tables add no bar. Held-out flags do not assert that historical development
never used those files.

Excluded rows are published separately, once per file/key, with overlapping
KD attribution and counts per KD, key, container and development/held-out
part. No media hashes, paths or captured values enter that public report.
The 98% threshold and existing selections are not changed. This tool does
not alter fixtures, B4 timing or historical results.
