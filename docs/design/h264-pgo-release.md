# Opt-in H.264 PGO builds

## Scope

This recipe builds the native H.264 `decode` example with profile-guided optimization (PGO). It is an opt-in Linux x86-64 experiment, not a change to published packages, the full CLI, Cargo's default profiles, or release defaults. It uses `dist`, default features, and no post-link optimizer. Other targets and compiler versions need their own evidence.

The earlier training-only diagnostic used a merged profile containing three build-script profiles. Reproduction must retain that profile and its relocation flag. Removing those profiles creates a different artifact. The clean recipe instead separates host compilation from target instrumentation and collects each decoder invocation in a new directory. It records an explicit inventory rather than merging everything in a shared directory.

## Registered held-out evaluation

The first attempt stopped during acquisition with an oracle-capture failure. The [preparation record](../measurements/h264-pgo-preparation.md) reports the incomplete roster and absence of judged timing. The amendment below supersedes only acquisition failure and continuation rules. The stopped attempt remains incomplete.

The plan and tools in the first commit precede all runs. Neither this PR nor its verification may fetch, extract, probe, decode, calibrate on, or time held-out media. The allocation reservation and this PR must both merge before acquisition or selection. Results go in a separate PR. The results do not decide a release default.

The neutral allocation label is `h264-pgo-heldout-v1`. Its private reservation fixes the source population and keeps source names out of public records. The deterministic rule uses seed `coreav-h264-pgo-heldout-v1:20261103`. Order candidate identities by SHA-256 of the seed, a NUL byte, and the identity. Acquire in that order, without extending the frozen population. Exclude every previously allocated or used input, including all training and prior speed inputs, encoder inputs, and other operations' draws. The exclusion registry binds full file hashes, normalized source identities, and source groups. Check identities before acquisition and full hashes after acquisition. A missing registry component, a duplicate, or an overlap is fatal. Do not relabel another operation's draw.

Select sixteen independent files in each of `sd`, `720p`, `1080p`, and `4k`, using the first eligible video track of each file. Classification uses displayed width and height: at most 640 by 480, 1280 by 720, 1920 by 1088, or larger. Admission is metadata-only: progressive H.264, 8-bit 4:2:0, supported profile, positive dimensions and frame count. No CoreAV result or elapsed time selects an input. Stop collection at the fixed population or preparation budget. An unfilled class is an incomplete evaluation, not permission to reduce its count or substitute an input after decoding begins.

Sixteen files per class improve on the four-file diagnostic's uncertain class intervals. They do not guarantee that a one-percent bound can be resolved. There is no claim of a numerical power calculation: this is a budget-bounded evaluation with an explicit inconclusive outcome. Keep naturally short inputs. Measure up to 1,800, 900, 300, and 150 frames respectively, without looping or concatenating media. Publish actual presented frame counts.

Freeze one clean PGO artifact and a matching unprofiled artifact before opening the allocation. Both use the same source, locked dependencies, compiler, target, features, and path normalization. An independent clean-target-directory rebuild using the retained merged profile must match the PGO binary byte for byte. Regenerating a concurrent profile is not the reproducibility check. Retain binary, compiler, linker, training, raw-profile, merged-profile, source-tree and tool hashes.

The allocator creates one content-bound allocation contract after verifying both merged revisions and the reservation's tracked manifest blob. The contract binds the frozen population and its metadata snapshots, exclusion registry, deterministic candidate order, source revision, build receipt, binaries and retained profile. Record its printed SHA-256 with the frozen listing before acquiring media. Execution and offline auditing require that separately recorded digest, not a replacement contract found beside the results. A closed collection ledger must be an ordered prefix of the allocation, with complete successful metadata captures. Only used bytes, an already selected source group, unsupported metadata, or an already full class can exclude a candidate. The roster must be the first eligible independent inputs from that ledger. A profile or population change after allocation invalidates the contract.

The reservation supplies an exact committed checker for standing spent and allocated markings and a separately frozen input reservation. Registry creation verifies that metadata's identity and includes every selected input, even when its reserved operation has not run. The required hashes and checker identity are retained in the allocation contract; omitting them fails allocation and audit. Source inventories still supply normalized identity, group and abbreviated-hash exclusions.

### Bounded acquisition amendment

This amendment's plan is committed before its tools, in the same PR. Before merge, verification uses synthetic inputs only. Acquisition then precedes a single evaluation and a separate results PR. Counts, frame caps, estimators, parity, calibration, diagnostics and speed thresholds do not change.

Reuse the original allocation, exclusion registry, order and artifacts. Replay the five selected elementary streams and seven completed decisions against their retained receipts and hashes. No CoreAV command has opened them. Retain the eighth original and its failed capture without downloading or probing it again. Record its exclusion under this amendment, then resume the same ordered prefix. This continues the same reservation, not a fresh draw. The whole pool remains excluded from future operations. Never rebuild or retrain on these inputs.

Keep the original registration and allocation contract byte for byte. A separate acquisition registration binds their digests, the original artifact revision and the stopped state, collection and roster digests. After merge, freeze an acquisition receipt binding the merged tooling revision and this registration. Record its digest separately before continuation. Execution and offline audit require both allocation and acquisition digests. Tooling and measured-artifact revisions are separate; do not edit the build receipt to make them match.

The only replaceable failures are `nonzero-exit`, `stderr`, `invalid-metadata`, `empty-extraction` and `invalid-extraction` in source-probe, packet-copy or elementary-stream-probe capture. Retain exact command, stdout, stderr, source hash, stage, exit or timeout facts and available metadata. Positive exits and diagnostics from packet-copy or elementary-stream-probe capture remain replaceable only when every diagnostic line matches the collector's closed stream-error vocabulary. Unregistered text on a nonzero exit or at either later stage remains fatal.

The maintainer chose a general rule for completed exit-zero source probes: after the registered fatal checks, any other nonempty stderr rejects the file as `stderr`, including previously unseen diagnostic text. This is not a special case for one message. The next eligible source is taken from the unchanged frozen order, with no quota transfer or operator choice. Ignore the rejected probe's stdout for admission and class inference, and charge every unfilled class once as unknown under the existing sixteen-failure limit. Exact diagnostic bytes remain in the hashed stderr receipt. Keep every previously admitted file and reuse retained terminal captures without executing them again. Qualification, judging thresholds, the cumulative 14 GiB cap and the single evaluation are unchanged. This broader rejection rule does not prove that every unseen message is stream-local; inference remains limited to the capture-clean eligible cohort.

Registered resource, infrastructure and external-protocol faults remain fatal even on exit zero or when mixed with other text. Signals, capture timeouts, one-MiB stdout or stderr ceilings, contradictory or missing receipts and unknown capture exceptions remain fatal. Run new children in the C locale. Malformed complete probe JSON or stream schema is `invalid-metadata`. Empty copied output is `empty-extraction`; format, geometry or frame-count disagreement is `invalid-extraction`. Require exactly `min(source frames, class frame cap)` extracted frames, including for retained files. A shorter positive count is not complete work. Failed stdout never supplies admission metadata. Every admitted capture still requires empty stderr. Download, checksum, operating-system, checkpoint and operational-limit failures stop that invocation, not exclude the source. Resumable operational bounds do not close the approved acquisition.

Each class permits sixteen capture-failure exclusions. A successful source probe fixes the class of a later extraction failure. Without a successful source probe, charge one failure to every unfilled class rather than infer dimensions from failed stdout. Stop before the next candidate when an unfilled class reaches sixteen failures. Preserve that final exclusion and the stop record. Ordinary metadata exclusions keep their original reasons and do not consume this limit. No class can lend quota or failure allowance to another.

Sixteen is an operational ceiling equal to the target class size, chosen to bound unsuccessful collection work. It is not a statistical guarantee or an acceptable missing-data rate. A completed class can still have fifteen known-class failures followed by sixteen survivors. Deterministic successors prevent operator choice, but probing and extraction can favor cleaner or easier streams. Inference is limited to the capture-clean eligible cohort, not the frozen source population or the failed inputs. No outcome for excluded files is inferred from the survivors.

Every results record, including an incomplete outcome, publishes `acquisition-report.json`. It reports selected counts, per-class failure charges and selected replacement counts, broken down by reason, stage and known versus unknown failure class. Global failed-source counts distinguish the actual unknown-class sources from their conservative charges to several classes. For accounting, each selection discharges the oldest outstanding failure charge in its class; unmatched charges remain reported even if the class quota is full. This records selected successors, not proof of the absent source's class or outcome. The report carries the capture-clean inference scope and any terminal stop reason. The collector retains it at every decision and at completion or abort; offline replay recomputes it from receipts. The evaluation summary includes that same audited record. Do not publish speed results or an incomplete closeout without this accounting.

Scan the original global order. The next independent eligible file in a deficient class replaces that class's failed input. Another class cannot fill its slot. Keep the first sixteen per class. Replay recomputes failure reasons, class charges and successor order. Never retry a terminal capture. An interrupted capture without a terminal receipt stops incomplete. Originals and receipts become durable before decisions, and decisions before cursor advancement. Lost acknowledgements replay checkpoints without downloading or executing the child again.

Charge every prior download attempt against the cumulative 14 GiB cap, at declared size plus one byte per attempt, including retries and interruptions. The aggregate acquisition deadline is removed for the existing frozen receipt `98c294c2a2744d435c0593b7882829a1c58c06c844bcb325cf186e67d9061378`. That cutoff was an operational limit, not a judging predicate. Preserve the original receipt, its historical 6,600-second deadline, the stopped prefix and the registration byte for byte. Later merged tooling may continue that receipt beyond its historical deadline; its final acquisition binding records the executing tool hashes separately. Other receipts retain their registered deadlines.

Every acquisition VM still has a hard lifetime and an explicit infrastructure budget. Keep the original 180-second child and source socket timeouts, child memory and output limits, protocol restrictions and durable receipts. A VM interruption resumes only from retained originals and terminal captures; a lost uncommitted download remains fully charged before another attempt. Source order, selection, per-class replacement accounting and the cumulative 14 GiB cap do not change. Stop at the first population, replacement, byte or operational budget limit. Qualification starts only with sixteen files per class, and the single evaluation and all judging thresholds remain unchanged. No replacement is allowed after a CoreAV qualification or timing command starts.

Restore the stopped state, collection and roster as `preparation/state.json`, `preparation/collection.json` and `preparation/roster.json`. Keep raw captures, originals, selected media and the source inventory at their original relative paths. On the isolated Linux host, `python3 -I scripts/h264_pgo_acquire.py freeze DIRECTORY` verifies the original contract and prints the acquisition receipt digest. Record it outside the directory before continuing. The existing operator calls `h264_pgo_acquire.acquire` with both separately recorded digests, its guarded public-address opener and its durable checkpoint callback. The collector owns replacement decisions, replay and sanitized child resource limits; the adapter still owns network policy, remote persistence and infrastructure budgets. A directory lock prevents concurrent collectors. The full source-attempt charge is durable before network access, so a crash cannot refund bytes; per-chunk state rewrites are unnecessary.

Run and audit with `h264_pgo_round.py`, supplying both `--allocation-sha256` and `--acquisition-sha256`. The CLI audits complete source and capture receipts before qualification, and binds the acquisition files and tooling separately from the original measured-artifact contract. Restoring the directory elsewhere normalizes only the command paths used for replay; retained commands and raw receipt bytes do not change.

### Host and execution

Use one standard on-demand `c4-standard-16`, eight physical cores, SMT off, Xeon Platinum 8581C, and provider-accepted `ALL_CORE_MAX`. Pin 1T to CPU 2 and 8T to CPUs 0 through 7. Never time on spot, development machines, or a laptop. The host records CPU topology, affinity, provisioning and turbo settings before media execution. Lack of an OS frequency control is disclosed, not described as exactly fixed frequency.

Calibrate on the four fixed training references, one per class, not the allocation. For each thread count, collect nine interleaved rounds of two independently copied identical base binaries. Both the A/A ratio and an identical-copy null ratio must be within [0.99, 1.01], using the median of four class medians. Check the same references at the beginning and end. A greater-than-five-percent reference drift invalidates the entire run. Warm each measured input and arm once, then execute nine paired rounds. Shuffle stream order and the three arms (`base`, `pgo`, `ffmpeg`) with the registered seed. Time complete process exit with a Linux process-exit descriptor, not timeout polling. Timing excludes hashing and raw-output qualification.

Before timing, compare complete cropped planar output against the pinned FFmpeg oracle for base and PGO, at both thread counts. Require equal bytes, SHA-256, and positive integral frame counts within the registered frame cap. Hash output as it is read, with a geometry-derived byte ceiling. A nonzero exit, timeout, unexpected diagnostic, output overflow, missing cell, changed input or binary, or nonfinite timing aborts the run. Do not tolerate unresolved streams or analyze a successful subset. Native stderr must be empty. Oracle stderr must also be empty; no diagnostic exception is authorized for this new allocation.

Keep an append-only event log and a terminal completion or abort record. The offline audit requires the exact qualification and timed-cell roster, positive finite times, all registered rounds, matching hashes, successful calibration and both host checks. Partial output never produces a speed verdict. Retain invalid attempts. A speed miss is final; only a documented host fault can justify a separately recorded recovery, never a narrow miss or a method change.

### Estimator and thresholds

Every ratio is PGO elapsed time divided by base elapsed time, so lower is better. Divide each file's nine-call medians. Class and overall point estimates are medians of those file ratios. All four classes have equal file counts. Use 10,000 hierarchical bootstrap replicates with `random.Random(20261103)`: sample sixteen files with replacement within each class, then nine paired round indices with replacement per sampled file. Use those same round indices for both arms. Take the median within each class and across all sixty-four resampled file ratios. The two-sided 95% interval uses linearly interpolated 2.5th and 97.5th percentiles.

Both conditions are mandatory:

- Overall 1T median ratio is at most **0.97**, and its 95% interval upper bound is strictly below **1.00**.
- In **every** 8T class, the 95% interval upper bound is at most **1.01**, including equality. A passing point estimate does not pass this condition.

Report every class and overall estimate, interval, faster-file share, and each file's median, minimum, maximum and range. Report the matching base and PGO comparisons against the pinned oracle as information, not as substitute PGO bars. A claim of faster-than-oracle performance additionally requires its interval upper bound below 1.00 and point estimates at most parity overall and per class. Do not tune after seeing this allocation.

## Design choices

### Registered non-H.264 diagnostics

This addition is registered after the initial construction checks and before any diagnostic implementation or run. It does not change the H.264 thresholds or authorize a release-default change. Like the held-out evaluation, these measurements run only after both PRs merge, on the same on-demand host within the existing evaluation limit.

Build diagnostic-only full-CLI companions with default features plus `native-h264`, using the same source, compiler, target, `dist` profile, path normalization and retained clean decoder profile as the example. Keep an unprofiled CLI and a PGO CLI, and require an independent rebuild of the PGO CLI. Do not train on the diagnostic commands. Most CLI functions are outside the decoder training profile, so these companions do not establish the behavior of the published `release-full` feature set.

Use the three fixed commands and fixture parameters in `scripts/h264_pgo_registration.json`: a probe of an ALAC MP4, an MP4 remux of that file, and native FLAC-to-WAV decoding from Matroska. Both media fixtures come from the same deterministic sixty-second, 48 kHz stereo S16 signal, with 2,880,000 sample frames and seed 20261103, encoded by the pinned oracle. These synthetic fixtures are separate from the fresh held-out allocation. Bind their hashes and both CLI artifacts in the allocation contract before opening that allocation.

The signal generator advances unsigned state as `(1664525 * state + 1013904223) mod 2^32` once per interleaved channel sample, starting at the registered seed. Store the upper sixteen bits as little-endian two's-complement S16. Do not repeat a shorter block. Encode ALAC as `s16p` in `ipod` with `+faststart`, and FLAC as `s16` at compression level 5 in Matroska. Both oracle encodes use the shared single-thread audio input arguments, `-map 0:a:0`, `-flags:a +bitexact` and output `-fflags +bitexact`.

The expected direction is neutral for every command: no systematic improvement is expected outside the trained decoder. Run both CPU affinities, CPU 2 and CPUs 0 through 7, with the same one-warmup, nine interleaved paired-round protocol, fixed randomization seed, process-exit timer and host checks. The probe and remux need not use eight workers just because eight cores are available; audio decoding explicitly requests the matching thread count. Include file writing in the user-operation timings, remove prior outputs outside the timed interval, and prohibit fallback with `COREAV_STRICT_SAFE=1`.

Qualify complete native outputs before timing. Require equal probe JSON and complete MP4/WAV output bytes between CLI arms, and independently check decoded remux/audio samples and sample counts against the fixed source signal. A failed diagnostic command has an explicit incomplete diagnostic result, never a fast timing. Infrastructure errors and shared host or artifact failures still invalidate the run.

For each command and affinity, report the ratio of the nine-call PGO and base medians, the complete per-call values and ranges, and a paired-round 95% bootstrap interval. Resample nine round indices with replacement 10,000 times using seed 20261103, keep both arms paired, and use the same interpolated percentile rule as the H.264 estimator. The diagnostic non-regression guard is an interval upper bound **at most 1.01** for every command and affinity. Report every guard result, including inconclusive or failed ones. These diagnostic guards **do not gate the H.264 verdict** and do not imply a release-default recommendation.

One serial build recipe owns profile provenance. Separate base, instrumented and optimized target directories prevent stale build reuse. The historical reproduction is a separate mode because its flags and profile are intentionally different.

One environment boundary rejects inherited Cargo profile, build, target and compiler overrides before startup probes and every compilation, including historical and diagnostic companions. It rejects Cargo-home and hierarchical configuration files; the CLI has no `--config` passthrough. Thus independently rebuilt directories cannot silently share an unrecorded profile override. The build receipt records the fixed command and explicit Rust flags, while the clean source revision binds the manifest profiles.

The measurement executor writes events, while the auditor checks completeness before the shared `h264_parity_bars.py` estimator computes intervals. Reusing the older parity runner unchanged would retain tolerated diagnostics and unresolved-stream behavior that this evaluation does not allow. The VM lifecycle remains owned by `gcp_vm_job.py`, always with explicit standard provisioning for timing.

No decoder instructions or guarded command are changed. PGO may change generated instructions and executable size; the held-out evaluation measures those consequences rather than presuming a gain.
