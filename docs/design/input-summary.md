# Native input summaries

## Goal

Make `coreav ffprobe INPUT`, `coreav ffprobe -i INPUT` and `coreav ffmpeg -i INPUT` without an output file print the native input summary on standard error. Standard output stays empty. The reference is the pinned FFmpeg 9.0.2, used only as a black-box executable.

The comparison covers every byte from `Input #0` through the final stream's metadata and side data, including format metadata, duration, start time, bitrate, chapters and programs. Containers are ISO BMFF, Matroska/WebM, MPEG-TS and the standalone WAV/FLAC probes when available. A field that cannot be represented faithfully makes the whole summary unsupported before anything is written. Unsupported inputs use the existing fallback, or exit 4 under strict-safe mode.

## Deliberate divergence

CoreAV never prints FFmpeg's version, configuration or library banner. These commands behave as though `-hide_banner` were always present, including the fallback invocation. CoreAV does not identify itself as an FFmpeg version. This is an identity rule, not a relaxed summary comparison.

## Design and ordering

1. Commit this plan before implementation. Review this commit first.
2. Build a complete summary in memory from native probe information. Keep the printer shared between the two compatibility commands. Preserve metadata ordering, stream identifiers, codec descriptions, dispositions, chapter times, program membership and side-data descriptions. Add native information only where the existing report loses a fact needed by the summary.
3. Keep summary support separate from structured section support. Validate the complete summary before writing, so an unsupported field cannot leak a partial native summary before fallback. Respect the command's log level without changing structured output.
4. Replace the no-section fallback hint after the command-line compatibility change lands. Start from main and rebase onto main after that change merges; do not edit its branch.
5. For `ffmpeg -i INPUT` without an output, print the same summary, then the pinned reference's missing-output message and exit status. Keep malformed commands and unrelated output jobs on their existing paths.

## Evidence

Generate small fixtures covering each native container, video and audio codec descriptions, unknown values, nonzero and negative starts, metadata escaping and multiline values, chapters, multiple streams and programs, dispositions and supported side data. Compare both bare ffprobe spellings and the no-output ffmpeg command against the pinned oracle with its banner hidden. Assert exact standard error, empty standard output, exit status, strict-safe native execution and fallback without partial output.

Use only the existing development partition for real-file diagnostics, with the parity tooling's explicit development identities. Explicitly exclude both judged inputs and held-out inputs. Never read, fetch, sample or measure either population, and never change command sets, judging rosters, divergence records, round records, bars or tolerances. Heavy or real-file runs belong on GitHub Actions; local checks use generated media only. No paid infrastructure is required.

Unit tests cover formatting and refusal boundaries. Integration tests drive the built CLI. Existing structured-output regressions remain unchanged. Run formatting, affected tests, Clippy, public-text and pull-request shape checks, and the similarity guard before handoff. An oracle disagreement is resolved from the public specification and file bytes; an undecidable case is escalated without inventing an exception.

## Development diagnostic privacy

The real-file checker is development-only, not a judged run. Admission requires the existing development identity, `set=real` and an explicit `holdout=false`; missing or ambiguous classification is rejected. Judged and held-out files cannot enter the download or comparison list. This checker does not open any judged or held-out partition.

Detailed diagnostics must be encrypted for a supplied certificate before they can leave the runner. That includes input identities and paths, metadata, raw child stdout or stderr, and detailed comparisons. The private decryption key stays with its local owner and is never uploaded. If the certificate is absent or unusable, encryption is unavailable, or encryption fails, the run fails closed and cannot claim a completed comparison. It must not publish plaintext diagnostics as an alternative.

Public logs and plaintext artifacts contain only aggregate counts and closed reason labels. Never print or upload plaintext input paths, metadata, child output or stderr diffs. The artifact step uses an explicit allowlist of the aggregate report and encrypted diagnostic file; it must not upload a workspace, temporary directory or unencrypted diagnostic file. Native refusals and mismatches remain visible in aggregate counts without exposing input content.

Prior artifacts are invalidated before preparation. Preparation and capture failures retain an incomplete report and encrypted partial diagnostics instead of discarding completed work. At most four inputs are outstanding; a failure stops further submission and active workers stop before their next child call. Cancellation retains the current half-pair, including its completed child's status, stdout and stderr. Only aggregate counts and closed stage/reason labels are public. Exception arguments are never serialized. The report reconciles processed, failed, cancelled and unprocessed inputs, and `complete` requires every input to finish plus successful encrypted evidence publication. An incomplete run exits 2 and cannot satisfy the zero-mismatch gate. Child timeouts, integrity failures and mismatches are not retried; comparison bytes, input selection and timeouts remain unchanged.

## Native admission

The diagnostic uses the existing ordered probe report, plus raw microsecond format times and the source of video aspect ratios. A new report is unverified by default. ISO metadata walking, Matroska metadata retention and packet analysis must explicitly establish completeness. A recoverable source-read failure, omitted metadata, unsupported timecode grouping, unknown codec description or unrepresented side-data field refuses the whole summary before emission. Structured section output does not acquire diagnostic fields.

Negative Matroska diagnostic starts remain unqualified and use fallback. The native and reference packet timing differ on the generated negative-start case; this change does not reinterpret those timestamps. Detailed logging, nonzero spherical poses, unsupported stereo geometry and Dolby Vision records without retained metadata-compression information also use fallback.

Matroska packet analysis must also distinguish a stopped scan from end of input. If the existing packet-count or cluster-span cap stops collection while an audio or video window remains pending, the summary is unqualified. One packet-header lookahead under the existing element-work budget distinguishes an exact-count EOF from truncated analysis; no extra payload enters the retained window. Short EOF and completed windows preserve their existing admission, and structured fields remain unchanged. A generated dense-audio case places the remaining video timestamps after the packet cap and requires atomic refusal rather than an invented rate.

Codec and stream aspect ratios are independent facts. The codec ratio precedes the bitrate in brackets; a differing stream ratio follows it. Missing provenance refuses the diagnostic instead of promoting a container ratio to a decoder fact. Rates retain two decimal places when fractional hundredths are present, four for rates rounding below one hundredth, and use only integer `k` units. Ordinary metadata lines have a 255-byte budget; a truncation that would split UTF-8, or a long line with control characters, remains unsupported.

ISO summaries refuse fragmented timelines, conflicting visible geometry, cadence disagreements, changed video starts, unqualified legacy PCM layouts, in-band-only parameter authority, clean-aperture boxes and unconsumed or ambiguous metadata. AV1 summaries remain unsupported while sequence and configuration pixel formats are not independently retained. Container AAC summaries require an LC configuration with explicit negative SBR signalling; the shared classification reuses the existing configuration readers and adds no bitstream grammar. Transport-stream AAC remains unsupported because its decoder extensions and bitrate analysis window are not certified by the retained facts. These restrictions affect summaries, not structured probing. Every unanswered native summary reaches fallback atomically through one command-level failure arm, independent of its error variant, including filesystem failures before analysis. Summary and structured probes share local-path resolution: `file:` is removed only for filesystem access, while the original input name remains in the header and fallback arguments.

ISO `mdcv` and `clli` sample-entry boxes retain their fixed-width values for the diagnostic. Their syntax and units follow ISO/IEC 14496-12:2022, clauses 12.1.6 and 12.1.7. Metadata follows the container specifications; text layout, numeric spelling and decoder-description aliases are qualified against the pinned executable rather than another implementation's source.

## Unspecified H.264 aspect ratios

Commit this qualification plan before implementation and review it first. Ordinary generated `avc1`/AAC inputs already have exact native summaries. A remaining refusal conflates an unspecified codec aspect ratio with an unverified one: an SPS with no aspect declaration leaves no codec ratio for the diagnostic, independently of any container pixel aspect ratio. ITU-T H.264 E.1.1, E.2.1 and Table E-1 distinguish these states.

Retain that distinction in the existing configuration parser, with separate unverified, unspecified and positive-ratio states. Structured consumers continue to receive the same optional ratio. ISO H.264 summary admission requires an `avc1` configuration with one complete sequence parameter set and one complete picture parameter set. Reserved aspect identifiers, zero Extended_SAR dimensions, truncated syntax and ambiguous parameter-set authority do not establish unspecified provenance. The authority check also protects the profile and pixel format when the aspect ratio is explicit; structured ratio fields remain unchanged.

Only ISO summary admission consumes the new proof; the renderer already separates codec and container ratios. Structured parsing and decoder behavior remain unchanged. Summary authority requires complete SPS and PPS syntax through their RBSP trailing bits, a PPS that names the sole SPS, and a bounded first sample whose VCL prefixes name that PPS. ITU-T H.264 clauses 7.3.2.1.1, 7.3.2.2, 7.3.3, 7.4.1.2.1 and 7.4.2.2 define syntax and activation. A NAL header, a valid parameter-set prefix or an unused parameter set cannot certify the printed profile, pixel format or aspect. Unsupported syntax, conflicting in-band authority, malformed framing, missing VCL references and exhausted existing packet or box-byte limits refuse the whole summary before emission. The sample check proves framing and parameter references, not decoded picture integrity. Slice groups and separate colour planes remain unsupported. No decoding or additional packet iteration is introduced. Cadence disagreements, changed video starts, geometry conflicts, timing-model disagreement and missing explicit negative AAC SBR evidence retain their current refusals. Planning timing, structured format-display timing, seek and concat origins remain separate and unchanged.

Generated controls must turn the unspecified-aspect refusal into complete FFmpeg 9.0.2 summary-byte equality for all three command spellings, including an independent container ratio. Negative configuration and syntax controls retain atomic refusal and exact fallback, without partial summaries. Existing structured output and native summary identities must not change. Run the existing development comparison with the same input identities and require a complete zero-mismatch result; preserve its encrypted evidence policy. Do not change frozen material, judging, baselines or tolerances, or use judged or held-out inputs. This qualification establishes no refreshed public coverage count.

Standalone audio uses the existing bounded WAVE and FLAC readers, without adding frame parsing. Summary times come directly from their integer calculations. WAVE requires complete RIFF/data extents, an explicit speaker mask, matching valid/storage precision and no unqualified format extension or fact chunk. Unmasked WAVE remains on fallback because ffmpeg guesses a layout that bare ffprobe leaves unknown; the command families cannot share that description exactly. The intentional structured PCM24-in-32 disagreement also refuses the summary instead of reproducing the oracle's incorrect storage interpretation.

FLAC retains distinct unknown and zero start states. Native summaries require a nonempty payload, a known sample total and either mono/stereo or one explicit supported mask matching the channel count. Duplicate or rejected masks and normalized metadata-key collisions refuse. Format language tags, empty audio, clamped WAVE data and other unqualified facts use atomic fallback without changing structured reports. Generated comparisons cover explicit back/side layouts, precision, truncation, tags and all three command spellings; the original development roster remains unchanged.

FLAC timing additionally requires complete payload validation through the existing native decoder, not STREAMINFO or byte-count inference. The summary-only probe reads from the metadata end to EOF without sync searching or recovery, checks every frame's header and footer CRC, one blocking strategy, zero-origin contiguous frame/sample numbering, block/frame bounds, the exact sample total and any declared nonzero MD5. RFC 9639 Sections 8.2, 9.1 and 9.1.5 define those integrity and sequence constraints. Only then does the diagnostic use the pinned binary's observed distinction: one complete frame has no start field; two or more contiguous frames have zero start. Other origins or unproved sequences refuse instead of inventing timing. Ordinary structured probing remains metadata-only and grants no FLAC summary certificate.

The entire payload must fit the caller's `max_box_bytes` (1 MiB by default), `max_packet_bytes` and remaining retained-byte budget. Validation accounts for encoded bytes, frame visits, decoded channel-samples, predictor work up to order 32, PCM/wide scratch and fixed MD5 storage; its conservative envelope charges 64 work units per decoded channel-sample. Integer PCM and wide scratch use fallible reservation, and MD5 needs no heap buffer. The existing frame reader also checks the reserved header bit, the coded-number ranges of RFC 9639 Table 18 and zero alignment padding from Section 9.3, including CRC-correct mutations. Exhausted budgets, malformed or truncated frames, CRC/MD5 failures, incomplete totals and trailing bytes refuse the whole summary before emission; there is no validated-prefix shortcut.

The development checker selects only explicitly non-held-out real files from the existing development manifests. It streams them on a Linux GitHub runner, checks content hashes before opening them and deletes each downloaded file after comparison. Public artifacts contain aggregate counts and encrypted diagnostics only. The certificate is supplied at dispatch; the private decryption key never leaves its local owner.
