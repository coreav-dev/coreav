# HEVC wavefront decoding

## Choice

Start with wavefront parallel processing (WPP) for a single-tile picture whose first independent slice supplies one entropy substream per CTU row. Keep every other slice on the existing serial path. Both paths use the same CTU decoder. This remains an opt-in `native-hevc` feature.

Frame parallelism has the broadest eventual coverage, including streams without entry points. It also needs concurrent DPB lifetimes, reference-row publication after deblocking and SAO, motion-field publication, and cancellation across picture dependencies. The current DPB publishes only complete filtered pictures. Changing that contract is larger than a first threading path and overlaps the filtering work.

Tiles have independent entropy and prediction state but help only streams that signal multiple tiles. Independent slices also need no entropy synchronization, but arbitrary slice boundaries and dependent segments complicate admission. Neither is a reliable assumption about the existing reference inputs. WPP already has parsed entry points and a serial second-CTU context checkpoint. It can expose most entropy and reconstruction work without changing the DPB or filtering.

The expected gain is limited to WPP-signalled inputs and excludes serial filtering. Wide pictures offer more useful overlap than narrow pictures because each lower row trails the row above by two CTUs. The reference run must report actual eligible-picture coverage rather than treating non-WPP inputs as parallel work. No numerical speed-up is assumed before that run.

## Ownership and ordering

Each worker owns reconstruction scratch and its mutable picture storage. A row publishes completed CTUs, their prediction cells and SAO metadata under one mutex. A lower row waits until the upper row has completed the current column plus its upper-right neighbour, or the upper row has ended. It imports only published data. The second completed CTU also publishes the CABAC context checkpoint required by H.265 clause 9.3.2. Spatial prediction and QP derivation continue to use the existing slice and tile availability rules.

Prediction imports only the last four luma rows of the upper band, including its last prediction-cell row. At column zero it also imports the first four rows, because CABAC restart availability checks the above-right CTU's first cell. Full CTUs remain published, and the final merge still imports every row for filtering and DPB storage. This avoids copying three complete upper CTUs at every column without changing worker ownership or memory admission.

Rows are assigned in increasing order to a bounded group of scoped workers. Dependencies point only to the preceding row. Completed row storage is merged in row order before the unchanged whole-picture finalization and hash check. No partially reconstructed or filtered picture enters the DPB. The output callback still runs on the caller's thread in presentation order.

The decoder session retains private worker allocations only after every row has reconciled successfully. Reuse requires the same worker count, geometry, bit depth, CTU shape, reference-storage shape, buffer lengths and total retained capacity. Every frame field and scratch buffer is reset from the new working picture before dispatch, with exhaustive destructuring requiring new fields to be handled. Workers borrow these private frames only within the thread scope. Failure drops them rather than returning partial state to the session.

The codec exposes `PictureDecoder::with_threads`. The backend follows the existing native decoder option shape, `NativeOptions { threads: Option<usize> }`, with `None` selecting available host parallelism and explicit counts bounded to 1 through 16. Memory admission can reduce the effective count to one. Threadless targets retain serial decoding. The existing command-line decoder thread option supplies this backend option without adding a new CLI flag.

## Failure and resource bounds

Charge worker picture buffers, row publications, synchronization records and bounded thread stacks before starting work. Preserve the existing serial path when extra storage does not fit. Workers never call user callbacks or mutate the DPB.

Select the worker count using the original cold calculation, including its transient scratch reservation, regardless of idle storage. Idle allocations are accounted separately and released before required allocations would exceed the same limit: RBSP and entry-point storage, working-picture and range storage, finalization scratch, and external output reservations. Requested and actual capacities are checked at the allocation boundary. An allocation/accounting hook at finalization's existing source allocation supplies this release point without changing filter arithmetic or control flow. Idle memory cannot turn an otherwise admitted decode into a refusal or admit additional workers. Changing the requested thread count or finishing the session releases the pool.

Moving the active frame into a reserved slot keeps cache bookkeeping within the original fixed-state allowance. The allowance is still calculated from the legacy session layout, not by subtracting fields from the new layout, because padding is target-dependent. A physical-envelope test checks both session storage and active-frame metadata against that unchanged allowance on each supported test target. Idle worker-vector capacity is charged even when it contains no frames, and reported peaks include idle bytes.

Reserve a conservative complete-substream bin bound for every row before dispatch. CABAC's normalized range is at most 510, and a decision or zero termination reduces it by at least two. At most 128 such bins can occur before another input bit is required. Bypass bins consume a bit each, and PCM restarts consume nine initialization bits. `128 * (8 * bytes + 1)` also covers a final failed read. Each row receives only its own bound. If their sum exceeds the remaining stream or picture budget, use serial decoding instead. This keeps actual entropy work within the caller's limit rather than discovering overspending after workers finish.

For `B` entropy bytes across `R` rows, admission requires `1024 * B + 128 * R <= remaining_bins`. The default picture allowance is `2^28`, so even a fresh allowance limits parallel admission to approximately 256 KiB of entropy data; larger slices remain serial. Bounds are already sized per row, but all rows are reserved together. Reserving only active row batches and refunding unused work could admit larger slices. That requires a serial continuation point when the next batch cannot reserve its bound and is deferred rather than weakening the present work limit.

Each row records its entropy consumption and outcome. Reconcile rows in bitstream order, so scheduling does not choose the reported syntax failure. A failed row wakes dependent rows. Every worker is joined before returning, including after a spawn failure, decode error or panic. A caught reconstruction panic returns `Error::Internal`, mapped to the backend's existing `Backend` failure kind, at every thread count. It is not malformed media or a caller resource limit. Deadline checks remain inside CTU work and dependency waits. Failure publishes no partial picture and the session remains failed.

## Verification

Compare complete visible output, coded-component hashes, picture order, timestamps and work counters with one thread at 2, 4 and 8 threads. Run the admitted conformance set and generated WPP boundary cases, including one-column rows, partial final rows, malformed entry points, dependent-segment continuation, budget exhaustion, callback failure and deadline expiry. Stress repeated decoding under a hard process timeout. Exercise the synchronization owner with ThreadSanitizer on Linux where supported. Keep unsupported sanitizer coverage explicit.

The generated above-right fixture has three CTUs per row and two rows. Its lower row contains non-PCM angular-mode-34 CUs with zero residual. Different upper-row samples make the lower row's top-right CU samples depend on the above-right CTU. A test-only hook delays publication of upper column two until lower column one is waiting; the test rejects early lower publication and compares every plane and work counter with serial decoding. Separate hooks inject a middle-row error, panic and deadline expiry with real multiworker entry. Complete conformance runs with `--threads` greater than one fail if every picture falls back to serial decoding.

Warm-worker tests compare serial, cold and reused output across changed samples, picture indices, geometry and bit depth. Independent cold decodes locate constructor and worker-selection boundaries, including large input-scratch reservations; reused decodes must retain the same success, refusal and worker counts at each boundary. Removing the reset, idle release, or cold transient reservation must fail these tests. Parser callback tests require both requested and actual capacity reservations and propagate refusal before slice delivery.

Measure the existing reference inputs on GitHub Actions with full candidate and main SHAs, separate executables, warm-up and alternating repeated calls at automatic, 1, 4, 8 and 16 threads. The reference helper takes its memory budget from the backend policy defaults and records both that budget and the resolved automatic worker limit. First verify pixels against the qualified pinned oracle. Export enhancement metadata rather than applying it so both arms reconstruct the HEVC base raster, without resizing or pixel conversion. Report main time divided by candidate time, candidate one-thread time divided by candidate multithread time, CPU usage, host core count and WPP coverage. Separate WPP from non-WPP inputs when checking the automatic-worker cost. These are shared-runner reference figures, not speed acceptance bars. Retain the result privately and delete the disposable runs afterward.

No change in this work modifies `inverse_residual`, filter arithmetic or control flow, the default build, decoder isolation, or the admitted coding-tool set. Sources are ITU-T H.265 and conformance data only.

The next picture-level scheduling work is planned in [HEVC picture scheduling](hevc-frame-threading.md). It keeps complete-reference publication and does not make dependent picture chains parallel.
