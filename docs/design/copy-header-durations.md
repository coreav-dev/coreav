# Rebuild copied media durations without changing native remux

## Problem and scope

An ordinary `coreav ffmpeg -i INPUT -c copy OUTPUT.mp4` with a zero input origin still preserves a conflicting declared `mdhd` duration. On an independently generated edited H.264 source with all 78 samples and `mdhd.duration` changed to 10000, CoreAV succeeds with `duration_ts=10000` while pinned FFmpeg 9.0.2 reconstructs 39936. Generated AV sources reproduce the same discrepancy when either the video or audio media header is shortened. Their packet bytes, timestamps and durations already agree; this unit changes the copied output header policy, not source packet selection.

Scope: single-input ISO ordinary copy, faststart and explicit copy/mapping through the existing full-file remux. Native remux, sanitization and replacement defaults continue preserving their own declared-header policy. Multi-input mapping, seek, concat and probe output remain separate; no frozen input, generator, result or judging rule changes.

## Ownership and interface

Add opt-in `RemuxOptions::rebuild_durations: bool`, default false. When set, the writer derives track durations from the retained edit mapping or copied media, and media durations from complete copied sample durations. The compatibility `Job::Remux` sets it; native CLI, Python, WASM and replacement consumers leave it false. The existing explicit video-origin policy also implies rebuilt durations, so its admission guard and duration reconstruction remain one policy path rather than independent overrides.

The existing bounded table pass already owns the sum of sample durations and all source edits. Under the opt-in policy it does not retain declared track/media overrides, including the later movie-timescale rescaling override. Only absent or simple source edits are admitted; multiple or unmodeled edits and a later video sample composed before the first decoded sample refuse before writing, rather than pretending that rebuilding headers establishes compatible packet selection. A table-pass timing refusal fails the whole request even under the native drop policy, rather than silently publishing only the remaining audio. Native preservation keeps the old path. Samples, composition offsets, metadata and source timescales remain unchanged; edit endpoints follow the admission and canonicalization rules below. Positive-origin normalization retains its existing exact-common-clock policy. No extra scan, payload read or input-dependent allocation is introduced. If a reproduced case cannot match the unchanged pinned comparison under this policy, refuse it before output rather than rounding away the mismatch.

An unconditional change to remux would violate the native preservation contract. A probe-only change would leave the emitted file incorrect. Keeping the opt-in boundary lets compatibility output recompute its clock while native remux continues exposing the stored declarations.

A simple edit can still shorten the presentation while the full-file remux copies every sample. Pinned FFmpeg 9.0.2 reconstructs different timing for such video edits, including a cut within the final frame, and for audio edits that leave whole trailing samples outside the edit. The same table pass therefore validates the edit endpoint against sample composition times using exact cross-multiplied clocks. For video and other non-AAC media, the endpoint must cover the complete composition end and cannot exceed its ceiling in source movie ticks. AAC may retain a partial final sample, but the endpoint must be strictly after the final sample's start. An AAC edit extending beyond the complete end's movie-tick ceiling is shortened to that end only when it is exactly representable in the source movie clock; otherwise it refuses. This retains the established ordinary-copy control for a positive AAC media offset without accepting an incorrect overlong presentation. A fragmented last edit of duration zero keeps its existing sample-derived interpretation. Other endpoints refuse the entire request before output; they do not shorten, discard or retime copied samples. This admission rule does not relax the output comparison.
