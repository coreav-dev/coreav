# Threat model

Status: Design inventory. Evidence snapshot: `acd053413be6c4079af2ec2879fd5ee8022faae3`.

This note describes which inputs CoreAV trusts, what authority an attacker can reach, and which controls the implementation applies. A missing control is a gap, not evidence of an exploitable defect. Tests and fuzz targets below establish specific behavior, not the absence of other defects. This note makes no security certification or release-gate claim.

## Scope and assets

The scope includes the native CLI, its libraries, worker processes, and the JavaScript WebAssembly package. The assets are the caller's files and credentials, the host's network access, process memory, CPU time, disk space, and the integrity of reports and generated media.

The operator controls the installed program, environment, working directory, executable search path, output destinations, and selected limits. An embedding service must not give an upload author those controls merely because the upload is untrusted. A compromised operator-installed encoder or a malicious WASM host already has authority outside CoreAV's media parser.

Build selection matters. [The CLI manifest](../../crates/coreav-cli/Cargo.toml) defines Cargo `default` as `cli,net`. Linux and macOS packages use `release-default`, which adds dav1d, libvpx, and libopus. `release-full` also enables native H.264 and AAC. [Windows packaging](../../packages/cli/scripts/platform.sh) instead selects `cli,net`, with AAC added for its full build, and omits these C codec workers. Native VP9 and the standalone encoder backends have separate build selections. A library caller can instantiate a backend directly instead of using the CLI's worker arrangement. Controls described for CLI workers do not automatically apply to that caller.

## Input suppliers and authority

| Boundary | Who supplies the input | What an attacker can gain if the boundary fails |
|---|---|---|
| File bytes to parser | An upload author, downloaded-media publisher, or process that can alter an open file supplies container headers, sample tables, codec configuration, compressed packets, metadata, subtitles, or an HLS index. | A parser error can corrupt a report or output. Excess work or allocation can deny service in the calling process. A memory error in an enabled native dependency or an unsafe kernel can affect that process's memory and authority. |
| URL to HTTP source | A caller supplies a URL and optional headers. A remote server, redirect target, or network peer supplies responses and object changes. | The caller's host can be made to contact an unintended endpoint, disclose request headers, download excessive data, or wait on a slow response. Returned media then reaches the same parsers as a local file. |
| Standard input to compatibility fallback | A pipe producer supplies an arbitrary or endless byte stream. The caller supplies a command that selects stdin. | The separate FFmpeg program can parse those bytes with the caller's inherited authority and consume resources outside CoreAV's native limits. |
| CLI arguments and environment to execution and filesystem operations | The invoking user, or a service that forwards user-controlled command tokens, chooses inputs, output paths, flags, fallback settings, and executable paths. Concat lists supply additional local paths. | This grants file reads, output replacement, network operations through fallback, or execution of a selected program. Shell-free argument passing does not make these requested operations harmless. |
| Parent to decoder or encoder worker | Parsed but still untrusted packets, stream configuration, frames, or PCM enter a native backend. A faulty backend can return arbitrary messages, frame descriptors, or coded output. | Native code can compromise the worker. A broken parent-side check can turn a malformed reply into a parent allocation, read, incorrect output, or loss of availability. |
| JavaScript host to WASM | A host supplies operation names, options, source sizes and reads, sinks, promises, cancellation, and HTTP behavior. | A hostile source can lie or stall. A host can retain output, raise permitted limits, or refuse to settle callbacks. The host already controls its own JavaScript environment; the module cannot protect that host from itself. |

The following sections pair each threat with the current mitigation, its evidence, and the remaining gap.

The workspace [lint policy](../../Cargo.toml) forbids unsafe Rust unless a crate has a scoped exception. The container parsers retain that policy. This limits memory-error mechanisms in their own Rust code. It does not prove parser correctness, termination, successful allocation, or the behavior of dependencies.

The gap is that these parsers run in the parent process for native probe, copy, report, and audio operations. Worker isolation begins at selected codec backends, not at the file boundary. A logic defect, excessive allowed work, blocking source read, or panic outside lint detection can still affect the caller. Syntax validation also does not authenticate media or make metadata suitable for direct HTML or terminal display.

## Resource exhaustion

`Limits` are caller-selected budgets with different scopes, not one command-wide allocator or deadline. The code defines the following principal bounds. Values are defaults at the evidence snapshot, not recommended service quotas.

| Type and evidence | What it bounds | Scope or gap |
|---|---|---|
| [`coreav_isobmff::Limits`](../../crates/coreav-isobmff/src/limits.rs) | Box depth 32; 10,000 top-level and 1,000,000 total boxes; 1 MiB box payloads; 16 MiB retained metadata; 256 MiB sample tables; 128 MiB packets; `2^26` sample-work visits; 1,000,000 fragments; 1,024 tracks. Inflated movie metadata is capped at 16 MiB and a 256 expansion ratio. | Structural counters and retained-byte budgets, not total RSS or elapsed time. A legal request can still perform substantial work. |
| [`coreav_mkv::Limits`](../../crates/coreav-mkv/src/limits.rs) | 1,000,000 probe elements; 1 MiB element buffers; 16 MiB retained metadata; 256 MiB cue indexes; 128 MiB packets; `2^26` listing or scan element visits; 1,024 tracks; 256 MiB inflation work for size listings. | Inflation-size budget exhaustion can leave a frame size unknown rather than fail the whole listing. This is not an aggregate process allocation limit. |
| [`coreav_mpegts::Limits`](../../crates/coreav-mpegts/src/limits.rs) | 16 MiB initial probe, 4 MiB tail with zero retry doublings, 1 MiB resynchronization, 256 programs, 1,024 streams, 64 MiB packets, 256 MiB buffered across PIDs, and `2^32` listed transport packets. | Listing defaults allow a very large amount of input. A byte or packet budget is not a wall-clock deadline. |
| [`coreav_audio::Limits`](../../crates/coreav-audio/src/limits.rs) and [`TextLimits`](../../crates/coreav-text/src/lib.rs) | Audio adds 32 channels, 16 MiB packets, `2^33` output samples counted across channels, and 100 decode errors replaced with silence. Text adds 1 MiB samples, 10,000 chapters, and 4 MiB title bytes. | The audio pipeline inherits ISO and Matroska limits. These bounds do not provide a hard process-memory or wall-time limit. |
| [`coreav_decode::Limits`](../../crates/coreav-decode/src/lib.rs) | Width and height 16,384, `2^27` pixels, 512 MiB per packed frame, 4 GiB decoded bytes per decoder, 1 GiB pending bytes, 128 MiB packets, 16 reference frames, a 60-second decoder-session timeout, and an 8 GiB memory budget. | Decoded bytes are not a sample count or a command-wide total. The memory budget is per sandboxed process where the OS enforces it. Retained caller outputs and multiple sessions need separate accounting. |
| [`coreav_h264::Limits`](../../crates/coreav-h264/src/limits.rs) and [`coreav_vp9::Limits`](../../crates/coreav-vp9/src/limits.rs) | H.264 bounds macroblocks, DPB pictures, slices, NAL bytes, threads, and estimated decoder memory. VP9 bounds dimensions, pixels, packets, and aggregate retained capacities and allocation requests during a call. Both default to an 8 GiB memory budget. | H.264 can lower thread count to fit. VP9 excludes borrowed packets, previous returned outputs, and allocator overhead. Neither budget is a host-wide memory reservation. |
| [`SandboxLimits`](../../crates/coreav-worker/src/protocol.rs) and [`EncoderLimits`](../../crates/coreav-transcode/src/encoder.rs) | Address space, CPU seconds, and open descriptors for worker or encoder processes. The launcher additionally sets core-file and regular-file size limits to zero on Unix. | Platform enforcement differs below. Each child has its own budget. The sum can exceed available host memory. |
| [`annexb::Limits`](../../crates/coreav-transcode/src/annexb.rs) and [`PacketLimits`](../../crates/coreav-transcode/src/contract.rs) | H.264 output NAL and access-unit bytes, units per access unit, pictures and bytes per open period, and total pictures. The packet ledger bounds packet count, individual packet bytes, and cumulative output bytes. | Annex B's default total-picture count is `u64::MAX`; the pipeline must supply or update the bound from submitted frames. These bounds do not limit all temporary disk use or all output writers. |
| [`coreav_avi::Limits`](../../crates/coreav-avi/src/lib.rs), [`coreav_aac::Limits`](../../crates/coreav-aac/src/lib.rs), and [`coreav_h264_encoder::Limits`](../../crates/coreav-h264-encoder/src/api.rs) | AVI writer layout metadata and packet work; AAC configuration channels; native encoder coded pixels, frames, access-unit bytes, and total NAL bytes. | These are separate APIs, not a new AVI input parser or a global decode budget. AAC and native encoder inclusion depends on the build and caller. |

[Pinned allocation tests](limits.md) measure selected parser and writer paths, including oversized declared counts and large synthetic fragmented sources. [CI](../../.github/workflows/ci.yml) invokes the unsafe registry check and workspace lint and test checks, with dedicated fixture and memory checks. Those tests do not measure every allocation path or every combination of limits.

The remaining threat is aggregate exhaustion across requests, streams, child processes, retained frames, output bytes, or spools. Native [`Source::read_exact_at`](../../crates/coreav-isobmff/src/source.rs) is synchronous and has no cancellation argument. A parser counter cannot interrupt a blocked implementation of that trait. A service still needs admission, concurrency, disk, and lifetime controls outside these types.

Limit forwarding also differs by operation. [`coreav-wasm::ops`](../../crates/coreav-wasm/src/ops.rs) accepts ISO limit overrides, but `probe_document` uses the Matroska wrapper's defaults and the Matroska remux branch explicitly supplies default MKV limits. [`check::probe_source_limited`](../../crates/coreav-cli/src/check.rs) likewise uses default Matroska or TS limits for those formats. Lowering the ordinary WASM `limits` option does not lower those readers. In contrast, [`ffprobe::probe_limited`](../../crates/coreav-cli/src/ffprobe/mod.rs) translates limits for MKV and TS through [`ffprobe/limits.rs`](../../crates/coreav-cli/src/ffprobe/limits.rs). Policy `file.max_size` is evaluated after probing, not as an ingress byte cap.

## Native libraries and unsafe code

The Linux and macOS packaged default links these C media libraries. The table distinguishes decoding untrusted compressed bytes from encoding derived samples. [The codec build recipe](../../packages/cli/scripts/codecs.sh) pins versions and archive hashes; feature-enabled development builds can instead use installed libraries. The pins do not establish the bytes used by every local build.

| Library | Entry and current mitigation | Evidence and gap |
|---|---|---|
| dav1d | AV1 packets enter `coreav-backend-dav1d`. The CLI selects a `SandboxedBackend` worker rather than decoding in the parent. | [Backend manifest](../../crates/coreav-backend-dav1d/Cargo.toml), [backend implementation](../../crates/coreav-backend-dav1d/src/lib.rs), and [CLI backend selection](../../crates/coreav-cli/src/thumbnail.rs). CoreAV uses the Rust `dav1d` wrapper, with C and FFI below it. No CoreAV-authored unsafe site does not mean no native memory-error exposure. |
| libvpx | VP8 and VP9 packets enter `coreav-backend-libvpx`, also in a CLI worker. Rust checks packet sizes, advertised geometry, and returned frame views. | [FFI](../../crates/coreav-backend-libvpx/src/ffi.rs) checks ABI layouts, pointer-related row extents, and borrowed-image lifetimes. The checks still trust libvpx's allocation and image-storage contracts. The `frame_sizes` fuzz target tests Rust headers, not libvpx decoding. |
| libopus | The CLI's Opus encode worker feeds PCM to `coreav-backend-libopus` and reads bounded packet messages back. Opus source decoding is the separate Rust `coreav-opus` implementation. | [Backend](../../crates/coreav-backend-libopus/src/lib.rs) and [worker](../../crates/coreav-worker/src/opus.rs). Rust wrapper calls still enter native libopus. This is an encode boundary, but input sample values and counts remain derived from untrusted media. |

[`docs/unsafe-sites.md`](../unsafe-sites.md) is the authoritative file inventory and precondition record. Its groups include H.264 SIMD dispatch, loads, stores and prefetch; H.264 hot-path target-feature calls and assembly; the audio AVX kernel; libvpx FFI; worker shared-memory mappings and copies; test-only allocation instrumentation; and the standalone Apple framework FFI.

The mitigation is confined unsafe modules with checked windows, CPU-feature evidence, ownership rules, and documented contracts. The worker parent validates descriptors before copying bytes out of shared memory without creating a Rust reference to concurrently writable mapped storage. The `descriptor` fuzz target exercises both ordinary buffers and real shared-memory copies. Kernel targets compare optimized paths with reference paths. The test-only allocator is not a production dependency.

The gap is that [`unsafe_sites_check.py`](../../scripts/unsafe_sites_check.py) checks file registration and lint exceptions, not each new unsafe expression's soundness. It does not audit third-party FFI or C source. A listed file can gain an incorrect site without gaining a new inventory row. Reference comparisons and sanitizer runs do not prove all CPU paths or native dependencies correct.

The standalone [`coreav-backend-apple`](../../crates/coreav-backend-apple/Cargo.toml) uses VideoToolbox and AudioToolbox in-process. Its checked frame storage, native ownership, callback lifetimes, and returned-output validation are additional boundaries, not a subprocess sandbox. Framework calls and allocations are not interruptible or bounded by a hard process-memory budget. Its presence in the tree does not establish inclusion in the packaged CLI default.

Apple's audio and video `Limits` separately bound submitted frames, chunks, pending identities, packet and configuration bytes, cumulative output, and retained storage. Video limits also bound pixel-buffer allocation requests. [Standalone backend CI](../../.github/workflows/encoder-backends.yml) tests these APIs on macOS. The standalone [`coreav-backend-svt-av1`](../../crates/coreav-backend-svt-av1/src/lib.rs) currently contains only output readers with packet, OBU-count, and sequence-header bounds. It links and calls no encoder library. Neither standalone crate is a current CLI encoder session.

## External programs and worker replies

There are two distinct FFmpeg boundaries. The compatibility fallback runs the installed program on the original command and input. A decoder backend or encoder can instead run under the worker launcher.

| Execution path | Current mitigation and evidence | Gap |
|---|---|---|
| `coreav ffmpeg` or `coreav ffprobe` compatibility fallback | [`fallback_cmd::refuse` and `run`](../../crates/coreav-cli/src/fallback_cmd.rs) select `COREAV_FALLBACK` or a different program on `PATH`, set a recursion guard, and pass the original argument vector without a shell. [`fallback.rs` tests](../../crates/coreav-cli/tests/fallback.rs) check original arguments, stdin, strict-mode refusal, and post-probe fallback. [Windows tests](../../crates/coreav-cli/tests/fallback_windows.rs) check exit propagation and self-copy avoidance. | This runs a separate `ffmpeg` or `ffprobe` program on the same untrusted input, not a validated or sanitized substitute. On Unix `exec` replaces CoreAV's process image; elsewhere CoreAV waits for the child. This path does not use the resource-limited worker launcher, clear the environment, or impose native parser limits. The installed binary and its protocol support are outside this note's source evidence. |
| Sandboxed codec workers | [`thumbnail.rs`](../../crates/coreav-cli/src/thumbnail.rs) launches the CoreAV executable in hidden worker modes for dav1d and libvpx. The optional [`coreav-backend-ffmpeg`](../../crates/coreav-backend-ffmpeg/src/lib.rs) runs an external FFmpeg decoder. [`coreav-worker`](../../crates/coreav-worker/src/lib.rs) bounds messages and validates frames returned by these backends. | A process boundary protects neither files nor network access by itself. Resource controls and descriptor checks do not make a compromised child trustworthy. Direct library backend use can bypass the CLI worker. |
| External video and audio encoders | [`encoder.rs`](../../crates/coreav-transcode/src/encoder.rs) discovers x264 or FFmpeg, feeds frames through pipes, bounds queues and retained stderr, and parses coded output. [`audio.rs`](../../crates/coreav-transcode/src/audio.rs) feeds PCM to FFmpeg for AAC or MP3, or to the CoreAV libopus worker. CLI launches use [`coreav-worker::exec`](../../crates/coreav-worker/src/exec.rs). | x264 and FFmpeg remain operator-installed programs. Generated arguments are not executable authentication. Derived raw samples reduce the compressed-input parser boundary at an encoder, but native encoder defects and malicious output remain possible. Library APIs with an optional launcher must not be assumed to have CLI confinement. |

[`protocol::read_message`](../../crates/coreav-worker/src/protocol.rs) checks message length before payload reservation. [`descriptor::check`](../../crates/coreav-worker/src/descriptor.rs) checks sequence, slot, format, geometry, plane extents, strides, and byte totals. [`parent::read_worker`](../../crates/coreav-worker/src/parent.rs) rejects incorrect ordering and reused slots, counts decoded bytes, and applies queue backpressure. [Worker hostile tests](../../crates/coreav-worker/tests/hostile.rs) exercise malformed replies, blocked input, deadlines, and slot ownership. [Encoder lifecycle tests](../../crates/coreav-transcode/tests/sandboxed.rs) exercise early exits and stalled I/O. These checks constrain replies, not the integrity of pixels produced by a compromised decoder.

[`StrictSafe`](../../crates/coreav-cli/src/strict_safe.rs) centralizes `--strict-safe` and `COREAV_STRICT_SAFE`. It refuses compatibility fallback, FFmpeg decoder selection, and FFmpeg audio or video encoding. It also refuses sandboxed work when `enforces_memory_limit()` is false. Hidden worker entries carry the mode in arguments because worker launches clear the environment. [Strict-mode tests](../../crates/coreav-cli/tests/strict_safe.rs) cover these entries, resolved encoders, and refusal before reading input.

This mode is an execution policy, not a guarantee that every native parser or dependency is isolated. Executable filename and canonical-target checks cannot identify arbitrary malicious programs renamed to x264. Executable paths, `PATH`, and environment settings remain operator-trusted inputs.

## Platform confinement

The code calls the resource-limited worker a sandbox. Here that means a separate process, constrained I/O arrangements, and the controls below. It does not mean a filesystem or network capability boundary.

| Platform or entry | Existing controls and evidence | Missing control or limitation |
|---|---|---|
| Linux worker and external-program launcher | [`sandbox::apply`](../../crates/coreav-worker/src/sandbox.rs) lowers soft and hard `RLIMIT_CORE`, `RLIMIT_FSIZE`, `RLIMIT_AS`, `RLIMIT_CPU`, and `RLIMIT_NOFILE`, preserving tighter inherited values. Parent and launcher code clear the environment, use pipes, and manage process lifetime. [Exec tests](../../crates/coreav-worker/tests/exec.rs) check effective limits, environment clearing, and regular-file growth refusal. | No syscall filter, network namespace, filesystem allowlist, privilege drop, process-count limit, or aggregate cgroup memory limit is installed by these launch paths. `RLIMIT_FSIZE=0` is not a filesystem-read or network prohibition. Address-space limits are per process, not host-wide memory guarantees. |
| macOS worker and launcher | The Unix CPU, descriptor, core-file, and regular-file limits still apply. Parent-side deadlines and reply validation still apply. | `enforces_memory_limit()` excludes Apple targets. Address-space memory budgeting is advisory. Strict mode refuses sandboxed work instead of claiming a hard memory cap. The launcher does not install an Apple application sandbox. |
| Windows | Native parsers and the compatibility fallback have Windows test coverage in [CI](../../.github/workflows/ci.yml). The exec launcher refuses non-Unix execution with status 125, and packaged Windows builds omit the C codec-worker features. | The worker's non-Unix `sandbox::apply` is a no-op. This is not Windows Job Object or restricted-token confinement. A working Windows fallback is not evidence of an isolated decoder or encoder. |
| Native parser and direct library calls | Rust lint policy and per-operation limits apply in the embedding process. | CoreAV does not create a separate process around all parsing or direct library calls. The embedding application supplies any OS isolation. |
| WASM module | The engine invokes the compiled module through host adapters and validates source and sink contracts. Package limits and cancellation controls apply as described below. | The runtime and host grant memory, CPU, network, and I/O authority. The Rust module does not install a native OS sandbox around its host. |

The initial decoder `Open` message is parsed before `sandbox::apply` in [`child::run`](../../crates/coreav-worker/src/child.rs), under protocol size checks rather than the requested OS limits. Unix keepers kill the worker's process group and immediate child at the deadline. That is not a guarantee against a descendant creating a separate session. `a_worker_that_escapes_its_group_cannot_hang_the_parent` in the hostile tests proves prompt parent timeout and separately cleans up the escaped process. Windows has no corresponding group kill in this implementation.

## URLs, object changes, and stalled sources

A URL is both a source of bytes and a request for network access. The native [`remote.rs`](../../crates/coreav-cli/src/remote.rs) adapter and JavaScript [`sources.js::httpSource`](../../packages/wasm/src/sources.js) adapter have their own request and response policies. A valid HTTP response does not establish that contacting its destination was authorized.

Both adapters check range responses, lengths, request counts, and available object validators, and bound reader buffering. Native CLI defaults permit 10,000 reader requests, a 4 GiB spool, 15-second connect, 60-second idle, and 300-second body timeouts. They have no object-wide deadline, and [`Settings::NATIVE`](../../crates/coreav-range/src/lib.rs) leaves received bytes at `u64::MAX`. JavaScript defaults permit 1,000 reader requests with bounded cache and pipeline buffers, but `httpSource` supplies no total-transfer or elapsed-time option. Redirect hops are outside the reader request count.

Native CLI options intentionally permit private addresses, HTTP, and environment proxies. `Options::guarded`, the [Python URL entry's](../../crates/coreav-py/src/lib.rs) default, instead requires HTTPS, disables proxies, checks every resolved address, and connects using that checked resolver result. It adds a 16 GiB receive cap and a one-hour object deadline. [Remote unit tests](../../crates/coreav-cli/src/remote.rs) cover guarded-address classification. [Range tests](../../crates/coreav-range/tests/plan.rs) cover request and byte caps, retries, and changed objects.

Native [remote tests](../../crates/coreav-cli/tests/remote.rs) cover range fallback, changed objects, failure classification, and command behavior over URLs. JavaScript [HTTP tests](../../packages/wasm/test/http.test.mjs) cover identity encoding, gzip rejection, and cross-origin header handling. The JavaScript adapter refuses userinfo on initial and redirect URLs, defaults redirects off, and permanently drops caller headers after a cross-origin hop when redirects are enabled. Native initial URL checks refuse userinfo too, but `Job::fetch` checks redirect scheme without reusing `check_url`'s userinfo check. CoreAV's own redirect code therefore does not establish the same userinfo refusal for native redirects; dependency behavior is not verified here.

The gap is destination authorization for the CLI defaults and JavaScript adapter. JavaScript delegates resolution and destination access to its fetch host rather than applying the native guarded-address policy. A permitted URL can name a private or privileged HTTP endpoint reachable from that host. Guarded mode reduces this exposure but is not an application-specific destination allowlist. Network timeouts also do not bound native local filesystem reads, arbitrary user-supplied `Source` implementations, or compatibility fallback.

Object validators and size checks detect selected changes, not cryptographic identity. [`hls::prepare`](../../crates/coreav-cli/src/hls.rs) checks source length against the stored index. A same-length replacement is not authenticated by that check. A service that reuses indexes must bind them to the intended immutable object separately.

## CLI arguments, stdin, files, and output

The native compatibility parsers refuse stdin media inputs. [`ffprobe::args`](../../crates/coreav-cli/src/ffprobe/args.rs) refuses `-`; [`ffmpeg::args`](../../crates/coreav-cli/src/ffmpeg/args.rs) refuses `-` and `pipe:` inputs. Without strict mode, those refusals can select the compatibility fallback, which inherits stdin, stdout, stderr, environment, and working directory. Thus stdin has a different limit and parser boundary from native file input. A service cannot treat a pipe as a way to force native bounded parsing.

[`concat::read`](../../crates/coreav-cli/src/concat.rs) accepts only local file directives and the supported header, caps the list at 1 MiB plus one detection byte, and applies portable relative-path rules unless `-safe 0` was requested. That reduces traversal through list syntax. It is not a canonical-directory confinement rule against filesystem symlinks. `-safe 0` deliberately expands the caller's path authority.

[`output::refuse`, `to_file_patched`, and `place`](../../crates/coreav-cli/src/output.rs) reject the input as output, use exclusively created temporary files, check flush errors, and normally install successful results without replacing an existing destination unless requested. This reduces accidental destruction and partial output. The fallback path has the external tool's output behavior instead. On filesystems without hard links, the native no-overwrite fallback checks existence and then renames, so it is not an atomic no-replace operation against another directory writer.

The remaining gap is application authorization and aggregate output control. These helpers do not restrict outputs to a service-owned directory, reserve disk capacity, or provide one byte cap for every writer. A caller that forwards arbitrary command tokens has granted more authority than a caller that accepts one media upload and chooses its own paths and policy.

Reports and logs are another output boundary. [`fallback::log_line`](../../crates/coreav-cli/src/fallback.rs) replaces non-public argument values before writing its optional log. `private_values_never_reach_the_log` checks marker removal. This is evidence about that log, not a promise that ordinary metadata, paths, stderr from external programs, or caller-selected output contains no sensitive data.

## WASM host behavior

The JavaScript adapters and Rust operations layer must treat claimed source lengths, read results, options, and sink failures as untrusted. Native fuzz targets for [`coreav-wasm`](../../crates/coreav-wasm/fuzz/fuzz_targets/ops.rs) inject source and sink failures and exercise damaged HLS indexes. The [`ffprobe` target](../../crates/coreav-wasm/fuzz/fuzz_targets/ffprobe.rs) also checks deterministic clean results and errors under injected reads.

[`bindings::Js::read_exact_at`](../../crates/coreav-wasm/src/bindings.rs) checks extents and exact read length. Ordinary operations start with ISO defaults except a 64 MiB table limit; their overrides can raise or lower those fields. Ordinary [`engine.js`](../../packages/wasm/src/engine.js) does not enable exclusive admission, and a custom source may ignore the reader's memory hints. It has no universal operation deadline. [Module tests](../../packages/wasm/test/module.test.mjs) check that host exceptions stay in `cause` rather than public I/O messages.

The separate H.264 package enables exclusive admission in [`engine.js`](../../packages/wasm-h264/src/engine.js) and accepts only its bounded source adapters. [`thumbnail::resolve`](../../crates/coreav-wasm/src/thumbnail.rs) lowers parser retention, tables, and packets to 4 MiB and decoder memory to 32 MiB, with only lower overrides. Its [Node broker](../../packages/wasm-h264/src/node-broker.js) has a default 5,000 ms deadline, only lowerable, and terminates the worker thread. [Node wiring tests](../../packages/wasm-h264/test/node-wiring.test.mjs) exercise message-port behavior. [Node lifecycle tests](../../packages/wasm-h264/test/node-lifecycle.test.mjs) cover cancellation and cleanup. This is not a native child-process memory cap or a guarantee that every other WASM host can interrupt synchronous work.

The gap is the distinction between module budgets and host budgets. The host must bound concurrency, retained JavaScript buffers, callback lifetimes, and runtime resources. Native Rust fuzz execution does not exercise the generated WASM glue, JSPI behavior, browser or Node scheduling, or the HTTP adapter. Package tests cover selected cases in those layers, not every hostile host behavior.

## Fuzzing coverage and its limits

The current inventory is 79 targets across 26 projects. Regenerate it with `python3 scripts/fuzz_plan.py --all`; target discovery and dependency closure come from Cargo metadata. The count is a snapshot, not a coverage percentage.

Targets cover ISO probe, packets, metadata, compressed movies and buffering; Matroska probe, blocks, packets and scans; TS sections, PES, packets and probe; text and policy; audio packets and decoding; native H.264 and VP9; H.264 and audio kernels; writer operations and stored HLS indexes; frame operations and thumbnails; encoder-output parsers; worker messages, descriptors and Opus packets; and CLI and WASM operation layers. The standalone Apple and SVT-AV1 projects add output-parser targets, not proof of the OS or native encoder internals.

[`ci.yml`](../../.github/workflows/ci.yml) selects affected projects for ready pull requests using [`fuzz_plan.py`](../../scripts/fuzz_plan.py). Its per-target time is `clamp(480 / target_count, 5, 30)` seconds, split over two shards. [`fuzz-nightly.yml`](../../.github/workflows/fuzz-nightly.yml) schedules every target daily for 900 seconds each by default. Main pushes and merge groups do not run the short PR fuzz phase. [`fuzz_run.sh`](../../scripts/fuzz_run.sh) uses cargo-fuzz, a pinned nightly, a 10-second per-input timeout, a 2 GiB RSS limit, and captured target logs. Nightly findings are uploaded privately rather than exposed as public crash artifacts. PR findings are withheld from public logs too.

Important gaps remain. The libvpx target parses frame sizes without enabling libvpx, and there is no dav1d decoding fuzz project in this inventory. Pure Rust output-parser targets do not fuzz a running x264, FFmpeg, Apple framework, or libopus session. Fixed argument choices in the CLI `ffprobe` target do not cover arbitrary command-line fallback. Native WASM-operation targets do not cover a live malicious JavaScript host or HTTP server. Platform and CPU-feature branches depend on which machine executes the target. A scheduled workflow is not proof that every scheduled run completed or that the separate [release campaign](fuzz-campaign.md) passed. No fuzz campaign or hostile-media execution is part of this documentation change.

## Ranked gaps

This order weighs reachable authority and service-wide impact before narrower verification gaps. It is a planning order, not a vulnerability severity score or evidence that a particular input exploits the code.

1. Compatibility fallback crosses into an unconstrained external parser on the original input and arguments. Native parsing limits do not carry across that boundary. Keep this path distinct from resource-limited codec workers when selecting and interpreting hostile-input tests.
2. Worker isolation lacks filesystem, network, and syscall restrictions. A compromised native backend can retain the user's read and network authority even where address-space and CPU limits work.
3. Resource budgets do not compose into one service-wide memory, work, output, disk, concurrency, or lifetime limit. Some WASM operations do not forward lowered limits to Matroska or TS. Synchronous native source reads cannot be interrupted by parser counters. Defaults permit substantial individual requests.
4. HTTP CLI defaults and the JavaScript adapter permit destinations that an embedding service may not intend. Native guarded mode exists, but application authorization, redirect validation consistency, and fetch-host behavior remain separate concerns.
5. Platform memory confinement is uneven. macOS uses advisory worker memory budgets and strict-mode refusal; non-Unix resource-limit application is a no-op. In-process parser and Apple framework paths have no worker memory boundary.
6. Native dependency and unsafe-path assurance is incomplete. The registry is file-level, C storage contracts remain trusted, and current fuzz targets do not exercise every C decoder, encoder, architecture, or process-launch path.
7. Host and filesystem consistency depend on the embedding application. WASM host retention and scheduling, same-length source replacement, concat symlinks, and non-atomic no-overwrite fallback are not resolved by media syntax validation. Tests for those contracts must stay separate from parser fuzz results.
