# SVT-AV1 output validation

The [encoder contract](../encoders.md) defines the backend's scope and acceptance bars. This crate implements bounded AV1 framing, sequence and frame-header validation, complete temporal-unit samples, and a feature-gated native worker for 8-bit 4:2:0 SDR output. Parser-only builds link no native library. The standalone CLI route is implemented, but release feature sets do not select the native backend yet. Native runtime correctness and release linkage remain unverified.

## Framing is a separate boundary

An encoder packet is untrusted even when it comes from a linked library. The framing reader borrows the supplied bytes and checks their extents without copying payloads. Caller-provided limits bound the packet size and number of OBUs, including zero-length OBUs. AV1 size fields occupy at most eight bytes and cannot exceed the specification's 32-bit value range. Nonminimal size encodings remain valid.

The reader rejects forbidden or reserved header bits, reserved OBU types, missing size fields, truncated extensions or payloads, invalid size fields, and temporal delimiters with payloads. It also rejects extension headers on sequence headers, temporal delimiters, and tile lists, following the published HTML specification's layer-specific table. Reserved-type rejection is a strict backend-output subset: a general AV1 decoder must ignore reserved types. The reader exposes OBU kinds, layer identifiers, and borrowed payloads only through its checked views.

Framing validity does not establish that a sequence header or frame payload is valid. It also does not establish frame count, order, timestamps, color metadata, or agreement with submitted frames. Callers must not derive an MP4 sample description or mux packets from framing checks alone.

## Sequence configuration

The sequence reader takes a checked OBU and rejects any kind other than a sequence header. Caller limits bound payload bytes and maximum frame dimensions before the reader returns configuration. The reader consumes the sequence syntax, including optional timing, operating points, decoder-model fields, and trailing bits. Both normal and reduced still-picture headers are supported.

The accepted output scope is profile 0, 8-bit, non-monochrome 4:2:0 without film grain or PQ or HLG transfer characteristics. Valid AV1 formats outside that scope are unsupported rather than silently converted. Reserved fields, invalid clock values, malformed conditional syntax, and missing or nonzero trailing padding are errors. The configuration retains the signaled color description and range without changing them. Unspecified color metadata remains accepted, but does not prove that the source is SDR. The caller must establish the SDR source requirement separately.

Sequence maximum dimensions are upper bounds, not the dimensions of every decoded frame. Timing describes the sequence clock, not submitted-frame timestamps. The reader does not establish frame syntax, actual dimensions, frame count, order, decoder-level conformance, or agreement with the request. Those checks remain necessary before output can be accepted for muxing.

The four-byte `av1C` header comes from checked profile, level, tier, bit-depth, and chroma fields. It is not a complete MP4 sample description. Its optional initial presentation delay is absent: the sequence's initial display delay counts frames, while the container's initial presentation delay counts samples and cannot be derived without sample grouping.

## Safe verification

The crate is a workspace member and uses the root lockfile. Its local lint configuration retains the workspace's production restrictions and scopes the native exception to its private module. The fuzz project keeps its separate lockfile. Safe verification uses:

```sh
cargo fmt --manifest-path crates/coreav-backend-svt-av1/Cargo.toml --check
cargo clippy --manifest-path crates/coreav-backend-svt-av1/Cargo.toml --all-targets -- -D warnings
cargo test --manifest-path crates/coreav-backend-svt-av1/Cargo.toml --locked
cargo test -p coreav-transcode --features svt-av1 --test av1 --test contracts --locked
cargo deny --all-features --manifest-path crates/coreav-backend-svt-av1/fuzz/Cargo.toml check licenses
```

Construction checks the packet byte limit. Iteration checks each OBU and its count limit. Callers must consume the reader through its final `None` and propagate every error before accepting a packet. An error ends iteration permanently. An empty packet is an empty sequence, not a valid encoded frame.

The hostile-output fixtures check truncated input, invalid headers and lengths, and exact limit boundaries. The `fuzz/` project exposes the `obu` and `sequence` targets for affected-target CI. The framing target checks finite iteration, caller bounds, layer-ID ranges, and terminal errors. The sequence target parses arbitrary payloads behind a valid sequence-OBU header and checks configuration bounds. These are correctness checks, not encoder acceptance results. None of bars A1 through A6 has been measured by this unit.

## Runtime acceptance remains separate

The optional native feature builds the C bridge against the verified recipe installation. Actual FFI files and their safety rows are recorded together in `docs/unsafe-sites.md`. The backend-scoped licence checker validates the native dependency separately from Rust licensing. SVT-AV1 distributions retain the upstream copyright, licence, and AOM Patent License 1.0 notices. These requirements do not change the licence of CoreAV's own glue code.

The versioned worker protocol and backend-local stdio entry are implemented, with synthetic native-fixture tooling whose execution remains gated. The safe parent `coreav-transcode::av1::OutputSink` validates complete samples into one bounded spool and binds them to the completed submission ledger by replaying one payload at a time. The sample reader owns each segment's parser allowance, the smaller of its fixed session cap and remaining job samples, for both the parent and native fixtures. This allowance never shrinks native retention. The parent constructs `av1C` from the four-byte checked header followed by the complete validated sequence OBU. Segment-local native assertions never replace global source timestamps. Synthetic tests cover continuous variable clocks with positive and negative origins, exact final duration and sync positions, changed configuration, reset global identities, invalid native assertions, incomplete output, count mismatches, spool extents and terminal failure classification. They do not decode entropy-coded tiles or run SVT-AV1.

The parent `av1::Encoder` drives the existing `Process<OutputSink>` and bounded frame queue. Its checked request supplies both the raw input layout and the output expectations; it sends sequential identities and original source timestamps with packed rows, then the actual count and physical pipe EOF. The ledger stays on the caller's thread until final replay. An input failure replaces the running state with the first terminal error and drops the process through the existing keeper. One deadline covers input writes, output parsing, teardown and replay. The private worker must be an absolute executable path, never a PATH-discovered encoder. Synthetic process fixtures reexecute their own Rust program through the real sandbox launcher, validate every received input record and plane byte, and exercise failed output, incomplete completion, nonzero exits, stalled input and stalled completion. This is not production CLI dispatch, native execution or MP4 evidence. The eventual pipeline caller must keep its private spool owner alive and always supply the sandbox launcher.

The shared pipeline's H.264 and AV1 frame owners each return one private completed-video value with a validated sample entry and source-clock sample table. A single engine owns source preparation, decode pacing, audio encoding and replacement/remux. The legacy `transcode` entry retains its options and version 1 summary; H.264 input preparation, timestamp repair, settings and program discovery stay in its existing frame owner.

The feature-gated `Av1Transcode::prepare` entry checks build availability and parameter-known failures before media I/O. Its separate `Av1Options`, `CommonOptions` and `Av1Summary` do not add AV1 settings or result variants to the legacy API. Production callers must provide the sandbox launcher and implement the private worker entry in their executable. The job uses the timed driver, and every process actor retains the private spool owner until it releases the shared process state, including after caller cancellation. Synthetic source-to-MP4 fixtures exercise this engine with handwritten AV1 bytes and synthetic decoded pictures; they are not native encoding or independent reconstruction evidence.

AV1 admission requires planar 8-bit 4:2:0, positive SDR transfer metadata and an applied source range. Known header incompatibilities are refused before decoder opening; decoded geometry, format and effective colour must remain fixed. Missing and contradictory metadata is not replaced with H.264 defaults. Only an explicit scale resizes pictures, with representable chroma siting and an exact adjusted sample aspect. Parent staging and source-timeline storage are checked separately from the native retained-input budget; neither budget claims to include SDK-internal allocations. A native layout fault retains encoder-error classification instead of becoming an unsupported-source refusal.

The optional timed driver entry consumes a bounded expected source timeline. It uses the exact presented average `N * clock_den / ((last_pts - first_pts + final_duration) * clock_num)` for the native settings cadence, reduced before conversion to native rational fields. This is not a constant-frame-rate conversion: every submitted timestamp must equal the next original presented timestamp. Duplicate source times, unrepresentable MP4 intervals, an unknown single-frame duration and unrepresentable rational fields are refused. The final duration is the last presented packet's positive duration, or its preceding positive presentation interval when that packet has no duration. Reference-only packets do not affect the cadence. Timeline construction, input and completion use one deadline. Missing or extra submitted frames, a changed timestamp or a different final duration terminate the job. The low-level raw driver remains available without a container timeline. These source-timing and synthetic process checks do not establish source colour admission, native output, MP4 muxing or production CLI integration.

The CLI's private `__coreav_svt_av1` entry is dispatched before command parsing and accepts only an optional strict-safe flag. It checks strict-safe sandbox policy and the supported native build before entering the backend's stdio worker. The CLI's `transcode` feature includes safe AV1 adapters; `svt-av1` also enables this private entry, and `svt-av1-native` additionally selects the verified static native backend. Public selection and private dispatch share one availability check requiring both the CLI's native feature and the supported compiled backend. Parser-only builds refuse this entry without emitting worker output. Safe fixtures cover rejected arguments, the strict-safe flag and environment, and reexecution through the existing sandbox launcher. They do not invoke the native encoder. The release feature sets do not select the native backend yet.

Only explicit `coreav transcode --video av1` selects this backend. Its CRF and preset are exact integer tokens, with defaults 32 and 8. Every AV1 route checks the original CRF token as a bounded integer before deriving a floating-point value, including when the legacy H.264 parser accepts a rounded probe value. H.264 keeps its original parser and fractional CRF behavior. AV1 refuses bitrate and thread controls and incompatible encoder choices. The embedding entry always selects a private Embedded host variant, so an executable path or unified Cargo feature cannot claim to supply the standalone worker hook.

The separate AV1 serializer emits [`coreav.transcode/2`](../../schema/transcode-v2.md). Source codec and decoder remain distinct from `video.encoding`, which names the software encoder, version, sandbox launcher, exact settings cadence, colour, retained-input accounting and completed session counts. Parallelism level 1 is separate from a null thread limit, and address space remains a requested allowance rather than an enforcement claim. One shared serializer owns copied streams, encoded audio, dropped streams and output size for both versions. The H.264 video document and version 1 schema are unchanged. Synthetic serializer fixtures and an illustrative example test this contract without encoding media.

CLI selection and serialization are implemented, but native source-to-MP4 execution, independent decoder gates, release packaging and required four-target native runtime coverage remain unverified. No quality or speed campaign is authorized by these source tests. A measurement-only in-process arm must never become a release feature or the default path.

## Static library build

`scripts/encoders/svt-av1/build.py` builds the pinned SVT-AV1 release into a new installation prefix. It does not enable the Rust backend, link a codec into CoreAV, or authorize distribution. Release packaging, notice integration, and the scoped licence check remain the integration owner's work.

Each target builds on its native OS and architecture. The script refuses a different host rather than silently cross-compile or substitute a glibc library.

| Target | Build host | C compiler | macOS deployment minimum |
|---|---|---|---|
| `x86_64-unknown-linux-musl` | Linux x86-64 | `musl-gcc` | Not applicable |
| `aarch64-unknown-linux-musl` | Linux AArch64 | `musl-gcc` | Not applicable |
| `x86_64-apple-darwin` | macOS x86-64 | `clang` | 10.12 |
| `aarch64-apple-darwin` | macOS AArch64 | `clang` | 11.0 |

The host needs Python 3.9 or later, CMake 3.16 or later, Make, and native C and C++ compilers. CMake configures both languages even though the encoder library is C. x86-64 builds also need NASM 2.14 or later. Linux needs `readelf`, `gcc-ar`, and `gcc-ranlib`. The recipe explicitly supplies GCC's LTO archive tools because CMake's compiler-name inference can look for nonexistent musl-prefixed tools. macOS verification needs `lipo` and `otool`.

```sh
python3 scripts/encoders/svt-av1/build.py \
  --target aarch64-apple-darwin --prefix /absolute/path/to/svt-av1 --jobs 2
python3 -m unittest discover -s scripts/encoders/svt-av1 -p 'test_*.py'
```

The prefix's parent must exist and the prefix must not exist. No other process may create or change that destination during the build. `--archive` accepts a local copy of the same pinned tarball. The script verifies the full SHA-256 before extraction in both download and local modes. `--cmake` selects the CMake executable. `--jobs` accepts 1 through 16 and defaults to 2.

The recipe uses a Release static build with applications and upstream tests disabled, CPU-native tuning disabled, LTO enabled, and position-independent code. It ignores inherited build flags rather than let a caller's shell silently change the recipe. Temporary source and build directories are removed on success or failure. Installation is staged, verified, and published only after its link-and-version probe passes. Existing installations are never reused as evidence of a fresh build.

Each build-tool command has a one-hour timeout. Timeout or cancellation terminates and reaps the command's process group before removing its workspace. This is a build-tool bound, not an encoder deadline guarantee.

The probe retains the encoder API symbols and calls only the public version query. It checks the exact release version and target architecture. Linux's probe has no ELF interpreter or shared dependencies; macOS permits only system libraries. The probe performs no encoding, so success proves neither encoder conformance nor the release acceptance bars. The installed manifest records build settings and hashes of the archive, probe, headers, and notices.

The installation retains `LICENSE.md`, `LICENSE-BSD2.md`, and `PATENTS.md`, plus the `fastfeat` and `safestringlib` licence files. These are copied from the verified archive, not reconstructed from licence identifiers. The files alone do not establish complete release-package notice coverage.

## Specification

The readers are written from the [approved AV1 specification](https://aomediacodec.github.io/av1-spec/av1-spec.pdf), sections 4.10, 5.2, 5.3, 5.5, 6.2.2, and 6.4, and the published HTML specification's [OBU header semantics](https://aomediacodec.github.io/av1-spec/#obu-header-semantics). The configuration record follows the [AV1 ISO Media File Format binding](https://aomediacodec.github.io/av1-isobmff/), section 2.3. Other encoders' wrappers are not implementation references.

## Phase 1 implementation plan

This plan precedes the runtime implementation. It covers a safe native wrapper, sandboxed encoding, MP4 output, and explicit `coreav transcode --video av1` selection in one change. Existing H.264 output remains the default. Windows, AV1 output from the compatibility command, ten-bit input, HDR, and quality or speed acceptance runs are outside this implementation.

### Establish the native contracts before FFI

API declarations come only from the pinned recipe's installed public headers and the upstream `v4.2.0` documentation under `Docs/`. Input storage is retained through destruction of each bounded encoder session, not released on an inferred copy boundary. AV1 syntax and MP4 mapping come from the specifications linked above. Native implementation sources and other projects' integrations are not references. Hosted native smoke artifacts retain installed headers and the installation manifest for reproducible citations. Those headers are not committed to this repository.

The installed headers do not document input-picture reuse. [`EbSvtAv1Enc.h`, lines 1161–1166](https://gitlab.com/AOMediaCodec/SVT-AV1/-/blob/v4.2.0/Source/API/EbSvtAv1Enc.h#L1161-1166) describes `svt_av1_enc_send_picture` only as sending a picture with a header pointer. It gives no synchronous-copy guarantee or input-release event. [`EbSvtAv1.h`, lines 80–114 and 146–159](https://gitlab.com/AOMediaCodec/SVT-AV1/-/blob/v4.2.0/Source/API/EbSvtAv1.h#L80-159) defines the header and three plane pointers without a lifetime annotation. The examined user guide, parameter reference, and common-questions page supply no missing lifetime contract. This is a documentation gap, not evidence that the library retains input or copies it synchronously.

Two nearby copy guarantees do not close that gap. [`EbSvtAv1Enc.h`, lines 1122–1130](https://gitlab.com/AOMediaCodec/SVT-AV1/-/blob/v4.2.0/Source/API/EbSvtAv1Enc.h#L1122-1130) says that `svt_av1_enc_set_parameter` copies configuration. [`EbSvtAv1.h`, lines 234–259](https://gitlab.com/AOMediaCodec/SVT-AV1/-/blob/v4.2.0/Source/API/EbSvtAv1.h#L234-259) says that the structures and data passed through `p_app_private` are copied during `send_picture`. That text applies to private-data nodes, not `p_buffer`, `EbSvtIOFormat`, or the Y, U, and V planes.

The implementation does not wait for an upstream documentation change and does not assume immediate input reuse. Post-return page protection leaves an unobserved interval between `send_picture` returning and protection taking effect on every mapping. An asynchronous reader can finish in that interval without faulting. Repeated schedules and protection-fault controls cannot turn its absence of faults into a safe release boundary. No page-protection result authorizes early release of pictures, descriptors, ordinary headers, or EOF headers. Runtime wrapper FFI remains held until this bounded-session plan passes independent review. Actual test and native sites must receive their safety inventory and integration review before commit.

The installed evidence was produced by the pinned recipe on all four native Unix targets. The examined x86-64 musl artifact records upstream version `4.2.0` and the recipe's pinned archive digest. All seven installed headers matched their manifest digests before examination. In particular, `include/svt-av1/EbSvtAv1Enc.h` has SHA-256 `97e15377e1ac4634bdd0f36f1bf3ae3bd9644ff4e950f3f3eecaa38b463ffb90`, and `include/svt-av1/EbSvtAv1.h` has SHA-256 `cf84b3d5121798bf7af4396e9d01dd6ed214e42bdc6f52dc6f895e225a83adcc`. Line citations above refer to those installed bytes. Native build and link success establishes neither input ownership nor encoder correctness.

SVT's level of parallelism is not a thread count. [`Docs/Parameters.md`, lines 375–403 at `v4.2.0`](https://gitlab.com/AOMediaCodec/SVT-AV1/-/blob/v4.2.0/Docs/Parameters.md#L375-403) states that higher levels create more threads and retain more pictures. Lines 384–387 explicitly say that the level neither targets a thread count nor constrains logical processors. The `--pin` behavior in lines 400–403 restricts eligible cores, not the number of threads. The installed [`EbSvtAv1Enc.h`, lines 687–695](https://gitlab.com/AOMediaCodec/SVT-AV1/-/blob/v4.2.0/Source/API/EbSvtAv1Enc.h#L687-695) declares `level_of_parallelism`, supports levels 1 through 6, and describes 0 as automatic selection based on core count. The plan sets level 1 explicitly rather than making retained work depend on host core count. This remains a library parallelism choice, not a thread limit. The backend must not translate CoreAV's `--threads N` into parallelism level N or report that value as a thread limit. Initially, an explicit thread-count request is refused for AV1. The effective summary records parallelism level 1 separately from a null thread limit.

### Bounded sessions retain every submitted allocation

The selected design derives the maximum pictures per native session from a fixed retained-memory budget and the normal configured keyframe interval. The default retained-input budget is 1 GiB, or the caller's lower assigned budget, fixed before encoding. Let B be that budget, F the checked fixed retained overhead including the separate EOF header, and P the exact retained capacity for one picture's planes, descriptor, ordinary header, and retention slot. Compute C as `floor((B - F) / P)` with checked arithmetic and S as `min(K, C)`. The minimum supported segment length is one picture. Refuse before native initialization if F does not fit or one complete picture exceeds the remaining budget; do not round capacity up to the floor. Thus S is at least one only when one picture actually fits.

K is the backend's normal explicitly configured five-second closed-GOP interval, `max(1, floor(5 * frame_rate_num / frame_rate_den))` pictures. The five-second policy follows the documented approximate default in [`Docs/Parameters.md`, line 256](https://gitlab.com/AOMediaCodec/SVT-AV1/-/blob/v4.2.0/Docs/Parameters.md#L256). It is an explicit configured value, not a claimed observation of the library's opaque `-2` auto calculation. Refuse a zero rate, arithmetic overflow, or an interval outside the native field's range. Configure `intra_period_length = K`, `intra_refresh_type = SVT_AV1_KF_REFRESH`, `pred_structure = RANDOM_ACCESS`, and `multiply_keyint = false`. The installed [`EbSvtAv1Enc.h`, lines 228–267](https://gitlab.com/AOMediaCodec/SVT-AV1/-/blob/v4.2.0/Source/API/EbSvtAv1Enc.h#L228-267) describes the interval, closed-GOP choice, and prediction structure. The native tests verify actual emitted boundaries rather than trust settings alone. Do not round S upward to a picture-group boundary beyond its memory capacity. A memory-limited segment can drain a partial picture group and forces the next segment's keyframe earlier than K.

Fix K, P, F, B, and S once for the job's checked layout and settings. Every new session receives the same geometry, colour, rate, preset, parallelism, and sequence settings. The final segment may contain fewer than S pictures; its configuration is otherwise unchanged. For illustration, 1080p at 30 pictures per second has K = 150; its 150 tightly packed pictures contain 466,560,000 sample bytes before owner and padding overhead. The implementation computes S from actual retained capacities, not from this illustration or a flat 32-picture limit. It does not change the source frame rate or timestamps.

A session exclusively owns stable allocations for every submitted `EbBufferHeaderType`, its `EbSvtIOFormat`, and all three planes. It also owns a separate EOF header. Before the first native call, geometry and allocation arithmetic establish `F + S * P <= B`, including allocator-visible capacities and all retained owner storage. Charge those capacities before allocation. Private data and metadata pointers are null. Neither a submission return, a matching packet, EOS, nor a completed drain releases these allocations. Safe callers cannot regain or mutate them while the native handle exists.

The S-picture cap belongs to a session, not the job. On reaching it, the backend stops accepting input for that session, submits its EOF, drains and validates its complete output, releases native output packets, and successfully deinitializes and destroys its handle. Only then are its retained pictures, descriptors, and headers released, and a fresh session is opened for the next pictures. The worker uses one native session at a time. The next picture is not submitted to the previous session, and no accumulated list of prior sessions is retained. Existing packet, metadata, spool, and deadline limits still bound the whole job. Retained-input memory does not grow with total job length.

Before admitting a picture, check the remaining session count and retained-byte capacity. A call past a session's cap is refused before allocation or native submission; the backend's normal full-segment transition drains and destroys the session before it admits the next picture. A layout for which even one complete picture cannot fit is refused before encoding. Otherwise the formula selects a shorter memory-limited segment instead of refusing a long job. Every native or validation failure is terminal for the job, not a reason to restart a failed segment. No output is published and the existing destination is preserved. Failed submission and EOF calls may have retained pointers, so their storage remains owned through teardown too. If destruction fails or stalls, retain the handle and storage until the sandboxed worker is terminated and reaped; do not drop possibly borrowed allocations while native work may still run.

### EOF headers have the same ownership as pictures

Each session allocates its own stable, caller-owned `EbBufferHeaderType` before EOF submission. Its `size` is the exact header size, `flags` is `EB_BUFFERFLAG_EOS`, its filled and allocated lengths are zero, and `p_buffer`, `p_app_private`, `wrapper_ptr`, and `metadata` are null. All other fields are initialized to zero. The representation uses the public header's EOS flag ([`EbSvtAv1Enc.h`, line 65](https://gitlab.com/AOMediaCodec/SVT-AV1/-/blob/v4.2.0/Source/API/EbSvtAv1Enc.h#L65)) and buffer fields ([`EbSvtAv1.h`, lines 80–114](https://gitlab.com/AOMediaCodec/SVT-AV1/-/blob/v4.2.0/Source/API/EbSvtAv1.h#L80-114)); acceptance of this zero-payload input marker is checked with the pinned binary, not presented as an undocumented synchronous-copy guarantee.

The EOF header is not stack-local, is not a reused picture header, and has no non-null pointee outside session ownership. Submit it once per session. A successful or failed EOF submission does not release it, and an error does not cause another EOF submission. The header remains allocated and unchanged through output drain, error cleanup, and successful handle destruction. If cleanup cannot establish destruction, it remains with the retained session until worker termination. A new segment gets a new header; no EOF allocation is shared between live handles.

### Segments form one checked MP4 track

Every segment must start with an independently decodable keyframe. The safe output reader validates its random-access syntax; native picture flags alone are insufficient. Retain the exact bytes of the first segment's validated sequence-header OBU as the job's configuration. Every subsequent sequence header, including repeated headers and the final short segment's header, must be byte-identical to it. Compare the complete header OBU, not only its parsed fields or four-byte `av1C` prefix. A differing, missing, or unsupported header fails the whole job. Never splice a changed configuration into the existing sample entry or silently open another MP4 track.

Only that validated configuration supplies the single `av1C` and `av01` sample entry. Append the complete validated temporal-unit samples of each segment in decode order under the AV1 binding. Segment EOS is an internal lifecycle event, not the worker protocol's final job-completion record or an MP4 sample. All segments must drain and their frame identities must reconcile before the one final job-completion record is accepted.

Submitted identities and source presentation times belong to the job and do not reset when a native session restarts. The worker maps local output identities into the checked global submission interval of that segment. The codec-neutral packet ledger derives one continuous track's decode and presentation times from those global identities and the original source clock. Do not add a segment-local zero timestamp, insert padding frames, duplicate the last picture, or replace a variable-rate source clock with a frame counter. The first sample of each segment is a checked sync sample. Copied audio keeps its existing global packet clock.

The explicit cost is a fresh native initialization and drain, plus a forced keyframe, for every segment of at most S pictures. A nonempty job of N pictures uses `ceil(N / S)` sessions and forced segment-start keyframes. When memory accommodates K pictures, segment starts follow the normal configured interval; large pictures with S below K pay more frequent forced keyframes. Truncated lookahead and reset rate-control history can also affect output. The effective summary records B, F, P, S, and K rather than claiming a fixed duration or hiding the memory-limited interval. This is a bounded-memory implementation choice, not a quality, bit-budget, or speed claim. It does not change the separate acceptance bars or claim they have passed.

### Required lifecycle and segment verification

Before native execution, commit a closed case roster with exact settings, picture counts, geometry, strides, and expected outcomes. Independent review reconciles that coverage with the supported runtime settings. No test result authorizes immediate input reuse. Actual native and test sites and their inventory are reviewed before commit. Tests use the same verified static installation as the backend on all four native Unix targets.

1. Cover zero-input refusal, one picture, full S-picture sessions, and short tails. Multi-segment cases include lengths `S + 1`, `2 * S - 1`, `2 * S`, `2 * S + 1`, and `3 * S + 1`, with exact numeric counts frozen in the roster and distinct pictures. Cover both K-limited and memory-limited S, including the one-picture floor. Decode every segment separately and the combined stream, require exact presented counts and order, and check every segment starts with a keyframe and byte-identical sequence header.
2. Exercise constant and variable source timestamps at segment boundaries, including nonzero origins and a final one-picture segment. Require continuous global identities, monotonic decode times, unchanged presentation times and final duration, no duplicate or missing boundary sample, correct sync indices, and copied-audio agreement. Mutated-header and reset-timestamp fixtures must fail.
3. Exercise controlled caller-side failure after accepted pictures, EOF submission and drain failures, and teardown without drain before and after output starts. Keep every input and EOF allocation alive through destruction. Tests with controlled delayed native readers and observable allocation drops must reject early reclamation of any plane, descriptor, ordinary header, or EOF header. Cover teardown failure and deadline termination without permitting an early release. The test does not use invalid pointers as a supported native API error path.
4. Check the derived picture and retained-byte caps at and beyond their boundaries, including descriptor and EOF storage. Check floor division just below, at, and above a full-picture boundary, K as the tighter bound, the one-picture floor, and refusal when even one picture does not fit. Prove that picture `S + 1` opens a second session rather than failing the job or exceeding the first session's cap. Check that no two native sessions or their retained input sets are live together and that an oversized single picture is refused before allocation or native calls.

Record the archive pin, installed manifest and header digests, linked archive digest, compiler and target, driver revision, settings, closed roster, per-scenario child status, session and retained-byte high-water marks, output counts, and terminal result. Missing scenarios, unexpected signals or errors, incomplete drain, failed destruction, and timeouts cannot become passing evidence. Successful normal cases require complete independently decodable output; error and abandonment cases assert their intended cleanup outcome without claiming a complete stream.

Relocate the existing four-target native matrix into `ci.yml` and add these lifecycle and segment gates there, with no second automatic matrix or new required-check name. A dedicated `ci-changes` output covers recipe and pin, installed-header validation, driver, native wrapper and configuration, build/link settings, and workflow inputs. Relevant pull requests and merge groups run every target with the prescribed per-target job concurrency. Unrelated changes may skip this matrix. Add it to `ci-report.needs`; when requested, the required report accepts only success, not skipped, cancelled, failed, or missing work. Each leg completes all registered scenarios and early-reclamation regression controls. Tests check the exact four-target roster and every report outcome. No earlier run's artifact substitutes for this gate, and a pin bump reruns it. Existing merge-group and main-run isolation rules continue to apply.

### Wrapper ownership

The optional native feature links only the exact verified static recipe installation. No system-library, dynamic-library, or runtime-download fallback is added. The Rust glue retains its existing licence. The wrapper accepts checked, owned eight-bit planar 4:2:0 SDR pictures and validated settings, never a media file or a compressed source packet.

A session owns its native handle, configuration, every retained input allocation, and each output buffer until its documented release point. Its state distinguishes accepting input, draining, completed, and failed. Initialization failure cleans up partial ownership. Failure is terminal. No submission or output follows it. Finalization signals EOF once, drains through the encoder's end marker, releases every native output exactly once, and destroys the session before releasing any input that may still be borrowed. The session has no concurrent native calls and does not expose raw pointers.

Every actual Rust FFI site and lint exception receives its safety precondition in `docs/unsafe-sites.md` in the same commit as its code. The native wrapper, build integration, licence inputs, and inventory receive the shared integration owner's exact-diff review before commit. The existing global safety and licence checks remain enabled.

### Worker and packet boundaries

The release path always reexecutes the CLI as a private encoder worker under the existing sandbox launcher. The worker receives settings, sequential picture identities, and checked raw planes. One bounded writer queue and a concurrent bounded output reader prevent pipe deadlock. The existing process keeper owns the deadline, process group, stderr tail, cancellation, and reaping. A worker cannot publish files or receive the source container. Strict-safe keeps its existing platform memory-enforcement requirements.

The worker protocol has a versioned header, bounded records, explicit picture identity and packet extents, and an unambiguous completed-drain record. Neither worker-supplied flags nor native timestamps alone certify a valid output sample. The parent checks every record, consumes the stream to its final boundary, and rejects unknown, duplicate, missing, extra, truncated, or out-of-range data. Count, packet, total-byte, retained-frame, and metadata limits are charged before allocation.

The safe AV1 reader validates OBU framing and sequence configuration, then establishes complete samples, presentation identity, decode order, and random access under the selected prediction structure. It checks the emitted geometry, bit depth, chroma format, range, and colour description against the request. Unsupported frame structures are refused, not guessed from packet flags. A configuration change or incomplete drain fails the entire job. Codec-neutral submission and packet ledgers continue to own work and timing accounting. Encoded sample payloads are spooled rather than accumulated in memory.

### MP4 and command integration

The MP4 writer builds an `av01` sample entry and `av1C` from validated output. It follows the binding's temporal-unit/sample rules and sync-sample requirements. Configuration OBUs and sample payloads obey that binding rather than the external H.264 transport's Annex B conventions. Existing replacement timing, metadata handling, copied audio, temporary-output publication, and destination-preservation rules remain shared.

Both `--encoder auto` with `--video av1` and explicit `--encoder svt-av1` select the built-in backend when compiled for a supported Unix target. An explicit incompatible encoder, unsupported setting, or unavailable build fails before media reads where the failure is parameter-known. Header-known incompatibilities fail before decoding. Decoded-only incompatibilities fail before the first submission. No fallback follows an accepted frame. Preset 8 and CRF 32 are AV1 defaults only. Explicit numeric presets accept 0 through 13 and CRF accepts 0 through 63. No bit-depth, range, frame-rate, or geometry conversion is implicit.

New encoded-stream metadata uses `coreav.transcode/2`, with its schema, examples, serializers, and tests updated together. It reports the backend that actually ran, native version, software kind, sandbox isolation, and effective settings. Existing summaries keep their version 1 contract. The compatibility command's vocabulary does not change. Release-owner coordination precedes opening the implementation pull request.

### Independent reconstruction

Raw-wrapper completion is separate from reconstruction. Each successful native case records hashes and byte lengths for its wire output, combined OBU stream, every segment, sample metadata and complete configuration. Those files remain bound to the current source revision, closed roster, target, workflow run and attempt, native installation and executable. The reconstruction gate refuses missing cases, changed files, changed identities and imported results from another run. Error and abandonment cases retain their lifecycle outcomes; they are not complete-stream decoding evidence.

The native-case driver captures that inventory only after its producer exits with an absent process group, then rechecks every successful case before completing the target report. `scripts/svt_av1_media.py` refuses missing, extra, empty or nonregular media files and symbolic links. It also refuses changed bytes or identities and exhausted read budgets. Metadata and configuration files count toward its conservative target-byte allowance. This binds captured bytes to the producer; it does not decode them or establish independent reconstruction, and it is not a filesystem quota on the encoding process.

Capture and verification also check the deadline after their final I/O and record comparison. The driver checks it after writing the final report, replacing an expired success with failure. Synchronous filesystem operations are not interrupted; an overrun refuses successful completion after the operation returns.

The reconstruction gate runs on Linux x86-64, where the pinned FFmpeg binary is available. One arm explicitly selects FFmpeg's `libaom-av1` decoder. The other uses a standalone dav1d executable built from the exact version and archive digest already owned by `packages/cli/scripts/codecs.sh`. Both executable identities and versions are checked before and after the cases. The FFmpeg build's bundled dav1d is not substituted for that pinned arm. Decoder source is compiled without inspection; only its public command interface is used.

`python3 scripts/build_dav1d_oracle.py --prefix DIR` acquires that standalone tool into a newly absent directory. It requires curl, a C compiler, Meson, Ninja and NASM. The acquisition checks the existing archive pin, uses bounded opaque build commands, retains the distribution's three dav1d notices and records the executable identity before and after publication. Failed publication removes only the invocation's own output. This tool acquisition does not implement the reconstruction comparisons or establish SVT output correctness.

Every complete case is decoded both as a combined stream and as separate segments. Require exact frame count, eight-bit planar 4:2:0 output and the registered dimensions. Neither decoder may scale, convert range or pixel format, or drop or duplicate frames. The decoded bytes from both libraries must agree exactly. Concatenated segment reconstructions must also equal the combined reconstruction. The independent probe checks the coded configuration and each segment's initial keyframe. Any decoder error, timeout, incomplete frame or extra frame fails the gate.

The source-identity check uses the registered `binary-picture-identity-v1` pattern, not decoded frame position alone. Each picture contains four rows of eight luma cells. The bits are `(identity * 0x9e3779b1) XOR 0xa5a5a5a5`, reduced to 32 bits. Cell row r and column c carry bit `8*r+c`. Zero and one cells have source luma 32 and 224. Column c spans `[ceil(c*W/8), ceil((c+1)*W/8))`; row r spans `[ceil(r*H/4), ceil((r+1)*H/4))`, including nonaligned geometry. Discard `floor(cell_width/4)` columns from each side and `floor(cell_height/4)` rows from each end. Compare the remaining mean against 128 using integer sums. A mean below 128 is zero, above 128 is one, and exactly 128 is ambiguous and fails. Every cell of every displayed picture must identify the expected global source picture, including segment boundaries. These fixed predicates are not tuned after native output is observed and are not quality scores.

Bound the gate to 512 MiB per encoded file, 2 GiB of encoded files per target, 120 seconds per decoder invocation and 1200 seconds per target. Raw output is bounded to the expected displayed count plus one frame, so an extra picture is observable rather than silently truncated. Reports retain commands, versions, hashes, process outcomes, decoded counts and frame identities. Elementary OBU reconstruction establishes neither source-container timestamps nor copied-audio agreement. Integrated MP4, timing, destination preservation and confinement remain separate required cases.
