# Apple encoder output readers

The Apple backend is under development. The standalone crate has checked AAC and H.264 metadata readers and a macOS AudioToolbox adapter. It is not integrated into the CLI and provides no acceptance-bar or performance result. The [encoder contract](../encoders.md) defines the remaining work and its acceptance bars. Platform encoding is not a finding that an operator's use is patent-covered. Paid services may need their own patent licence.

## AAC configuration and packet boundaries

`coreav-backend-apple` has no production Rust dependencies. Its standalone manifest and lockfile permit isolated checks until workspace integration. macOS fixture tests alone depend on CoreAV's independent AAC decoder. This does not add a decoder to the production library graph.

`aac::Config::parse` reads a two-byte ISO/IEC 14496-3 `AudioSpecificConfig`. It accepts AAC-LC with 1024-sample frames, an indexed sample rate, and mono or left-right stereo. The parsed rate and channel configuration must equal the requested PCM format. Explicit frequencies, program configurations, 960-sample frames, core-coder dependencies, and extensions are refused. `from_cookie` additionally reads bounded MPEG-4 ES, DecoderConfig, DecoderSpecificInfo, and SLConfig descriptors. It accepts the optional ASC suffix that explicitly signals absent SBR, normalizing that representation to the same two-byte configuration. Unknown descriptors, ES flags, unexplained suffixes, and present SBR are refused.

AudioToolbox's private cookie may clear the DecoderConfigDescriptor's reserved low bit: hosted output uses `0x14` where the standard descriptor uses `0x15`. Cookie parsing accepts both audio-stream forms, with the upstream flag still clear and all descriptor extents checked. It extracts only the validated ASC; the private descriptor wrapper is not copied into container configuration. The captured-cookie regression refuses every other stream-type/flag byte and any requested rate or channel mismatch.

`aac::PacketBatch` checks copied `AudioStreamPacketDescription` values against the supplied buffer and caller-supplied batch limits before allocating packet storage. Signed offsets must be nonnegative. Packets must be nonempty, in buffer order, nonoverlapping, and wholly within the buffer. Apple permits gaps between packets. The reader copies only the packet bytes into owned storage. Both zero, meaning the format's fixed frame count, and an explicit count of 1024 are accepted. An empty batch must have an empty buffer and does not by itself prove completion.

The packet reader validates extents and declared frame counts, not compressed `raw_data_block()` syntax or successful decoding. Per-batch limits do not replace cumulative output, queue, or deadline limits. Those belong to the future session owner. No decoder is linked by this crate.

`aac::Trim` checks that the cumulative checked packet count, minus declared leading and trailing trim, accounts exactly for the submitted PCM sample frames. Sample frames count one sample in every channel, not interleaved scalar samples. Both trim counts are bounded by the caller. The counts describe the encoded stream, not input lookahead requested by `AudioConverterPrimeInfo`. Arithmetic agreement does not prove impulse placement, channel order, or the truth of the declared trim. Independent decoding must check those properties.

## Verification

The standalone fixture tests cover the four AAC acceptance formats, every two-byte configuration for a requested 48 kHz stereo format, packet ownership, permitted gaps, malformed extents, exact batch bounds, and drain underflow, overflow, missing packets, and excess packets. The packet fixtures contain synthetic bytes and test packetization only.

The crate-local `aac_output` fuzz target exercises configuration, packet descriptions, and trim accounting. Fuzz runs belong on hosted CI, not the development machine.

The hosted macOS runner runs these commands, with one Rust build at a time:

```sh
cargo test --locked --manifest-path crates/coreav-backend-apple/Cargo.toml
cargo clippy --locked --manifest-path crates/coreav-backend-apple/Cargo.toml --all-targets -- -D warnings
```

The standalone VideoToolbox owner, callback cancellation, hosted H.264 independent-decode capability smoke and reference-host driver are described below. They do not integrate an encoder into the transcode API. No M1 through M5 or AAC acceptance result is claimed. The development machine is not a measurement host, and no physical measurement host is provisioned or promised.

## H.264 configuration and access-unit metadata

The safe `h264` module adds no native calls or production dependencies. `Dimensions` represents nonempty even visible geometry. `Config::from_parameter_sets` checks one complete SPS and PPS against that geometry before constructing an owned avcC record, including the High-profile chroma/depth extension fields and four-byte NAL lengths. It retains the exact checked parameter-set NALs; in-band replacements must match them byte for byte. Configuration size and uncropped coded geometry have caller limits. Cropping uses progressive 4:2:0 crop units, not raw pixel offsets.

The initial subset is High profile, 8-bit 4:2:0 progressive output with POC type 0 or 2. The readers check bounded Exp-Golomb fields, parameter-set references, emulation-prevention bytes, complete parameter-set trailing bits, and the optional VUI/HRD syntax with its bounded CPB table. Custom scaling matrices, intra-profile constraints, interlacing, POC type 1, frame-number gaps, slice groups, redundant pictures and a nonzero VUI reordering allowance are explicitly unsupported. This is not a general H.264 parser or a decoder, and it does not certify every level constraint or compressed slice.

`AccessUnit::copy_from` validates complete four-byte length-prefixed NAL extents, NAL headers and caller byte/NAL-count limits before copying the access unit. It requires an I/P coded-slice header starting at macroblock zero. Additional slices must have increasing start addresses and matching frame number, parameter-set reference, IDR identity, reference/non-reference classification and POC fields. B/SP/SI slices and other NAL forms outside the subset are refused. Declared sync must agree with IDR NAL headers; a non-IDR I slice is not relabeled as a random-access point. Identical parameter sets before the slices, an initial access-unit delimiter, bounded SEI payload extents before the first slice and filler after the first slice are supported.

The owned bytes preserve their original order and framing. Slice payload syntax, macroblock coverage, decoded pixels and reference availability are not validated by these metadata checks. Source-frame identity, timestamp order, durations and final submitted-frame accounting belong to the later session owner. A metadata-reader success does not establish successful decoding or complete encoder drain.

Configuration parsing uses bounded temporary RBSP buffers and retains parameter-set bytes plus avcC; peak storage is a fixed multiple of the caller's configuration bound. Access-unit parsing holds at most one bounded temporary RBSP plus its final owned byte copy. Processing is linear in the bounded input sizes, with no recursive parsing or untrusted-count allocation. Synthetic fixtures build header metadata only, not decodable video. The `h264_output` fuzz target checks hostile parameter sets and access units on hosted CI; no local hostile-fixture or fuzz execution is required.

## AudioToolbox ownership and streaming

`audiotoolbox::Encoder` uses the direct `AudioCodec` push/pull API instead of `AudioConverter` input callbacks. The component copies accepted input into its own buffer during `append`. No Rust frame reference or callback state survives a call, and there is no callback queue. One private native module owns one successful non-null component instance and disposes it on every later failure or drop. Failure outputs from component creation confer no ownership. The owner is neither Send nor Sync.

Settings select the Apple software AAC-LC component, CBR, unchanged indexed rate, mono or left-right stereo, and quality 0 through 127. Format properties are set before codec controls. A control is written only when the property API reports it writable; the initialized value must still equal the required value. The codec owns its priming method and delay mode. Neither is an input to the adapter, and their optional properties are not written. Final trim comes from checked codec metadata and must pass the independent decode fixture. The actual instance is resolved back to its component. Identity records its type, subtype, manufacturer, and documented component version value. The selected Apple software manufacturer identifies a software codec, not a requested hardware preference. No framework semantic version or OS build is invented.

The native fixtures request quality 96, the SDK's `kAudioCodecQuality_High`. In the [hosted diagnostic at `46b2013a`](https://github.com/coreav-dev/coreav/actions/runs/41403823335/job/125141266719), AudioToolbox reported the quality property writable but changed requested 127 to 96 immediately, before initialization. Such a request is refused with `Error::Setting`, not silently accepted as an equivalent quality. The settings constructor checks the numeric range; it does not promise native availability of every value. The adapter has no implicit quality default.

`append` accepts finite interleaved float PCM and a contiguous sample-frame identity. It reports partial consumption explicitly. Non-frame-aligned consumption is refused. Empty chunks do not signal EOF, and timestamp gaps are refused rather than filled with silence or closed. `start_drain` freezes a bounded tail plan from the direct codec's priming counts and the accepted source count. Each `pull` appends at most 1024 stack-backed zero frames toward flushing the reported delay and completing the last AAC frame, without counting that silence as source PCM. Once that tail is consumed, the API's zero-byte EOF marker is supplied once. Input exhaustion after that marker ends the native drain; input exhaustion before it is not EOF. `pull` returns at most one owned, checked AAC packet and a progress state. Failure, unknown output status, early EOF, a stalled output claim, excess output, and incomplete drain cannot become successful completion. A failed session accepts no further native work.

The caller supplies per-chunk, total sample, packet, output-byte, cookie, and trim limits. Output storage is fallibly allocated to a bounded size, and returned counts are checked against initialized buffers before the safe reader sees them. Cancellation and the session's single deadline are checked before and after synchronous framework calls. Neither can interrupt such a call or enforce a cap on the framework's own internal allocations. This adapter does not make strict-safe mode eligible.

Synthetic tail work has a separate bound, not a source or caller-chunk allowance: at most the leading and trailing trim limits combined, fed in chunks of at most 1024 frames through an initialized 2048-float stack buffer. Packet alignment must fit the trailing limit. Tail frames never increase the submitted-source count or permit more source input; all resulting packets still consume the cumulative packet and byte limits and the same deadline. A zero-consumption append does not advance the tail or authorize EOF.

Finalization reads the final cookie and codec-specific priming and padding values, checks their arithmetic against the actual accepted PCM and emitted packet totals, and returns validated container configuration only after drain. The final priming values must equal those that planned the tail; the codec must report no additional padded zeros after explicitly aligned input. Leading trim is the codec's reported delay, and trailing trim is the planned tail minus that delay. These are `AudioCodec` properties, not `AudioConverterPrimeInfo` input lookahead. The native fixtures independently decode synthetic AAC with the Rust decoder and check declared trim, channel impulse placement, and all four acceptance formats. They are correctness fixtures, not quality or speed bars against the pinned FFmpeg oracle.

## VideoToolbox ownership

`videotoolbox::Encoder` implements the native H.264 ownership described here. Its standalone safe interface remains separate from transcode, CLI selection, schemas and packaging. The existing H.264 readers remain the syntax boundary, not a decoder or a source-frame ledger.

### Input and session ownership

One owner-thread-only `videotoolbox::Encoder` creates, configures, submits to, completes, invalidates and releases one `VTCompressionSession`. It is neither Send nor Sync. Cancellation from another thread changes only Rust-owned state. No other thread calls the native session, and no callback calls application code, invalidates the session or borrows the movable Rust owner.

The initial request is High-profile, progressive 8-bit 4:2:0, with a checked bitrate, rational frame clock, no reordering and a two-second maximum keyframe interval. Source geometry, colour description and range are explicit. Unsupported values are refused rather than converted silently. Required settings are queried back after preparation and checked again against encoded output. Average bitrate is Apple's desired long-term average, not a hard byte cap. Cumulative output has an independent resource bound.

Each submission carries a sequential identity, exact presentation time and positive duration. Checked 4:2:0 planes are copied synchronously into a framework-owned NV12 pixel buffer; interleaving U and V changes packing, not samples or colour. The source borrow ends with the call. A successful pixel-buffer lock is paired with unlock, and plane count, geometry, strides, address arithmetic and storage bounds are checked before row copies. Allocate from the session's retained pixel-buffer pool with a threshold on every allocation. The threshold includes the encoder's outstanding buffers, not only Rust's pending ledger. Do not wrap caller storage with an external-byte constructor or recycle submitted pixels on callback arrival. Apple documents that the session or encoder retains its image buffer as long as necessary.

Reserve the source identity, timing and output allowance before `VTCompressionSessionEncodeFrame`: the callback can run before that call returns. A synchronous submission error makes the session fail, even if a callback already produced bytes. Such bytes cannot reach the caller as a successful output. The input acceptance count advances only on a successful submission.

### Callback lifetime without an undocumented teardown guarantee

The callback refcon is a nonzero, never-reused numeric registry key, not a pointer to a Box or the encoder. The registry contains an `Arc` to a safe bounded mailbox. A callback looks up the key, clones that Arc, releases the registry lock and reserves a bounded extraction slot under the mailbox lock. It performs CoreMedia extraction outside both locks, then commits or discards its owned result under the mailbox lock. Native session calls also occur outside both locks. No registry and mailbox lock is held at the same time.

The mailbox contains only Rust-owned bytes and metadata, not a native handle, caller reference or borrowed sample. A retired registry entry prevents new callback leases; an existing callback Arc keeps only its mailbox alive. A late callback with a missing key returns without inspecting the sample. Keys never wrap or recycle. Admission and aggregate reserved-storage permits live in the Arc-owned allocation, so retired mailboxes still held by callbacks count against the process limits. Counting active map entries alone would not bound late callbacks' retained storage. Exhausted key space or admission capacity refuses creation.

The alternative is a stable per-session Box passed directly as refcon. Reclaiming that Box requires proof that no callback can begin after it is freed. Apple's inspected `Invalidate` contract promises orderly teardown, but does not explicitly promise callback quiescence, and an active-callback counter cannot exclude a callback that has not entered yet. Permanently allocated tombstones would require a lifetime admission cap and eventually refuse all further sessions. The reclaimable key-to-Arc registry is chosen instead of assuming either guarantee or leaking per-session contexts.

Callbacks can overlap. Their native invocation order does not establish the order in which concurrent Rust copies finish. Reserve each known frame once, reject unknown or duplicate identities, and publish completed access units in submission order through a bounded pending ledger. A duplicate, dropped frame, callback error, missing sample, queue overflow or unexpected picture fails the session. No callback unwinds across the C ABI.

### Copy and validate output before delivery

The private native module requires ready data and exactly one complete sample. Sample size must agree with the block length and fit per-access-unit, queue and cumulative limits before allocation. `CMBlockBufferCopyDataBytes` copies noncontiguous block storage into initialized owned bytes; its destination is discarded on error. Copy bounded SPS and PPS while a retained format description remains alive, and require the supported parameter-set count and four-byte NAL lengths. Read attachments without creating or mutating them. An absent `NotSync` attachment means sync, still subject to the safe reader's IDR check.

Only owned data crosses into the safe reader and frame ledger. Parameter sets, geometry, supported colour signalling and sync must agree with the request and remain unchanged. Presentation time and duration must match the submitted identity; valid decode times cannot introduce reordering. Account separately for raw callback copies, parameter sets, the reader's final copy and RBSP scratch. A bounded output queue alone does not bound that peak.

Backpressure never increases a buffer bound. When output is needed but the oldest submitted frame is still pending, complete through its presentation time outside the locks, then wait only for bounded callback work within the session's remaining deadline. Final drain stops submission and calls `VTCompressionSessionCompleteFrames` with nonnumeric time to request all pending frames. Successful completion requires every accepted identity exactly once, no copying slot or pending frame left, and a fully consumed output queue. Metadata validity alone cannot establish that condition.

Finish, cancellation, failure and Drop close submission and retire the registry entry before final native teardown. Invalidation and CF release happen on the owner thread without callback locks. Already leased callback mailboxes discard work after closing and are reclaimed only with their last Arc and admission permit. Failure and Drop do not need a successful drain to make callback-context reclamation safe. Teardown is idempotent.

Synchronous framework calls cannot be interrupted. Deadlines are checked before and after them and around Rust waits; they do not prove a native-call or teardown deadline, bound all encoder-internal memory, or establish strict-safe isolation. `CompleteFrames` documents emission before return, not that every callback body has returned, so completion also accounts for active extraction slots. A failed or cancelled native call is not assumed to return each refcon once.

### Actual implementation and hosted smoke

The native `ExpectedFrameRate` control is an optimization hint, not the source clock. `Settings::expected_frame_rate_hint` rounds the source rate to the nearest whole frames per second, with ties upward, and the owner requires exact integer readback. Submitted presentation times and durations still use the original rational rate. Baseline evidence retains the derived nominal hint separately as requested-only and unobserved. It does not claim a baseline property readback. No timestamp or conformance tolerance depends on this hint.

Read the actual session's copied encoder ID and hardware-use property with runtime CF-type checks and bounded string conversion. Apple's public `VTCompressionProperties.h` documents querying [the hardware-use property](https://developer.apple.com/documentation/videotoolbox/kvtcompressionpropertykey_usinghardwareacceleratedvideoencoder) after hardware encoding is enabled; a software-only session may not expose it. When that property is unavailable, copy [the encoder list](https://developer.apple.com/documentation/videotoolbox/vtcopyvideoencoderlist(_:_:)) and bind the session's actual EncoderID to exactly one entry with an explicit CFBoolean hardware flag. Inspect at most 256 entries and bound each identifier to 4096 UTF-16 code units, with the copied session identifier also bound to 4096 UTF-8 bytes. Missing or invalid flags, absent identifiers, duplicate matches and no match refuse rather than assuming software or encoder unavailability. Candidate-list entries alone and requested preferences are not proof of the selected implementation. A hardware-required request refuses software results, and a software-only request refuses hardware results. No reliable encoder semantic-version query is assumed; the driver records OS version and build separately.

Hosted hardware-required and automatic macOS checks exercise synthetic submission, drain, independent decoding, exact frame count/order and source-pattern identity. Software-only availability requires real submission and drain, not framework presence or session creation alone. Normal software requests record recognized pre-submission unavailability, and refusal cleanup is tested; unsupported settings, unexpected native errors and any failure after accepting a frame cannot become a successful encode or a post-hoc exclusion. Mocked safe-backend tests cover synchronous/reentrant and overlapping callbacks, out-of-order copy completion, early/duplicate/late output, cancellation, partial drain, counter overflow and resource cleanup. Host timing is diagnostic only. The fixed-physical-host speed plan is a separate commit before any run.

Hosted CI does not exercise the software encode path. An explicit hosted-only mode records a distinct refused/unobservable outcome solely when initial creation finds the actual session EncoderID in exactly one encoder-list entry and that entry lacks the hardware flag. It is not encoded, available, unavailable or a conformance pass. Every other refusal still fails the job. If hardware status becomes observable, the stale-exemption check fails and asks for this mode to be removed. Hardware-required and automatic cells retain full encode/decode verification. Production admission and judged preflight remain strict; a regression rejects the hosted outcome before availability accounting. Software encode verification is deferred to the post-merge Apple-silicon run, which cannot use the hosted exemption.

Native declarations, pointer access, packed CoreMedia ABI types, CF ownership and the callback trampoline belong to `src/videotoolbox/sys.rs`. Other files retain safe Rust. The source ships with its site inventory in `docs/unsafe-sites.md`. This design note describes the ownership contracts, not a safety sign-off.

### Standalone tools

Build the bounded raw-I420 driver with `cargo build --locked --manifest-path crates/coreav-backend-apple/Cargo.toml --profile dist --example videotoolbox`. Its `smoke` command writes four synthetic frames, native source identities and timing, and an elementary H.264 stream. Its `encode` command consumes explicitly sized, timed BT.709 limited-range frames; it does not choose streams, trim a source, convert samples or mux a container. The driver includes report generation in its whole-process cost.

The `videotoolbox` workflow captures hardware-required and automatic output on hosted macOS, then verifies those immutable bytes with the unchanged pinned Linux oracle and the independent Rust decoder. It separately checks the typed hosted software refusal record without running a decoder or claiming software availability. Hardware or automatic refusal does not satisfy the smoke. No workflow invokes the judged timing command.

The Python tools under `scripts/encoders/macos` separate hosted `smoke.py capture` and `verify` from physical-host `timing.py gate`, `run` and `report`. `producer.py preflight` captures real native and FFmpeg availability, and `fixtures` retains both encoders' fixture outputs. On trusted Linux, `producer.py analyse` decodes every captured output with both independent decoders, checks their complete pixels and derives bound conformance, integer PSNR, VMAF and SSIM evidence. `timing.py report` independently replays the retained facts before judging. Neither a caller-supplied pass flag nor a successful encoding call satisfies those gates.

Timing still requires a merged clean registration, the exact physical host, a release-reviewed observable macOS baseline build, prepared raw references and complete host gates. A separately pinned cache observer must establish full-file residency before and after every side; reading a file once does not prove that it remains resident on the fixed 8 GB host. Framework worker counts remain uncontrolled, distinct from the registered caller and input-thread controls. No host, tool installation, input preparation or storage allocation is performed by these commands.

Stage one freezes thirty verified prepared-I420 inputs: ten each in the 360, 720 and 1080 classes. The [source freeze](../../../scripts/encoders/macos/videotoolbox-sources.json) binds the complete source and raw hashes, every frame hash, original clocks, observed metadata, labeled colour assumptions and progressive-header records. The [ordered selection](../../../scripts/encoders/macos/videotoolbox-selection.json) retains all 407 dispositions. The [2160 reconciliation](../../../scripts/encoders/macos/videotoolbox-uncovered.json) records one verified input and twenty-one exclusions without claiming 4K coverage. Quality and timing bars apply unchanged to each covered class and available cell, not a pooled roster. These results describe encoder behavior on prepared raw I420, not preservation of unknown source colour or integrated audio timing.

`source_freeze.py` verifies the merged source freeze before materialization. Its local source map is private operator input, not published acquisition information. On Linux, `preparation.py` verifies a bounded source spool and the unchanged pinned oracle, then reproduces the fixed conversion with exact whole-file and per-frame comparisons. Output directories are create-only. Decoder errors, nonempty error-level diagnostics, hash differences and uncertain child cleanup refuse rather than selecting replacements. The standard metric model is [Netflix's `vmaf_v0.6.1` JSON from the v3.0.0 release](https://github.com/Netflix/vmaf/blob/v3.0.0/model/vmaf_v0.6.1.json); the source freeze owns its byte identity.

Stage two separately binds the actual merged candidate and tooling revisions that reproduce the frozen native and tool bytes, reviewed clean builds and observed physical-host facts. It also binds the exact merged source-freeze digest and review revision. No future merge identifier, build identity or host observation is filled in ahead of that review. Both stages must merge before judged encoding or timing.

`coreav_build.py` captures a clean, isolated offline dist build from the candidate revision on each platform. The committed, reviewed Mac and Linux build records bind the native exporter and independent decoder to their candidate, configuration, pinned toolchain and resulting executable bytes. A merged candidate name alone does not establish executable provenance.

Analysis requires an explicit persistent-storage root and byte budget. Its `--resume` mode binds the registration, captures, tools, model and source bytes, revalidates completed units, and rebuilds only owned incomplete analysis. It never recaptures timed calls or retries a final conformance failure. The [measurement plan](../../../scripts/encoders/macos/videotoolbox-plan.md) gives the post-merge operator sequence and remaining registration prerequisites. This implementation supplies evidence producers, not an acceptance result.
