# H.264 ordered row deblocking

The caller owns syntax output. Decision workers publish immutable, unfiltered macroblock candidates. Once a row is complete, the caller writes its syntax while the caller and decision workers can complete its reconstruction planes. Prediction reads only published candidate tiles, never the filtered output planes.

Rows are consumed in raster order. Within each plane, each macroblock retains its vertical-then-horizontal edge order. Filtering a row can change the bottom border of the preceding row, but needs no samples from a later row. Cropping and reference publication happen only after every row is filtered and every worker has joined successfully.

The scheduler publishes each row outcome before sending a completion notification through a channel bounded by the picture height. Each worker owns its sender, and the caller drops the original sender before receiving. A failed or panicking decision propagates failure to dependent rows before its outcome is published. Every claimed row's compute callback stays inside the unwind boundary.

The caller remembers a consumer error or panic, stops consuming, and joins every worker. Plane-completion errors and panics stop further completion attempts but not decisions. The first raster decision error takes precedence over an output error, preserving the earlier decide-all-before-writing failure order. A one-worker picture completes decisions before consuming, without channels or threads. With one requested worker, filtering stays after committing the complete picture: no overlap is possible, and retaining whole-picture staging avoids interleaving costs. If no worker can start, the caller completes the decision work before consuming; partial starts retain the workers that did start.

The requested worker count still limits decision workers, with the existing geometry cap. The caller now does useful work concurrently but adds no operating-system thread. It can compete with decision workers on a limited CPU set, so the serial deblocking fraction is not a predicted speedup.

Band barriers would simplify completion ownership but add repeated spawning and idle boundaries. Moving mutable strips between workers would complicate border ownership while immutable candidates remain necessary. This design keeps the existing bounded decision table and picture allocations instead.

## Plane-owned completion

For multiple requested workers, each reconstruction plane has one private owner containing its pixels and next uncommitted row. A mutex protects that owner. After publishing a completed decision row, a worker tries each owner without waiting. The caller does the same after writing a syntax row. A successful owner processes its consecutive ready rows, committing candidate tiles and applying the existing filter in raster order. A busy owner is skipped; a worker never waits for output while holding up another decision row.

The last candidate in a row establishes readiness because the decision loop publishes its candidates in order. Completing a plane can modify its preceding row's border but reads no later row. Different planes have no filtering dependencies, so their owners can run concurrently without changing arithmetic or filter ordering within a plane. After every worker joins, the caller drains any remaining ready work before cropping and reference publication. That final drain also covers a last-row notification racing with an owner's release.

The scheduler accepts a shared completion callback beside its caller-only syntax consumer. Completion callbacks run inside an unwind boundary; one retained completion failure prevents further attempts, while all decision rows and joins still finish. No callback owns candidate storage or adds a thread. With one requested worker, plain planes retain the existing syntax-and-commit traversal and whole-picture filter, avoiding mutexes and worker assistance. Both paths use one syntax traversal and the same commit and filtering operations.

Dedicated plane threads would exceed the existing thread budget. Reserving decision workers permanently for planes would reduce search parallelism even when no output row is ready. Nonblocking assistance instead borrows existing worker capacity only at completed-row boundaries. Entropy fragments would require changes to the bit writer and its byte-joining contract, so they are outside this change.

Verification compares complete streams and reconstructions with an explicit current-main baseline at one, two, three and eight workers in automatic and scalar builds. Scheduler tests cover ordered overlap, existing-thread assistance, decision and output failures and panics, raster error precedence, and zero or partial thread-start refusal. Plane-completion tests withhold a row's last candidate, drain the remaining work, and require repeated completion to leave pixels unchanged. Row filtering is compared with whole-picture filtering on mixed edges and narrow pictures. Alternating explicit-SHA native reference calls quantify the one-worker cost and must show a four-worker improvement beyond variation before this change ships.
